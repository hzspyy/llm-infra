# 实验与证据规范

用于指导实验设计、运行测试及在正文中解释测量结果。连接远程机器前先看 `ENVIRONMENTS.md` 中的环境与目录配置。

## 1. 真实性与基础原则

- **区分事实与推论**：明确区分源码事实、实测读数、公式推演与待验证假设。实测注明测试硬件、输入规格与关键配置。
- **数据真实取自工件**：数据直接从运行日志或测试输出提取，不凭空估计。计算得出的指标给出算式与单位，不伪装成硬件原生读数。
- **实事求是记录结果**：保留负面或不符合预期的测量现象。若实测与理论推导不一致，以实测为准；未实测的内容标为 `UNVERIFIED`，不强行得出确定性结论。
- **不跨卡随意套用**：不同架构、不同设备的耗时与表现不可直接混用，模拟测试不能完全代表真实 kernel 的执行代价。
- **历史数据只读**：`results/` 下的历史数据用于归档，修改分析逻辑时不要篡改原始输出。

## 2. 测试与测量实用约定

实验前先明确控制变量。新增的 lab 脚本先在机器上运行验证，再写进教程章节。

常见场景的测试建议：

- **算子与 Kernel**：测试前充分预热，多次测量取稳定值。测量显存带宽相关算子时，输入工作集需大于 GPU L2 缓存容量，避免缓存命中干扰带宽测量。
- **服务吞吐（Serve）**：固定输入与输出长度（如生成 128 token），在典型并发与序列长度下对比各配置表现，明确标注是否开启前缀缓存。
- **到达率与压测**：测试长时服务时，固定请求序列并覆盖不同到达率，记录真实耗时与失败/超时情况。
- **数值与对拍**：小规模参考实现可与 CPU FP64 对照，核对数值正确性与关键状态。
- **参数扫描**：优先沿关键维度单轴寻找性能拐点，避免无目的全参数穷举。
- **统计与归因**：histogram 的增量 sum/count 是均值；阶段分位数由同一请求的配对事件计算，不能用分位数减均值得到。准入配置预算、实际到达率、完成吞吐和任务质量分别报告；干预在出现异常的同一负载条件下进行。
- **公式与实现对拍**：通信字节按实际发送张量、dtype、目标 rank 计算，并说明发送/接收及自身 rank 的计数方式；理论未展开的 KV 与实际 GQA 展开后的 buffer 分列。概率缓存明确温度、归一化、支持集和尾部质量，数值目标通过参照检查后再比较训练质量与性能。

### 完整教学训练

训练按[贯穿项目与预算](plans/pending.md#training-workflow)执行，机制小验证、完整教学训练和公开规模结果分别记录。模型与数据可缩小，但数据准备、训练、独立评测、保存恢复与导出部署各阶段齐备。

- 先用有限 step 的 pilot 估算有效处理速度、峰值显存、存储与总时长；教师/奖励服务、编译、评测、保存和重跑计入预算。规划值和作者租用成本不能标成本机实测。
- 运行前确定数据拆分、未训练/未适配基线、主指标、验证频率、质量标准与停止条件；最终测试不参与调参。保存训练/验证曲线、有效监督数量、实际更新数和退化样例，预算耗尽与质量通过分别判断。
- 从同一阶段 checkpoint 比较后训练分支；等预算、等数据与不同初始化的比较分别说明。loss/reward 上升或下降、单张生成图像、几条流畅回答不能代替独立任务质量。
- 基础数值检查先验证恢复后的下一批与参数更新，实际项目再执行中断、恢复、继续训练和导出。确定性设置、浮点容差、数据顺序及推理模板均明确；权重加载与完整训练恢复分开验收。
- 完整训练出现负收益或未达质量标准时保留结果与诊断；不能删去失败样本、自动扩大预算，或把单步实验写成完整训练完成。

## 3. 环境与运行约定

- **运行前核验**：先查看 GPU 占用与磁盘空间，加载对应目录的 `env.sh`。独占卡可充分使用显存，共享卡不挤占他人已有任务。
- **实验后立刻释放 GPU**：测试完成后主动杀掉自己起的推理服务与后台进程，确认 `nvidia-smi` 显存归零，不把常驻服务留到后续。
- **缺工具可直接装**：缺少工具链时可以直接安装（包括使用 apt 与各语言包管理器），只要不覆盖或破坏已有的驱动、CUDA 和既有 Python 环境即可。新装工具简要记入 `ENVIRONMENTS.md`。
- **Python 环境统一**：
  - 本地统一使用 `/Volumes/data/venvs/llm-infra/bin/python`。
  - 远程机器通过脚本指定各学习目录下的虚拟环境解释器（如 `/scratch/learn/envs/serve/bin/python`）。
- **硬件特性注意**：
  - RTX 5090 D（sm_120）不支持数据中心 Blackwell 的 TMEM/tcgen05 特性。
  - worldvln 磁盘空间紧张，共用已有权重，不重复下载。
  - Jetson 仅使用预编译包，不现场编译。

## 4. 存储与大文件红线

- **大文件不入库**：模型权重、训练 Checkpoint、原始大 trace 严禁提交进 Git 仓库，也不要占满系统盘；本地统一保存在外置盘 `/Volumes/data`，用完及时清理。
- **本地不用 `/tmp`**：本地构建和测试缓存统一放 `/Volumes/data` 专用目录，本机坚决不用系统的 `/tmp` 目录。
- **测试输出归档**：新实验结果保存至 `results/<机器>/<章节ID>/`，仓库内只提交轻量级工件（JSON、日志摘录、摘要表）。
- **回传按文件拉，不整目录同步**：远程输出目录里混着引擎与 mini store 的落盘数据（KV 文件、chunk 目录、profile 转储），整目录 `rsync` 回项目会把它们一起带进内置盘和 iCloud。只拉正文与 STATUS 要引用的证据文件；确有保留价值的大体积产物按 `ENVIRONMENTS.md` 的布局放 `/Volumes/data/artifacts/`，并在那里留一份来源说明。

## 5. 正文表达规范

实验结论按[章节规范](chapter-guidelines.md)写入正文，直接说明现象、解释和适用条件；实验记录保留理解与复现结果所需的信息。
