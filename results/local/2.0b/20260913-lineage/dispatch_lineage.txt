[A1] F.linear 是什么对象：Python 函数、绑定还是一张注册表
================================================================================================
torch.nn.functional.linear           = <built-in function linear>

它不是 Python 函数，而是 C++ 侧注册进 `torch._C._nn` 的绑定：
`native_functions.yaml` 里的 `python_module: nn` 决定它被生成到
`torch._C._nn` 命名空间下，而不是 `torch` 顶层。

schema 与注册来源（运行时 dump 的前几行）：
  name: aten::linear
  schema: aten::linear(Tensor input, Tensor weight, Tensor? bias=None) -> Tensor
  debug: registered at /Users/runner/work/pytorch/pytorch/build/aten/src/ATen/RegisterSchema.cpp:6
  alias analysis kind: FROM_SCHEMA

`alias analysis kind: FROM_SCHEMA` 说明别名信息不来自手写注释，
而是由 schema 里的 `Tensor input` / `Tensor(a!) self` 这类签名推导。

================================================================================================
[A5] 运行时验证：linear 在 aten 层被拆成 t + addmm
================================================================================================
F.linear(x, w, b)  ->  ['aten.t.default', 'aten.addmm.default']
输出 shape (2, 4)，其中 linear 这个名字没有出现在 aten 层。
x @ w.t() + b      ->  ['aten.t.default', 'aten.mm.default', 'aten.add.Tensor']
两条路径计算同一件事，但融合程度不同：有 bias 的 linear 直接走 `addmm`，
手写 `x @ w.t() + b` 是 `mm` 再加一次 `add`。复合算子只决定语义，
底层选哪个 kernel 由它调用谁决定。
