======================================================================
Layer 2: Python binding
======================================================================
这一层在源码中的位置:
  torch/csrc/autograd/generated/python_functions.cpp
  由 tools/codegen/gen.py 从 native_functions.yaml 生成

功能: 参数解析、类型检查、转发到 C++ at::linear

======================================================================
Layer 3: Dispatcher 层
======================================================================
调用: F.linear(x, w)
  aten.t.default
  aten.mm.default

输出形状: torch.Size([2, 4])

观察到: linear 被分解成 t (transpose) + addmm

======================================================================
Layer 4: Native 实现
======================================================================
addmm 的 CPU 实现位置:
  文件: aten/src/ATen/native/LinearAlgebra.cpp
  函数: TORCH_IMPL_FUNC(addmm_out_cpu)
  功能: 调用 CPU BLAS 的 gemm

addmm 的 CUDA 实现位置:
  文件: aten/src/ATen/native/cuda/Blas.cpp
  函数: addmm_out_cuda_impl
  功能: 调用 cuBLAS 或 cutlass

======================================================================
Layer 5: Kernel
======================================================================
观察工具:
  CPU: perf, gdb
  CUDA: nsys, ncu, cuobjdump

会看到:
  CPU: sgemm_ 或 dgemm_ (BLAS 函数)
  CUDA: kernel 名字如 volta_sgemm_128x128_nn

======================================================================
总结
======================================================================
每一层看到的名字和粒度都不同：
  L1: F.linear (用户 API)
  L2: THPVariable_linear (Python binding)
  L3: aten.t + aten.addmm (dispatcher 分解)
  L4: addmm_out_cpu/cuda (native 实现)
  L5: sgemm_ / volta_sgemm_* (实际 kernel)

关键：你在第 N 层看到的证据，只能证明第 N 层发生了什么。
