2. 同一组权重，四种口径下的实测占比
========================================================================
声明权重（按抽样概率）: {'web': 0.5, 'book': 0.25, 'talk': 0.25}，实际抽样 4000 次
源    | 声明 | 实测文档占比 | 实测 token 占比 | 期望 token 占比(p·L 公式)
web   | 0.50 |       0.5028 |          0.1044 |           0.1047
book  | 0.25 |       0.2515 |          0.7675 |           0.7667
talk  | 0.25 |       0.2457 |          0.1282 |           0.1286

声明的 50% 落在「被抽中的文档数」上。book 的平均长度是 web 的 14.6 倍，于是 25% 的文档权重换来 76.7% 的 token 权重。

========================================================================
折算后的抽样概率: {'web': 0.80791, 'book': 0.02758, 'talk': 0.1645}
源    | 目标 token 占比 | 实测 token 占比 | 实测文档占比
web   |          0.5000 |          0.4960 |       0.8085
book  |          0.2500 |          0.2495 |       0.0272
talk  |          0.2500 |          0.2545 |       0.1643
同一份目标，两套权重；写配方时必须说清 50% 是文档、样本、token 还是秒。

4. 时长口径：同一个音频源内部，秒和 token 也不成比例
========================================================================
  最慢 100 条:  34793 token /  15230.6 秒 = 2.28 token/秒，占该源 token 的 24.2%、占秒数的 42.7%
  最快 100 条:  35990 token /   5022.8 秒 = 7.17 token/秒，占该源 token 的 25.0%、占秒数的 14.1%
  talk 源整体 144062 token / 35636 秒
  按转写 token 配比和按音频小时配比会挑出不同的子集：慢速语音贡献的秒数远超它的 token 数。
  ASR 的监督量是转写 token，编码器成本按采样点/mel 帧算，两者必须分别记账。

5. 有放回抽样与重复 epoch
========================================================================
web 源 400 篇，在 2011 次抽取中被覆盖 396 篇，未被抽到 4 篇，最多的一篇被抽 13 次
无放回、重复 2 个 epoch（10 篇小集合）: [8, 3, 1, 4, 7, 0, 9, 6, 2, 5] / [1, 2, 4, 6, 5, 9, 7, 0, 3, 8]
有放回采样在一个 epoch 里既漏掉一部分文档也重复另一部分；只有无放回+重排才保证每轮覆盖一次。混合权重与覆盖率是两件事。

6. 阶段性课程混合：累计占比的轨迹
========================================================================
  截至第 2000 次抽样（当前阶段权重 {'web': 0.8, 'book': 0.1, 'talk': 0.1}）: 累计 token 占比 {'web': 0.3192, 'book': 0.5755, 'talk': 0.1053}
  截至第 4000 次抽样（当前阶段权重 {'web': 0.3, 'book': 0.5, 'talk': 0.2}）: 累计 token 占比 {'web': 0.1035, 'book': 0.8196, 'talk': 0.0769}
阶段切换后累计占比不会立刻跟上当前阶段的权重；报告数据配比时必须说明是瞬时权重还是累计消耗。

7. DistributedSampler 的尾部
========================================================================
  drop_last=False: 每 rank [[4, 3, 1], [0, 2, 4], [5, 6, 0]]，总条数 9，重复 [4, 0]，丢失 []
  drop_last=True: 每 rank [[4, 3], [0, 2], [5, 6]]，总条数 6，重复 []，丢失 [1]
7 个样本分给 3 个 rank：drop_last=False 靠重复补齐，drop_last=True 直接丢。两种都不是「每个样本恰好一次」，恢复时的样本清单要按实际取到的 ID 记录。

8. 真实配方里的权重字段与它们的单位
========================================================================
  SmolLM3 stage1: 41 个数据源，权重和 1.000000
  前 6 个源与按 train_steps 折算的 token 预算：
    dclm                   w=0.3700  归一化 0.3700  →   4.12T token
    fineweb-edu            w=0.3330  归一化 0.3330  →   3.71T token
    stack-edu-Python       w=0.0250  归一化 0.0250  →   0.28T token
    fw2-deu                w=0.0220  归一化 0.0220  →   0.24T token
    pes2o                  w=0.0200  归一化 0.0200  →   0.22T token
    fw2-spa                w=0.0200  归一化 0.0200  →   0.22T token
  单位来自加载器：tokenized_bytes.py:576-579 先把权重归一化，:589-590 用
  int((train_steps - it) * global_batch_size * w_i) 算样本数、再乘 sequence_length (4096) 得 token 数。
  这批数据已经预分词成等长序列，样本数与 token 数成固定比例，权重才等于 token 占比；
  同一份权重作用在变长文档上就变成文档占比。

  Qwen3-VL 的数据集名后缀：{'cambrian_737k%50': 0.5, 'mp_doc': 1.0, 'clevr_mc%25': 0.25}
  解析位置 qwenvl/data/__init__.py:38-44；消费位置 data_processor.py:277-280 是
  random.sample(annotations, int(len(annotations) * rate))——对 annotation 条目取样。
  一条 annotation 可能带 1 张图也可能带一段视频，因此 50% 的条目既不是 50% 的图像数，也不是 50% 的视觉 token 数。
