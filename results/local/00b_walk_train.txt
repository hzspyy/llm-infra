[1] 从 logits 到一个标量 loss
    logits           (1, 10, 18)        float32  contig=是  前4个: [+0.1560, +0.4895, -0.2074, +0.0675]
    per_token_loss   (10,)              float32  contig=是  前6个: [+2.8736, +3.0997, +3.3885, +2.9945, +2.6051, +2.1830]
    loss = per_token_loss.mean() = 2.995676

    交叉熵：位置 t 的 loss = -log p(正确字符)，p 来自 softmax(logits[t])。
    验证位置 0：正确字符 '吹'，p=0.056493，-log p=2.873633（脚本算出 2.873632）
    未训练时模型接近均匀分布，预期 loss ≈ ln(V) = ln(18) = 2.8904，实测 2.9957

    mean() 的分母是 10（有效 token 数）。真实训练里有 padding，
    那时必须用 mask 把 padding 位置排除，分母也只数有效 token（见 L7.0b）。

[2] 手算梯度 vs autograd
    先在一个两参数的函数上对拍，把链式法则写出来：
      f(a, b) = (a * b + a)^2，  取 a=2, b=3
      设 u = a*b + a = a(b+1)，f = u^2
      df/du = 2u
      du/da = b + 1,   du/db = a
      df/da = 2u(b+1), df/db = 2u·a
      代入 u = 8.0:  手算 df/da = 64.0, df/db = 32.0
      autograd:      df/da = 64.0, df/db = 32.0
      一致：True

    再看模型里最靠近 loss 的那一层：lm_head。
    交叉熵 + softmax 的梯度有一个简洁形式：dL/dlogits = (p - onehot(y)) / N
    其中 p 是 softmax 输出，N 是参与平均的 token 数（这里 N=10）。
    手算与 autograd 的最大绝对差 = 7.451e-09
    位置 0 的梯度前 6 个：手算 [+0.006362, +0.008880, +0.004424, +0.005823, +0.003122, +0.004670]
                              autograd [+0.006362, +0.008880, +0.004424, +0.005823, +0.003122, +0.004670]

    正确字符那一项的梯度是 (p-1)/N < 0，其余是 p/N > 0：
      降低正确字符的 logit 会让 loss 变大，所以梯度为负、更新时朝增大方向走。

[3] 反向需要前向的哪些中间值
    反向不是「再跑一遍前向」，它需要前向算出来的一些张量。
    PyTorch 把它们挂在计算图的节点上：
      loss.grad_fn 链（前 6 跳）：NllLossBackward0 -> LogSoftmaxBackward0 -> ViewBackward0 -> UnsafeViewBackward0 -> MmBackward0 -> ViewBackward0

    以 softmax+交叉熵为例：反向要用到前向算出的 p。
    所以 p 必须一直留在显存里，直到反向用完。这就是 activation memory。
    本例中 logits 本身就是 180 个 fp32 = 720 字节；真实模型里这一项是显存大头（L7.0/L7.1）。
    L2.6b 打印过完整的反向图：前向 11 个节点，反向 25 个。

[4] 一次参数更新改了什么
    lm_head.weight   (18, 32)           float32  contig=是  前4个: [-0.1212, -0.0809, +0.0522, -0.1445]
      .grad          (18, 32)           float32  contig=是  前4个: [+0.0017, -0.0146, +0.0118, -0.0236]
    梯度和参数**形状完全相同**：每个参数一个数。
    梯度范数 |g| = 1.765255

    (a) 最朴素的 SGD：w <- w - lr * g
      手算与 optimizer 的最大差 = 1.490e-08
      w[0,0]: -0.121226 -> -0.121391  (变化 -0.000165 = -0.1 × +0.001655)

    (b) AdamW：多了两个和参数等大的状态张量
      状态键：['exp_avg', 'exp_avg_sq', 'step']
      exp_avg          (18, 32)           float32  contig=是  前4个: [+0.0002, -0.0015, +0.0012, -0.0024]
      exp_avg_sq       (18, 32)           float32  contig=是  前4个: [+0.0000, +0.0000, +0.0000, +0.0000]
      w[0,0]: -0.121226 -> -0.221225

      第一步时 m/(sqrt(v)+eps) 经偏差修正后接近 sign(g)，
      所以每个参数的变化幅度都接近 lr=0.1，与梯度大小基本无关。
      代价：每个参数要多存 2 个 fp32 状态。参数 576 个 -> 权重 2304 B + 状态 4608 B = 6912 B。
      **优化器状态是权重的 2 倍**，这是训练显存账本的关键一项（L7.0b/L7.1）。

[A] 失败案例：labels 没有移位
      step      错误 loss      正确 loss
         0       3.1022       2.9957
        20       0.2592       0.2390
        40       0.0725       0.0668
        60       0.0332       0.0305
        80       0.0207       0.0191

    两条 loss 曲线几乎一模一样，错误版本没有任何异常表现。
    因为它学的是恒等映射：位置 t 的输入就是位置 t 的答案，
    模型只要把 embedding 抄到输出即可——这同样能把 loss 压到很低。
    **光看 loss 曲线分辨不出这个错误。** 分辨它要看生成结果：
      正确模型：'风吹过山谷，云落在水'
      错误模型：'风吹吹过过过过过过过'   ← 在复读输入

    训练脚本至少要有一个不依赖 loss 的检查：定期生成一小段看，
    或者在留出集上算指标（本例只有一条数据，无法留出）。

[B] 失败案例：detach 把梯度断在哪里
    正常                       tok_emb.grad = 范数 0.126201 | lm_head.grad 范数 = 1.728341
    对 embedding 输出 detach    tok_emb.grad = None | lm_head.grad 范数 = 1.728341

    detach 切断的是**这一条路径**上的梯度回传，它下游的参数照常拿到梯度。
    这正是冻结部分模块的做法（VLM 冻结 ViT、LoRA 冻结主干），见 L4.6 / L7.5。
