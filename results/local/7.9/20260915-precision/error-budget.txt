==============================================================================
A autocast 在 cpu 上把哪些算子降到低精度（实测输出 dtype）
==============================================================================

 autocast dtype = bfloat16
   linear                           → bfloat16
   matmul                           → bfloat16
   bmm                              → bfloat16
   conv1d                           → bfloat16
   scaled_dot_product_attention     → bfloat16
   softmax                          → float32
   log_softmax                      → float32
   layer_norm                       → float32
   cross_entropy                    → float32
   sum                              → float32
   mean                             → float32
   exp                              → float32
   pow2                             → float32
   rsqrt                            → float32
   silu                             → float32
   add(fp32,fp32)                   → float32

低精度组是 GEMM 类算子；softmax / 归一化 / CE / 归约留在 FP32。
这张表按设备分别成立，CPU 与 CUDA 的策略表是两份实现，不能互相推断。

  float16    delta=1.0e-02   → p=0.9902343750 变

BF16 在 1.0 附近的半 ULP 是 2^-9≈1.95e-3：小于它的更新整步消失，
这与梯度是否下溢无关，是参数写回时的舍入吸收。相对更新量 |Δ|/|p| 才是判据。

同一个数在不同 dtype 里是否为零：
  1e-05    float16=1.001e-05  bfloat16=1.001e-05  float8_e4m3fn=0.000e+00
  1e-07    float16=1.192e-07  bfloat16=1.001e-07  float8_e4m3fn=0.000e+00
  6e-08    float16=5.960e-08  bfloat16=6.007e-08  float8_e4m3fn=0.000e+00
  1e-40    float16=0.000e+00  bfloat16=9.184e-41  float8_e4m3fn=0.000e+00
FP16 的 1e-5、1e-7 落在次正规区仍非零；FP8 E4M3 在 1e-5 就归零。
是否 flush-to-zero 由具体算子和硬件路径决定，不能从存储格式直接推断。

C 长归约：累加 dtype 与累加顺序
==============================================================================
N=1000000，元素量级 1e-2，FP64 参照 = -8.145245141823
  float32    torch.sum=-8.145243645 相对误差=1.838e-07
             分块顺序累加=-8.145242691 相对误差=3.009e-07
             sum(dtype=fp32)=-8.145243645 相对误差=1.838e-07
  bfloat16   torch.sum=-8.125000000 相对误差=2.486e-03
             分块顺序累加=-8.250000000 相对误差=1.286e-02
             sum(dtype=fp32)=-8.158142090 相对误差=1.583e-03
同一份数据、同一个 dtype，换累加顺序就换结果；BF16 直接累加已不可用。
这解释了为什么 loss、归一化统计量和梯度归约都要指定更高的累加精度。

==============================================================================
D softmax / RMSNorm / cross entropy 的误差来源
==============================================================================
softmax：
  float32    最大绝对误差=1.443e-06 概率和偏差=1.812e-06
  bfloat16   最大绝对误差=1.490e-02 概率和偏差=2.360e-03
  float16    最大绝对误差=1.267e-03 概率和偏差=1.968e-04
  不做最大值平移时，FP16 的 exp(40) = inf （上溢，softmax 内部必须先减最大值）

RMSNorm 的统计量：
  float32    全程低精度=3.063520670 误差=1.228e-08 | 升精度求均值=3.063520707 误差=5.997e-11
  bfloat16   全程低精度=3.062500000 误差=3.332e-04 | 升精度求均值=3.063545910 误差=8.227e-06

cross entropy：
  logits float32    直接算=21.025588989 误差=4.208e-07 | 先转 FP32=21.025588989 误差=4.208e-07
  logits bfloat16   直接算=21.000000000 误差=2.559e-02 | 先转 FP32=21.026754379 误差=1.165e-03
  logits float16    直接算=21.031250000 误差=5.661e-03 | 先转 FP32=21.025661469 误差=7.206e-05
logits 一旦落到 BF16，先升精度也救不回已经丢掉的位；
autocast 把 CE 留在 FP32 指的是计算精度，不能替代 logits 本身的精度。

==============================================================================
E 前向、dX、dW、参数更新四处分别错多少
==============================================================================
误差口径：max|got-ref| / max|ref|，更新一列同时给 AdamW 首步的符号翻转比例
配置                                    前向          dX          dW        参数更新      符号翻转
FP32                            4.90e-07    9.63e-07    5.71e-07    1.50e-02     0.00%
FP32 + autocast BF16            3.26e-03    6.08e-03    5.19e-03    1.99e+00     0.18%
BF16 参数与计算                      3.57e-03    8.91e-03    6.91e-03    2.21e+00     0.23%
前向、dX、dW 三处误差逐级放大，量级与输入 dtype 一致。
参数更新一列反而最大：AdamW 首步的更新量约等于 ±lr，与梯度大小无关，
接近零的分量只要符号被扰动，整个更新就换方向。判断数值是否可用要看 dW，
不是看参数变化；反过来，更新看着正常也不代表梯度是准的。

F TF32 的表示：10 位尾数输入 + FP32 累加（CPU 模拟）
==============================================================================
  FP32         最大绝对误差=1.076e-04 相对 Frobenius 误差=4.075e-07
  TF32 模拟      最大绝对误差=3.330e-02 相对 Frobenius 误差=2.943e-04
  BF16 输入      最大绝对误差=3.818e-01 相对 Frobenius 误差=2.876e-03
TF32 与 BF16 的尾数分别是 10 位和 7 位，指数范围都与 FP32 相同。
TF32 是 matmul 的计算模式：张量仍以 FP32 存储和读写，它不是一种权重格式。
本段是 CPU 上的表示模拟，真实 TF32 kernel 的累加与分块另见 GPU 实测。
