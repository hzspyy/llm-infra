[B] 滑动窗口：KV 有了上界
==============================================================================
  full attention：KV 随上下文线性增长，无上界。
  滑动窗口（SWA）：只保留最近 W 个 token 的 KV，上界就是 W。
  代价：窗口外的信息完全看不到（除非靠层数堆出感受野）。

  以 Qwen3-1.7B 的配置算（28 层, 8 KV 头, D=128, bf16）
  每 token 每层 KV = 4096 B，全模型 114688 B
        上下文      full KV       W=4096       W=1024
       4096      448.0MB      448.0MB      112.0MB
      16384     1792.0MB      448.0MB      112.0MB
      65536     7168.0MB      448.0MB      112.0MB
     262144    28672.0MB      448.0MB      112.0MB
    1048576   114688.0MB      448.0MB      112.0MB

  上下文 1M 时 full 要 114 GB，W=4096 只要 448 MB —— 差 256 倍。
  更关键的是 **W 那两列不再增长**：显存与每步耗时都变成常数。

--- 实测：decode 每步耗时 vs 上下文 ---------------------------------------------------
  B=8 H=8 D=128 bf16
        上下文    full ms    W=4096 ms       加速
       4096     0.0909       0.0912    1.00×
      16384     0.6609       0.0907    7.29×
      65536     2.5253       0.0902   27.98×
     131072     5.5029       0.0910   60.49×

  W 固定之后，decode 每步耗时不随上下文增长 —— 这是 SWA 的全部卖点。

[C] 线性 attention：把 softmax 换掉之后
==============================================================================
  标准 attention：O = softmax(QK^T/√d) V，必须先算 QK^T（S×S）。
  线性 attention：把 softmax 换成一个可分解的核 φ(q)·φ(k)^T，于是
      O_i = φ(q_i) · Σ_{j<=i} φ(k_j) v_j^T  /  (φ(q_i) · Σ_{j<=i} φ(k_j))
  括号里那两个和是**可以增量维护的状态**（一个 d×d 矩阵 + 一个 d 向量）。
  于是：不需要 S×S，decode 时状态大小与上下文长度**无关**。

--- 复杂度对照（prefill，B=1 H=8 D=64） ---------------------------------------------
        S      标准 ms      线性 ms      标准/线性      标准峰值MB      线性峰值MB
      512     0.0556     0.4245      0.13×        1.0      130.0
     1024     0.1071     0.9224      0.12×        2.0      260.0
     2048     0.3458     1.8435      0.19×        4.0      520.0
     4096     0.8770     3.7624      0.23×        8.0     1040.0

  注意：这个朴素线性实现用 cumsum 物化了 S 份 d×d 状态，
  所以它的显存反而更大、也没有更快。**真实的线性 attention 用**
  **分块递推，不物化中间状态。** 这里量的是「朴素写法」，
  用来说明复杂度优势不会自动变成性能优势。

--- 线性 attention 换掉了什么：精确检索 -------------------------------------------------
  做一个最简单的检索任务：序列里埋一个 key-value 对，最后去查它。
  埋在位置 37，最后一个 query 指向它
  标准 attention 取回的向量 与目标的余弦相似度: 1.0000
  线性 attention 取回的向量 与目标的余弦相似度: 0.2393

  softmax 的指数放大让最大的那一项主导，可以做到近乎精确的检索；
  线性核没有这个放大，状态是所有 (k,v) 的加权和，信息被摊平了。
  这就是纯线性架构在「大海捞针」类任务上吃亏的原因，
  也是混合架构（几层 full attention + 多层线性/SSM）流行的原因。

[D] RoPE 与长上下文外推
==============================================================================
  从 config 读到：head_dim=128  rope_theta=1e+06  max_position_embeddings=40960
  rope_scaling = None

  RoPE 把 head_dim 拆成 64 对，第 i 对的角频率 = 1/base^(2i/d)
     第几对            角频率        周期(token) 说明
       0      1.000e+00              6.3  
       1      8.058e-01              7.8  
       8      1.778e-01             35.3  
      16      3.162e-02            198.7  
      32      1.000e-03           6283.2  
      62      1.540e-06        4080185.2  周期 > 训练长度 40960，从未转满一圈
      63      1.241e-06        5063256.0  周期 > 训练长度 40960，从未转满一圈

  关键：周期大于训练长度的那些维度，在训练时**从未见过完整的一圈**。
  推理时如果位置超过 40960，它们会进入训练中没出现过的角度区间 ——
  这就是长上下文外推失败的直接原因，不是「模型记不住」。

--- 三种 scaling 改的是什么 --------------------------------------------------------
  放大倍数 s = 4（想把 40960 撑到 163840）
  方案                 最高频周期(i=0)       中间(i=32)          最低频周期(i=63)
  原始                       6.28         6283.2            5063256.0
  PI                      25.13        25132.7           20253024.0
  NTK                      6.28        12705.4           20253024.0

  只看最低频那一列，PI 与 NTK **完全一样**（都 ×4）——
  NTK 的 base 放大公式本来就是这么设计的，让最低频恰好对上 PI。
  差别全在最高频那一列：
    PI  把 i=0 的周期从 6.28 拉到 25.13（×4）
    NTK 把 i=0 的周期从 6.28 拉到 6.28（×1.000，几乎不变）

  高频维度负责区分「相邻几个 token」。PI 把它也拉长 4 倍，
  等于让模型分不清近处的位置；NTK 保住高频，只拉低频。
  YaRN 在此基础上再按维度分段处理，并加一个注意力温度修正。

  **本 lab 只算了频率，没有测任何模型质量。**
  哪种 scaling 更好必须跑长上下文评测（大海捞针、长文困惑度），
  频率表只能说明它们改了什么，不能说明改得好不好。
