# 项目长期笔记（llm-infra）

规则以 `AGENTS.md` 为准，环境以 `ENVIRONMENTS.md` 为准，进度以 `STATUS.md` 为准。这里只记跨批次复用、且上面三份文件没写的做法。

## 引擎源码引用

- 被正文引用的 vLLM / SGLang 安装源码，**快照进 `results/<机器>/<批次>/source/<包路径>/`**，正文用项目相对路径 `{{srcfold:results/...}}` 引用。
- 不要在正文里写 `/Volumes/data/...` 或 `site-packages` 的绝对路径：`build.py` 会把 `ROOT / rel` 解析到项目外，站点因此依赖外部路径，发布后不可复现。
- 外置盘上的完整源码快照只作离线阅读与核对行号，不参与构建。

## 时延分解

- 做「A = B + C」这类减法前，先在源码里确认每个时间戳盖在**哪个进程**、覆盖到哪一步。vLLM 的 `arrival_time` 盖在前端进程、tokenization 之前，所以 `e2e − inference − queue` 是前端段；换个版本或引擎这条就不成立。
- 分解要验证闭合：各段相加应等于客户端墙钟（5.11 实测 0.79 + 0.005 + 76.32 + 0.63 = 77.75 ms）。不闭合说明有段重叠或遗漏。

## 实验设计

- 先量混淆项，再隔离主效应。5.11 想测「tokenization 阻塞事件循环」，直接上真实请求时引擎 prefill 带来 373 ms 扰动，把 11 ms 的主效应完全淹没；改成只做编码的对照端点后才测出来。
- 对照组的规模要跨过主效应的量级。主效应小于噪声时，结论只能是「测不出」，不能写成「没有影响」。
- 同一配置重复运行出现大差幅（5.11 并发 32 的 p50 差幅 > 20%）时，只写方向，不写绝对值，并在正文标注「这条趋势未解释，不要引用」。
