## 机制拆解与推导

### SFT 的监督位置

设 prompt 与 response 拼成 token 序列。若配方只监督回答，则 label 中 prompt 和 padding 为 -100，回答与真实 EOS 保留 token ID。标准 causal shift 使用 `logits[:, :-1]` 预测 `labels[:, 1:]`：

$$L=-\frac{\sum_{b,t}m_{b,t+1}\log p_\theta(x_{b,t+1}\mid x_{b,\le t})}{\sum_{b,t}m_{b,t+1}}.$$

最后一个 prompt 位置的 logit 会预测第一个回答 token，因而可能有梯度；prompt embedding 也会通过上下文影响回答。屏蔽 prompt labels 不等于冻结 prompt 表征。多轮 SFT 可以监督多个 assistant turn，也可以只监督选定回答，取决于数据目标。

当 pad token ID 等于 EOS，不能直接把所有 `ids==eos_id` 的 label 设为 -100；应以真实长度/attention mask 区分结束符和补齐位置。回答截空时，应在归约与 optimizer 前统一处理空监督，而不是对空集合取 mean。packing 还要分别隔离 attention 和跨文档 shift target，见 [7.8](7.8-training-data-engineering.html)。

### LoRA 的低秩更新与第一次梯度

对 $W_0\in\mathbb R^{d_o\times d_i}$：

$$W=W_0+sBA,\quad A\in\mathbb R^{r\times d_i},\ B\in\mathbb R^{d_o\times r},\quad s=\alpha/r.$$

冻结 base，只优化 A/B 时，参数量为 $r(d_i+d_o)$。普通 Linear LoRA 的常见初始化是 A 随机、B=0，使初始增量为零。此时第一轮数据梯度对 A 为零，对 B 可以非零；A 有 `.grad` tensor 不等于数值非零。后续 B 非零后，两者都可以获得梯度。

零增量初始化是一种选择，不是所有 adapter 初始化算法的普遍要求。`alpha/r` 是标准缩放，也有 `alpha/sqrt(r)` 等变体；改变 r 后是否调整学习率需按 recipe 验证，不能由公式保证。

部署可保留旁路，也可合并为 $W_{merged}=W_0+sBA$。合并后必须禁用/移除旁路，否则增量被加两次。浮点求和次序变化会带来舍入差，量化 base 的反量化/重量化还有额外误差。adapter checkpoint 通常需要匹配 base、target_modules、rank/alpha、模板和可能的额外模块；它不是包含 optimizer/RNG 的完整 resume checkpoint。

### DPO：序列 log-ratio 与偏好梯度

设 $\ell_w=\log\pi_\theta(y_w|x)$、$\ell_l=\log\pi_\theta(y_l|x)$，冻结 reference 的值为 $\ell_w^{ref},\ell_l^{ref}$，令：

$$a=\beta(\ell_w-\ell_w^{ref}),\quad b=\beta(\ell_l-\ell_l^{ref}),\quad L_{DPO}=-\log\sigma(a-b).$$

Bradley–Terry 模型比较奖励差；在 KL 正则目标 $E[r]-\beta KL(\pi\Vert\pi_{ref})$ 下，奖励可用 $\beta\log(\pi/\pi_{ref})+\beta\log Z(x)$ 重参数化，Z 在 chosen/rejected 差值中消去。DPO 不需要单独训练一个 reward model 来计算这个偏好目标。

$$\frac{\partial L}{\partial\ell_w}=-\beta\sigma(b-a),\qquad\frac{\partial L}{\partial\ell_l}=+\beta\sigma(b-a).$$

这是把两个 sequence logprob 视为坐标时的梯度；实际参数共享与其它样本会共同决定更新，不能保证每一步所有 chosen 概率都上升。β 同时进入分类 margin；固定 log-ratio 下的极限梯度不等于完整训练中的必然漂移规律。

### 长度风险需要连同 reference 分析

标准 DPO 通常使用回答 token 的 sequence logprob 和。若 policy=reference，50 token 与 5 token 的两项 log-ratio 都为零，loss=log 2；长度本身没有产生非零隐式奖励差。偏好数据、逐 token 偏差累积、截断、模板与归约仍可能导致长度相关行为，需要受控验证。

把 sequence sum 改为 length mean 会改变目标，不是普适修复。reference 必须保持固定监督语义；若直接用同一个可微 policy logprob 同时充当 reference，差值恒等于零，参数梯度会抵消。独立但未冻结的 reference 是另一种问题，不能据这个 alias 反例推断其必然立即坍缩。

### APO-zero 与 APO-down

固定 TRL 的两个 APO 分支使用上述 a、b：

$$L_{zero}=1-\sigma(a)+\sigma(b),$$
$$L_{down}=\sigma(a)+1-\sigma(a-b).$$

令 $s'(u)=\sigma(u)(1-\sigma(u))$，则 APO-zero 对 chosen/rejected logprob 的梯度为 $-\beta s'(a),+\beta s'(b)$；APO-down 为 $\beta[s'(a)-s'(a-b)],+\beta s'(a-b)$。APO-down 的 chosen 总导数包含两项，不能仅看第一项判断每次更新方向。

这里没有统一的序列长度除法或 SimPO 式 target margin。APO 选择不同的 anchoring 行为，不由此保证消除所有长度偏置。[SmolLM3 固定 APO YAML](../../results/local/7.3/20260914-review-fixes/source/handbook/recipes/smollm3/dpo/apo.yaml)使用 `apo_zero`、β=.05、LR=1e-6、max_length=24576，并从 `it-SFT` 接续；完整阶段配方见 [7.3](7.3-training-frameworks.html)。

### 设计取舍

| 方法 | 更新对象 | 主要额外成本 | 导出依赖 |
|---|---|---|---|
| full fine-tuning | 选定全参数 | 参数梯度与 optimizer 状态 | 完整模型与配置 |
| LoRA | 低秩 A/B，可能有额外模块 | 旁路计算与 adapter 状态；冻结 base 仍参与输入梯度 | base、adapter 或合并权重 |
| QLoRA | 低秩参数，base 低位宽冻结 | 反量化、量化元数据和计算 dtype | 匹配量化 base 与 adapter |
| QAT/QAD | 按 recipe 更新参数/量化器 | fake quant 或实际量化路径、教师等 | scale、量化配置与目标 loader |

容量和速度必须按 dtype、模块形状和实际执行测量。full fine-tuning 未必总比 LoRA 快，低位宽 base 也不自动获得低位宽反向 GEMM；优化器状态不是一律额外 12 字节/参数，见 [7.9](7.9-optimizer-mixed-precision.html)。

## 完整教学项目：SFT 与独立评测（7.5-I）

I 任务把 7.1-F 的预训练权重接上一次真正的 SFT，并用与预训练隔离的数据做独立评测。数据来自 [7.8](7.8-training-data-engineering.html) 的 `data-sft`：8,000 条训练会话（3,231,598 个回答 token）、621 条验证、592 条测试，监督只落在 assistant 段，模板在数据准备阶段就确定化。

训练入口 `labs/L7/teaching_sft.py` 与上游 `train_full_sft.py` 对齐的部分：lr $1\times10^{-5}$、BF16 autocast + FP32 master、clip 1.0、assistant 段 label 规则；本项目增加的是验证曲线、梯度记录、best 选择与导出。协议：micro-batch 8、累积 2（16 条/step）、900 步（约 1.8 个 epoch）、每 150 步在 621 条验证集上评一次。

loss 用**有效回答 token 加权**：每个 batch 返回 CE 的 sum 与有效 token 数，累计后再相除。这样长短样本、最后一个不满 batch 都不会改变分母——按样本平均会把 500 token 的长回答和 3 token 的短回答等权，两者对不同 task 的贡献完全不同。

| val CE（回答 token 加权） | 2.4131 | 2.3496 | 2.3218 | 2.3087 | 2.3024 | **2.2991** |

验证 loss 到 900 步仍在下降，没有回升，所以 best 与 last 都是第 900 步。同一个评测协议（固定题号、贪心、两个生成长度上限）跑预训练 base 与 SFT 权重：

|---|---:|---:|

| char-F1，生成上限 384 token / 100 题 | 0.1345 | **0.2999** |

四条判读：

**CE 与 F1 都指向同一方向。** test CE 降 0.504 nats，留出 char-F1 在公平协议下从 0.1345 升到 0.2999（相对 +123%）。这是"SFT 确实改变了任务行为"的证据。

**exact match 是 0，而且这个判据在本协议下不可达。** 测试集参考答案的监督 token 数 p50 = 433、p90 = 638、均值 407，第一轮评测把生成上限设成 128 token，结构上不可能逐字匹配。把上限提到 384 后仍然 0，因为参考答案是数百 token 的开放式文字，"逐字相同"本身就不是合适的判据。**这是协议缺陷，不是模型结论**：先定义可判定的指标再跑评测，比事后解释 0 分更重要。第一轮的 128 token 数字保留在原始现场里，不覆盖。

**格式子技能只学到了一半。** SFT 让 `<think>` 结构从 0% 出现升到 50%（参考 30%，属于过度生成），但 `<tool_call>` 只做到 2%（参考 14%）——工具调用需要精确的 JSON 结构与参数，8000 条样本、1.8 个 epoch 不足以稳定学到。**结构 token 比内容 token 更容易被 SFT 捕捉**，这条差异只有在分开统计时才看得见。

**生成上限改变 F1 的方向。** base 在 128 上限下 F1 反而更高（0.1723 对 0.1345），因为它本来就啰嗦，放开长度后多余内容拉低精确率；SFT 放开长度则从 0.2647 升到 0.2999。同一个指标在不同生成长度下可以给出不同的排序，所以 F1 必须与生成协议一起报。

### 遗忘

同一个 SFT 权重回到预训练留出集上：

| 数据 | base | SFT | 变化 |
|---|---:|---:|---:|
| 预训练 val CE | 2.2889 | 2.3959 | +0.107 |
| 预训练 test CE | 2.3294 | 2.4471 | +0.118 |

SFT 让语言建模能力退化了约 0.11 nats。这个量级不大，但它是真实存在的——**只看 SFT 任务指标会漏掉这部分代价**。要说清是否"灾难性遗忘"需要更长的训练和更广的评测，本项目只报这一组数字。

### 验收结论

协议在训练前声明：CE 必须下降；留出 char-F1 相对 base 至少提升 20%；tool-call 任务按"参考里有 tool_call 的样本中生成也出现 tool_call"的比例判定，目标 ≥ 0.5；exact match 不作主判据。结果是：CE 通过（−0.504），char-F1 通过（+123%），tool-call 未通过（0.02 对参考 0.14），遗忘已量化（+0.11 nats）。**未通过的项按计划保留，不用训练 loss 或单条样例替代。**

## 完整教学项目：后训练分支（7.5-J）

两个分支从同一个 SFT 起点（7.5-I 第 900 步的 `best.pt`）出发，各自在 4 GPU 小时预算内连续训练到预先声明的停止条件，并且都与原 SFT 起点比较。训练的循环是 `labs/L7/teaching_lora.py` 与 `labs/L7/teaching_dpo.py`：模型、注入方式、数据装载和损失都复用上游 MiniMind 实现，本项目补充逐步记录、held-out 曲线、步级 checkpoint、续训与导出。DPO 在启动时把本脚本的 `logits_to_log_probs`/`dpo_loss` 与上游 `trainer/train_dpo.py` 的同名函数在固定随机 batch 上对拍，logprob 最大差与 loss 差均为 0，不一致就直接退出。

### LoRA 领域适配

数据来自 [7.8](7.8-training-data-engineering.html) 的工具子集：任一会话轮带 `tool_calls`、或 system 消息带 `tools` 的样本进入候选，再按内容哈希切分，得到 7,925/978/1,097 条 train/val/test。这个子集的一个结构事实决定后面所有判据：**92.3% 的测试样本在对话中某处出现 `tool_calls`，但没有一条出现在最后一轮**——末轮全都是普通 content。也就是说，同一个测试集可以问两个不同的问题："给定需要动手的上下文，会不会发起工具调用"和"给定工具结果，末轮会不会按参考格式直接作答"。

协议：rank 16 注入所有方阵 Linear，共 16 个模块、32 个张量、393,216 个可训练参数，占全模型 64.31M 的 0.61%；AdamW 只拿 LoRA 参数，lr $1\times10^{-4}$ 余弦退到 10%，micro-batch 32，1,000 步（约 4 个 epoch），BF16，clip 1.0。运行 138.5 s、消费 3.63M 回答 token、峰值 8,780 MiB、约 0.10 s/step，占分支预算的 0.96%。

**判据必须先与参考的监督语义对齐，否则同一个数字可以读出相反结论。** 末轮参考全是 content，所以"生成里出现 `<tool_call>`"在这个切法下衡量的是**格式漂移**，越低越贴近参考；把切点移到首个带 `tool_calls` 的 assistant 轮之前，同一批题才在问工具调用能力。两个切法的结论完全相反：按末轮口径，适配后从 0.1667 掉到 0.0500，看起来像能力退化；按工具调用切法，函数名命中从 0.0667 升到 0.8917。协议写错一步，方向就会反过来——这与 7.5-I 里 exact match 在 384 token 上限下不可达是同一类问题。

**0.61% 的参数拿到了结构行为的大部分收益。** LoRA 的函数名命中 0.8917 高于全参的 0.7667，而两者的内容 F1 排序相反（0.6452 对 0.7146）。结构 token 是离散的格式决定，内容质量是连续分布拟合，两个目标对"更新容量"的需求不同。差异的机制本轮没有定位：要区分需要扫 rank 与步数，本轮只取了一个主配置。

**"只更新少量参数"不等于"遗忘更少"。** 预训练 val CE 两臂几乎相同（+0.019 对 +0.018），但留出 SFT 分布上 LoRA 退化更多（2.3266 对 2.3024）。冻结 base 保证的是原始权重不被改写，不保证输出分布不被推向新数据。

**合并是近似。** 16 个模块的 `B@A` 并入权重后与旁路推理的 logits 最大差 0.219、均值 0.0158（BF16 下"两次 matmul"与"一次 matmul"的差别）。合并前后逐位相同不成立，部署前要按容差检查，这与 [5.10](../L5/5.10-lora-multitenant.html) 的服务侧结论一致。

### DPO 偏好优化

偏好数据来自上游公开的 `dpo.jsonl`：扫描 17,166 对，丢掉 39 对命中有限粗筛词表的样本（规则与命中数写进 manifest），reservoir 采样后按内容哈希切成 8,000/477/458 对。协议：beta 0.15、lr $4\times10^{-8}$ 余弦退到 10%、micro-batch 4（一个 batch 实为 8 条序列，前一半 chosen 后一半 rejected）、max_len 1024、2,000 步（1 个 epoch），reference 固定为 SFT 起点。运行 121 s、消费 5.32M 偏好 token、峰值 5,523 MiB、约 0.052 s/step，占分支预算的 0.84%。

运行内部的 held-out margin 在 128 条验证对上逐步上升，没有出现回升：

| step | 250 | 500 | 750 | 1000 | 1250 | 1500 | 1750 | 2000 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| margin 均值 | −0.0861 | −0.0311 | −0.0294 | 0.0014 | 0.0244 | 0.0471 | 0.0696 | **0.1100** |
| 正 margin 比例 | 0.445 | 0.500 | 0.461 | 0.539 | 0.594 | 0.547 | 0.539 | 0.578 |

best 与 last 都是第 2000 步。换到 300 条测试对上独立复算，并同时记录偏好与任务两个轴：

| 指标 | SFT 起点 | DPO（第 2000 步） |
|---|---:|---:|
| 策略 log-ratio 均值 | −47.3189 | −47.0523 |
| margin 均值（相对起点） | 0.0000（同权重的自检） | **+0.2666** |
| 正 margin 比例 | 0.0000 | 0.6367 |
| 预训练 val CE | 2.3959 | 2.3966 |
| SFT test CE | 2.2851 | 2.2851 |
| 留出生成 char-F1（384 token 上限） | 0.2647 | 0.2706 |

**偏好 margin 上升没有转成可测的任务质量。** 每对平均 +0.2666 nats 的偏好改善在同一批题上只带来 +0.006 的 char-F1，通用能力与 SFT 分布上的 CE 都没有可辨变化（+0.0007 nats 的预训练 CE 差落在噪声内）。按计划这属于"训练偏好准确率不等于全部收益"的保留项：DPO 确实改变了偏好方向，但没有证据说明它改变了这批开放式问答的可用性。

**评测节奏会扰动训练流。** DPO 数据集的 `__getitem__` 用全局 Python RNG 决定是否去掉空 think 块，而 held-out margin 评测会取用该数据集，于是 `--eval-every` 的取值改变了后续 batch 的模板随机性。同一配置、只改评测间隔的两次运行因此给出不同的 margin 曲线。这是 [7.8](7.8-training-data-engineering.html)"固定 seed 不保证可复现"的一个具体形态：随机性不只来自初始化和采样，也来自数据管道被读取的次数。

## 前沿

多 adapter 服务把匹配同一 base 的增量共享加载，真实路由、合并、量化和输出验证见 [5.10](../L5/5.10-lora-multitenant.html)。QAT/QAD、视觉/语音/动作模型的 adapter target 和训练目标分别核对。当前小例未完成公开 16 样本与 TRL SFTTrainer 的逐 token 对拍，也未运行 bitsandbytes QLoRA；这些不因 PyTorch CE 或 Linear round-trip 通过而成为已验证能力。

## 陷阱

`target_modules` 与 `modules_to_save` 分别决定低秩注入和额外完整模块的保存，不能只按 adapter 文件大小估算训练容量。模板/词表不匹配会改变 logprob 的语义，影响幅度要实际测量。adapter 保存后要检查 base 身份和 rank/alpha，合并后要移除旁路；冻结 base 也不等于前向无需保存任何反向所需值。

## 自测题

1. 普通 LoRA 的 B=0 时，A 有 `.grad` 是否说明第一步 A 获得非零数据梯度？

::: fold
不是。对 A 的链式导数含 B，因此第一步数据梯度为零；B 可以有非零梯度。优化器 decay/动量的作用还要另看。
:::

2. 50 token 的回答概率比 5 token 的低，是否足以证明 DPO 必然偏短？

::: fold
不足。DPO 比较 policy/reference 的 log-ratio。两者相同则两条 log-ratio 都是零；长度影响需要连同 reference、数据与归约分析。
:::

3. APO-zero 是否等于 DPO 加长度归一化和 target margin？

::: fold
不是。固定实现为 1-sigmoid(a)+sigmoid(b)，APO-down 为 sigmoid(a)+1-sigmoid(a-b)。应使用对应公式与 recipe，不能按名称推断优化行为。
:::
