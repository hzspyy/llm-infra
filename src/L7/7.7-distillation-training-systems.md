## 本章回答的三个问题

1. 教师提供的是文本、概率、隐藏特征还是连续场，哪些量作为条件、哪些量作为目标？
2. CE、forward/reverse KL 与 generalized JSD 怎样定义 mask、归一化和学生梯度？两家真实实现的**分母口径**差在哪里？
3. 教师特征怎样离线生产、消费和恢复；导出契约如何决定学生的部署形态？

**关键要点**：

- 教师信号分两类角色：作**条件**（hidden 特征）与作**监督**（token 分布、序列、场）。同一实验里两种角色可以并存，但 loss target 只有后者。
- 分子相同、分母不同就是不同目标：EAGLE3 的 `LogSoftmaxLoss` 除以 `B×T`，DFlash 的 CE 除以权重之和，TRL 按 completion 有效位置归约。
- 离线特征库必须先定义身份字段与 ACK 协议，否则"缓存命中"可能命中过期数据。

## 机制拆解与推导

### 教师信号与目标分类

| 方法 | 教师提供什么 | 学生优化什么 | 不能混淆的边界 |
|---|---|---|---|
| sequence KD | 教师生成的 token 序列 | 这些序列上的 CE | hard target 丢掉完整概率分布 |
| logit KD | 对齐位置/词表的概率或 logits | KL、reverse KL 或 JSD | 相同词表大小不保证 token 语义相同 |
| feature KD | 隐层表征 | 投影后的 MSE 等 | 表征维度/层语义需对齐 |
| EAGLE3 draft | 多层教师特征作为条件，教师 token 分布作为监督 | token prediction（soft-target CE 或 LK 变体） | 输入特征不是 hidden-MSE target |
| DFlash draft | 教师 hidden 作条件，按块并行的逐位置 CE（可带位置衰减） | 块内每个位置的 token 预测 | 分母是权重之和，不是 `B×T` |
| 连续场蒸馏 | teacher velocity/noise/score 或轨迹端点 | 按所选方法定义的场/一致性/分布目标 | 减少 NFE 与压缩模型参数是不同收益 |
| QAD | 高精度教师与量化学生 | 在量化路径下的质量恢复目标 | 不等于仅做领域 SFT 或一次 PTQ 校准 |

teacher `eval()` 控制 dropout 等行为，`no_grad()`/detach 控制梯度路径，Parameter 是否在 optimizer 中控制更新；三者不是同一个开关。

### 四种目标与解析梯度

对一个有效位置，令 $p=softmax(z_s/T)$、$q=softmax(z_t/T)$，教师 q 视为常量；$y$ 为 one-hot label。未乘 $T^2$ 时：

$$L_{CE}=-\sum_i y_i\log p_i,\qquad \frac{\partial L_{CE}}{\partial z_{s,i}}=\frac{p_i-y_i}{T},$$
$$L_F=KL(q\Vert p),\qquad \frac{\partial L_F}{\partial z_{s,i}}=\frac{p_i-q_i}{T},$$
$$L_R=KL(p\Vert q),\qquad \frac{\partial L_R}{\partial z_{s,i}}=\frac{p_i}{T}\left[\log\frac{p_i}{q_i}-KL(p\Vert q)\right].$$

对 $0<\beta<1$，令 $m=\beta q+(1-\beta)p$：

$$L_J=\beta KL(q\Vert m)+(1-\beta)KL(p\Vert m),$$
$$\frac{\partial L_J}{\partial z_{s,i}}=\frac{(1-\beta)p_i}{T}\left[\log\frac{p_i}{m_i}-\sum_jp_j\log\frac{p_j}{m_j}\right].$$

所有位置再乘有效 mask 并除以有效位置数。教师 detach 使梯度只回到学生；空 mask 的 mini 返回可微零值，但训练应用还应统一处理是否推进 optimizer/scheduler。

固定 TRL API 特别规定：`beta=0` 选择 forward KL，`beta=1` 选择 reverse KL，内部值使用上面的 JSD。端点是显式分支；不能把 interior JSD 趋近端点时的零值当成它的 API 行为。

forward KL 会惩罚学生漏掉教师有概率的区域，reverse KL 对学生放在教师低概率处的质量更敏感。常说的 mode-covering/seeking 是受模型族和优化限制影响的倾向；无限表达能力下二者都在 p=q 取最小，不能直接推断某方向必然改善代码准确率或降低幻觉。

### 高温近似需要中心化

令 $\bar z=\frac1V\sum_i z_i$，在 logits 相对温度较小时：

$$softmax(z/T)_i=\frac1V+\frac{z_i-\bar z}{VT}+O(T^{-2}).$$

所以 forward KL 的梯度约为：

$$\frac{\partial L_F}{\partial z_{s,i}}\approx\frac{(z_{s,i}-\bar z_s)-(z_{t,i}-\bar z_t)}{VT^2}.$$

乘 $T^2$ 可以补偿这个高温主导尺度；它是目标权重的选择，不是所有 KD 算法的必要条件。固定温度 T=4 时，乘 T² 后梯度确实是该温度未乘版本的 16 倍，但不意味着它等于 T=1 的梯度。本机 FP64 实测三种梯度范数为 0.8320819、0.0694284、1.1108544。

若学生 logits 与教师只差常数，softmax 完全相同，KL 梯度应为零；缺少均值项的公式会在这个最小反例上失败（实测残差 4.5e-15 与 9.1e-15，与数值零一致）。

### 分母口径：同一分子配不同分母

三家实现的分母各不相同，这是"看起来都在做 KL/CE"却得到不同训练目标的直接原因：

| 实现 | 分子 | 分母 | 结果 |
|---|---|---|---|
| EAGLE3 `LogSoftmaxLoss` | $\sum_v q_v(\log\sum_j e^{z_j}-z_v)$，乘位置 mask | `B×T` 全部行数 | 被 mask 的位置仍占分母 |
| DFlash `loss_type=dflash` | $\sum \mathrm{CE}_i\cdot w_i\cdot e^{-(p_i-1)_+/\gamma}$ | $\sum w_i$（权重之和） | 有效位置决定尺度，衰减改变权重 |
| TRL DistillationTrainer | 分块 JSD/KL，按有效 completion 位置求和 | completion 有效计数（含 DDP 补偿） | 生成长度变化会改变尺度 |

本机用同一批 FP64 logits/target 直接比较前两家：把一半位置 mask 掉后，DFlash 口径与 EAGLE3 口径的比值恰为 **2.0**（分母分别是 4 与 8）。这不是谁"错"，而是两家定义的目标不同；跨库迁移必须换成对方的分母，否则等价于改学习率。

### DFlash 的块 mask 与位置衰减

DFlash 一次前向预测整个 block：Q 有 `N×block_size` 行，KV 由 `S` 个 context 槽加 `N×block_size` 个 draft 槽组成。按 `create_dflash_block_mask`（`dflash_family_model.py:234`）的语义：

- **context**：`kv_idx < S` 且**严格小于**该 block 的 anchor 位置（inference 时 anchor 位本身不可见）；给了 `sliding_window` 时再加下界 `anchor + q_offset - (window-1)`；
- **draft**：`kv_idx >= S`、与该 query 同一 block，且（有窗口时）`kv_block_offset <= q_offset`；
- 整行再乘 `block_keep_mask[b, block_id]`，无效块全屏蔽。

逐位置 loss 用 draft logits 对 target token 的 CE，按 `w = mask × exp(-(pos-1)_+/γ)` 加权（`dflash_family_model.py:723-746`）。本机小例取 `γ=2`、block=4：块内权重为 `[1.0, 1.0, 0.6065, 0.3679]`，平均权重 0.7436，带衰减的 loss 2.6154 与不衰减的 2.6551 不同——衰减改的是目标权重，不是数值噪声。

### acceptance rate 与 LK 变体

SpecForge 的 acceptance 定义是逐 token 的期望接受率 $\sum_v \min(p_{target,v}, p_{draft,v})$，再对有效位置取 masked mean；`log_acceptance_rate` 对严格大于 0 的位置取对数后同样取均值。三种 LK 目标（`lk_loss.py:83`）：

- `alpha`：$-\overline{\log \mathrm{acc}}$
- `tv`：$1-\overline{\mathrm{acc}}$
- `lambda`：$w\cdot KL + (1-w)\cdot(1-\overline{\mathrm{acc}})$，$w = \texttt{kl\_scale}\cdot e^{-\texttt{kl\_decay}\cdot \overline{\mathrm{acc}}.\mathrm{detach}()}$

本机小例的接受率 0.4491、$w=0.6382$，四种目标的梯度范数分别为 0.2932（纯 KL）、0.2059（alpha）、0.0956（tv）、0.2069（lambda）。把 acceptance 当"评估指标"而把 LK 当"loss 正则"都低估了差别：它们改变的是被优化的目标本身。

### 导出契约

`specforge export --to sglang` 目前只实现 EAGLE3 的 serving key 契约：`to_sglang.py:38` 的 `_REQUIRED_SERVING_KEYS = ("fc.weight", "norm.weight", "lm_head.weight", "t2d", "d2t")`；DFlash、DFlash2、Domino、DSpark、P-EAGLE 用 `--to hf`（`docs/sections/basic_usage/training.md:583`）。`to_hf.py` 按需读取 target embedding 而不物化 target lm_head。训练前缀残留与 key 归一化由 `normalize_draft_head_checkpoint_keys` 处理。

### 设计取舍

在线学生生成让教师监督学生会访问的上下文，但不会"彻底消除"分布偏差，也增加生成与教师前向成本。分块词表投影省峰值缓冲，checkpointing 用重计算换内存；离线特征可减少重复教师前向，却需要严格缓存身份、存储带宽与 ACK 协议。分母、衰减、mask 和损失方向改变的是目标，不能当成任意可互换的性能开关。

## 完整教学项目：蒸馏学生（7.7-J）

教师是 [7.5](7.5-rl-infra.html) 的 SFT 权重（768/8，63.91M 参数），学生是同一个 tokenizer 与词表（6400）下的 512/8（30.03M 参数，占教师 47.0%），随机初始化。同词表意味着 teacher/student 的 logits 下标逐位置对齐，可以直接做逐位置 KL，不需要跨词表映射。数据沿用 7.8-I 的 `data-sft`（8,000/621/592 条，3.23M 回答 token），监督只落在 assistant 段的有效位置上。损失取上游 `train_distillation.py` 的默认口径：

$$L=\alpha\,\mathrm{CE}+(1-\alpha)\,T^{2}\,\mathrm{KL}\!\left(p_{s}^{(T)}\,\|\,p_{t}^{(T)}\right),\qquad \alpha=0.5,\ T=1.5,$$

其中 $p^{(T)}$ 表示温度 $T$ 下的 softmax。脚本启动时用固定随机 batch 与上游 `distillation_loss` 对拍，本次运行的对拍差为 0。

### 软标签与纯监督的等预算对照

两个 arm 的数据、步数、lr、初始化完全相同，只有 $\alpha$ 不同：在线 KD（$\alpha=0.5$）与纯 CE（$\alpha=1$）。10,000 步、micro-batch 16、lr $1\times10^{-4}$ 余弦退到 10%。621 条验证样本上的 CE：

| step | 1000 | 2000 | 3000 | 4000 | 5000 | 6000 | 7000 | 8000 | 9000 | 10000 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 在线 KD | 4.4996 | 3.8291 | 3.5064 | 3.3356 | 3.2425 | 3.2104 | **3.2085** | 3.2185 | 3.2356 | 3.2486 |
| 纯 CE | 4.5996 | 3.9768 | **3.7606** | 3.7709 | 3.9383 | 4.1895 | 4.4435 | 4.6898 | 4.8868 | 5.0304 |

两条曲线的差别不只是水平，还有形状：纯 CE 在第 3,000 步见底后一路变坏（3.76→5.03），而 KD 在 7,000 步见底后基本平坦（3.21→3.25）。训练集上纯 CE 的 loss 降到 0.883，KD 停在 1.319（其中 CE 分项 1.623）——**学生把容量用去拟合硬标签的噪声时，验证集立刻反映出来；教师分布把它拉回了可泛化的方向**。教师前向的代价是墙钟 +56.8%、峰值显存 +27%。

| 指标 | 教师（SFT 768/8） | 学生 · 在线 KD | 学生 · 纯 CE |
|---|---:|---:|---:|
| SFT test CE（回答 token 加权） | **2.2851** | 3.1431 | 3.6821 |
| 留出生成 char-F1（128 token 上限） | 0.2647 | 0.3075 | 0.2889 |
| 预训练 val CE（语言建模能力） | **2.3959** | 4.9817 | 5.4706 |
| 训练墙钟 | — | 532.7 s | 339.9 s |
| 峰值显存 | — | 5,791 MiB | 4,552 MiB |

三条判读：

**蒸馏在三个轴上同向获胜。** 任务 CE（3.14 对 3.68）、语言建模 CE（4.98 对 5.47）、验证曲线的最优点（3.21 对 3.76）都指向同一结论，而且优势在训练越久时越大：这正是"软标签不只是更多信息，也是更少的噪声"的直接证据。

**学生的绝对质量仍远低于教师，缺口来自预算而不是方法。** 30.03M 的学生只见过 3.23M 回答 token 的 SFT 数据，没有经过 [7.1](7.1-training-loop-systems.html) 的 98M token 预训练；它的 test CE 3.14 对教师 2.29。把这条差距归因于蒸馏失败是错的，把它当作"蒸馏已复现规模结果"也是错的。

**char-F1 与 CE 的排序矛盾，说明它不能当质量判据。** 学生在 char-F1 上（0.3075）甚至高于教师（0.2647），而 CE 差 0.86 nats。这个指标按字符多重集重叠计分，重复常见字就能拿到高分，因此它只在同一模型的两种配置间做粗对照时才有意义；本章不据它给学生与教师排序。

### top-k 教师缓存：换目标，不是省一步

把教师监督离线成每个位置 top-64 的 logits，512 条样本共 50.7 MiB（101.3 KiB/样本），教师被截断的概率质量平均 8.52%、最大 18.63%。缓存把尾部词表合并成一个"其余"桶，用学生在该支持集上的残差质量补齐——**KL 对类别合并不保值，所以这是另一个目标，不是全词表 KL 的数值近似**。在同一个随机初始化学生上，全词表 KL 为 9.819、合并尾部 KL 为 16.063，相对差 63.6%。

同一 512 条子集、同样 2,000 步的两个 arm：

| 指标 | 在线 KD | top-64 缓存 |
|---|---:|---:|
| 最佳验证 CE | **5.7302** | 6.0054 |
| SFT test CE | **5.6456** | 5.9190 |
| 留出 char-F1 | 0.2516 | 0.2561 |
| 训练墙钟 | 108.1 s | 72.4 s |
| 峰值显存 | 5,734 MiB | 4,630 MiB |

缓存在这个规模上换来 −33% 墙钟、−19% 峰值显存和"训练循环里没有教师进程"，代价是约 0.27 nats 的验证 CE。101.3 KiB/样本 与同一位置全词表 fp16 logits 的 19.46 MB/样本（见上文「特征库」的字节账）相差约 188×。这个比率说明缓存的真正价值在教师前向的重复使用次数：本轮每个样本只被消费 62.5 次（2,000 步 × 16 / 512），教师前向本来就不贵；要让离线缓存划算，需要更小的教师/学生成本比或更多的复用次数。

## 生成模型与语音蒸馏的目标契约（7.7-G/H）

Latent consistency distillation、distribution matching 与语音两阶段蒸馏都用"蒸馏"这个名称，但目标、教师角色与状态完全不同。这一节先用一维解析场把两类目标的梯度流验证清楚，再定位四份公开实现的阶段与接口。

### LCM：边界条件是参数化，不是惩罚项

diffusers v0.40.0 的 SDXL LCM 训练脚本把一致性损失写成三步（行号取自仓库内快照）：

| 环节 | 位置 | 内容 |
|---|---|---|
| 边界缩放 | `train_lcm_distill_sdxl_wds.py:331` | $c_{\text{skip}}=\sigma_d^2/(\tilde\sigma^2+\sigma_d^2)$、$c_{\text{out}}=\tilde\sigma/\sqrt{\tilde\sigma^2+\sigma_d^2}$，$\sigma_d=0.5$、$\tilde\sigma=t\cdot10$ |
| 引导尺度 | `:397` | 把采样到的 $w\sim U[w_{\min},w_{\max}]$ 变成 embedding 注入 U-Net |
| 在线学生 | `:1358` | `model_pred = c_skip_start·x_start + c_out_start·pred_x0` |
| 教师轨迹 | `:1423`、`:1428` | CFG 组合出 $x_0,\epsilon_0$，再走一步 `solver.ddim_step` 得到相邻点 $x_{\text{prev}}$ |
| 一致性目标 | `:1453` | `target = c_skip·x_prev + c_out·pred_x0` |
| 损失 | `:1457` | `F.mse_loss(model_pred, target)` |
| EMA | `:383`、`:1474` | `update_ema(target_unet.parameters(), unet.parameters(), ema_decay)` |

一维两分量高斯混合场（均值 $\pm1.5$、标准差 $0.5$，VE 扩散 $x_\sigma=x_0+\sigma\varepsilon$，去噪器取解析后验均值）上的检查：

| 检查 | 结果 |
|---|---|
| 初始一致性 MSE / 一次 SGD(0.05) 后 | 5.0768 → 0.6053 |
| autograd 梯度 vs 中心差分 | 三项最大绝对差 1.95e-3（差分步长 1e-4） |
| $\tilde\sigma=0$ 处的 $c_{\text{skip}}/c_{\text{out}}$ | 1.000 / 0.000 |
| $\tilde\sigma=0$ 处 $\lvert f(x,0)-x\rvert$ | 0.0 |
| $\tilde\sigma=0$ 处 $\partial f/\partial\theta$ 的最大绝对值 | **0.0** |

两条判读：

**边界条件落在参数化里，不产生梯度。** 因为 $c_{\text{skip}}(0)=1$、$c_{\text{out}}(0)=0$，$t=0$ 处输出恒等于输入，对参数的导数精确为 0——不需要额外的正则项去"鼓励"它，也不会在这里浪费优化预算。这也解释了为什么 LCM 的采样器只需要很少步数：每一步都在把 $x$ 往 $x_0$ 拉，而端点已被结构固定。

**一次损失里有两个"教师"。** 提供轨迹点的是冻结的 `teacher_unet`（原 SDXL 与 CFG），提供一致性目标的是 `target_unet`——学生的 EMA。把两者都叫"教师"会掩盖一个事实：**EMA 目标随学生移动，冻结教师不动**；前者带来稳定性，后者带来方向。对照上文 7.7-J 的文本蒸馏，那里只有一个冻结教师，学生的正则来自软标签本身。

### DMD2：真假 score 之差就是一个可用的梯度

DMD2 的 SD 训练循环里，生成器与 guidance（critic）是两套优化器、两条更新路径：

| 环节 | 位置 | 内容 |
|---|---|---|
| 两套优化器 | `train_sd.py:191`、`:197` | `optimizer_generator` 与 `optimizer_guidance` 各自 AdamW + scheduler |
| 交替比例 | `:330` | `COMPUTE_GENERATOR_GRADIENT = step % dfake_gen_update_ratio == 0` |
| 生成器回合 | `:360` | `generator_turn=True`，可带/不带生成器梯度 |
| 两项损失 | `:369`、`:372` | `loss_dm`（分布匹配）与 `gen_cls_loss`（分类）各有权重 |
| 逐步更新 | `:376`、`:405` | 两个优化器分别 `step()` |

在同一维高斯族上把生成器写成 $x=\mu_\theta+s_\theta\varepsilon$，真假 score 都解析可写，于是估计量 $\mathbb{E}[(s_{\text{fake}}-s_{\text{real}})\,\partial x/\partial\theta]$ 可以与 $\mathrm{KL}(p_{\text{fake}}\|p_{\text{real}})$ 的解析梯度逐项对拍：

| 项 | 估计量（4096 样本） | 解析梯度 | 绝对差 |
|---|---:|---:|---:|
| $\partial/\partial\mu$ | 1.9907 | 2.0000 | 0.0093 |
| $\partial/\partial\log s$ | −0.6388 | −0.6400 | 0.0012 |

差落在蒙特卡洛噪声量级，说明"score 之差乘 $\partial x/\partial\theta$"确实是 KL 梯度的无偏估计——DMD2 不需要真实的似然或反向扩散。接着跑 6 次交替更新（critic 用假样本上的最小二乘拟合假 score，生成器沿 KL 梯度走 0.05）：

| 交替步 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---:|---:|---:|---:|---:|---:|
| KL（更新后） | 1.9733 | 1.7787 | 1.6029 | 1.4461 | 1.3013 | **1.1705** |
| $\mu$ | 1.8991 | 1.8042 | 1.7140 | 1.6293 | 1.5473 | 1.4696 |
| $s$ | 0.6203 | 0.6400 | 0.6593 | 0.6775 | 0.6965 | 0.7156 |

$\mu$ 从 2.0 向真值 0 移动、$s$ 从 0.6 向 1.0 移动，KL 单调下降。要注意这里 critic 与目标 score 同属线性族，critic 损失恒为 0：**这条检查证明的是梯度流方向正确，而不是 critic 容量够用**。

生成侧的三种"变快"必须分开说：LCM 减少的是**采样 NFE**（同一个模型学会跳步），草稿蒸馏减少的是**每步验证成本**（[5.5](../L5/5.5-speculative-decoding.html)），换 solver 只是**同一模型换积分器**——三者都不改变"模型压缩"这件事，也不能互相替代。

### 语音两阶段蒸馏与 QAT/QAD

ZipVoice 的 Emilia 配方有 12 个阶段，`run_emilia.sh` 把它们写成同一条流水线：

| 阶段 | 命令 | 关键参数 |
|---|---|---|
| 1 数据准备 | `local/prepare_emilia.sh` | — |
| 2 基础训练 | `zipvoice.bin.train_zipvoice` | `--world-size 8` |
| 3 权重平均 | `zipvoice.bin.generate_averaged_model` | `--epoch 11` |
| 4 蒸馏第一段 | `zipvoice.bin.train_zipvoice_distill` | `--num-iters 60000`、`--base-lr 5e-4`、`--teacher-model zipvoice/exp_zipvoice/epoch-11-avg-4.pt`、`--distill-stage first` |
| 5 再平均 | `zipvoice.bin.generate_averaged_model` | 对第一段蒸馏产物 |
| 6 蒸馏第二段 | `zipvoice.bin.train_zipvoice_distill` | `--num-iters 2000`、`--base-lr 1e-4`、`--teacher-model exp/zipvoice_distill_1stage/iter-60000-avg-7.pt`、`--distill-stage second` |
| 7–8 ONNX 导出 | `zipvoice.bin.onnx_export` ×2 | 基础模型与蒸馏学生各一份 |
| 9–12 推理 | `infer_zipvoice` / `infer_zipvoice_onnx` ×4 | PyTorch 与 ONNX、基础与蒸馏交叉 |

两处结构性事实：**教师永远是"平均后的 checkpoint"**（基础阶段取 `epoch-11-avg-4`，第二段的教师是第一段的 `iter-60000-avg-7`），所以权重平均不是可选的收尾，而是下一阶段的输入契约；**第二段的教师是第一段的学生**，两段是接续而不是并行。两段的预算差 30 倍（60,000 vs 2,000 迭代）、学习率差 5 倍（$5\times10^{-4}$ vs $1\times10^{-4}$），"少跑几步"这种说法完全掩盖了这个结构。

ModelOpt 的 `examples/llm_qat` 把两条路线放在同一份参数表里：29 个参数键里既有 QAT 的校准项（`--calib_size`、`--calib_batch_size`），也有独立的 `--distill` 开关（全文 8 处蒸馏/教师相关表述）。两者的状态归属不同：QAT 只需要 fake-quant 模块与量化器状态；QAD 还要教师前向、logits 存储与两者之间的对齐策略。**量化恢复与领域适配是两个问题**：前者要求恢复被量化破坏的分布，后者要求模型学会新任务，用同一份"训练后更好"的曲线去证明另一件事不成立。

## 前沿

- **草稿训练目标分家**。EAGLE3 把多层教师特征当条件、用 token 分布监督；DFlash/DFlash2 走块并行预测并按位置衰减加权。两者的 mask、分母和导出契约都不同，SpecForge 也明确 `--to sglang` 只覆盖 EAGLE3 的 key 契约，其余走 `--to hf`。收益最终要计入 target 验证、接受长度与完整请求成本，而不是只报"草稿几倍加速"。
- **在线蒸馏 API 的分化**。TRL 的 `DistillationTrainer` 与 experimental GKD 在采样、loss 与数据流上不同，升级要按真实入口迁移，不能只改类名。
- **连续场与语音蒸馏**。LCM、DMD2、ZipVoice 面对不同的场、状态与评估对象；ModelOpt 的 QAD 是量化路径下的质量恢复，不等于领域适配。本章未执行这些训练与导出，相关规模与质量结论保持 `UNVERIFIED`。

## 陷阱

- **分母不是细节**。同一分子换成另一家的分母，等价于改学习率；本机实测两家差 2.0 倍（一半位置有效时）。
- **mask 的位置**。EAGLE3 的 `LogSoftmaxLoss` 把 mask 放在分子、分母仍是 `B×T`；DFlash 的分母是权重之和。把两者混用会在长序列/稀疏监督下产生系统性尺度漂移。
- **不同 tokenizer 的同一 logit 下标未必是同一个 token**，不同切分下的序列位置也不对齐。跨词表需显式概率映射、序列级监督或其它经过验证的目标，不能直接逐元素 KL。
- **特征缓存的身份**。teacher revision、模板、token 切分、层号或 dtype 任一变化都会让离线记录失效；本章特征库对四类不符各拒绝 24/24 条，说明校验必须逐字段。
- **ACK 之前都算未提交**。消费者崩溃后从 ACK 日志继续，重放未 ACK 的队尾；把"文件已写"当"消费已完成"会重复计数。
- **温度、T² 与中心化**。温度改变概率形状，T² 只改变固定温度下的权重；高温近似必须减去各自均值，否则常数平移会产生非零梯度。

## 自测题

1. 学生与教师 logits 相差常数时，高温公式为什么要减去各自均值？

::: details 答案

softmax 对常数平移不变，概率和 KL 梯度应相同。中心化后两组 logits 的差为零；省略均值会错误产生非零梯度（本机反例残差 4.5e-15 与 9.1e-15，与数值零一致）。

:::

2. 固定 TRL 的 beta=.3 与 beta=0 分别是什么目标？

::: details 答案

内部 .3 使用 generalized JSD，mixture=.3q+.7p；端点 0 显式选择 forward KL。该 API 的端点不是直接把内部 JSD 公式代入得到的零。

:::

3. EAGLE3 输入了教师 hidden states，为什么不能说它做 hidden-MSE？

::: details 答案

输入条件与 loss target 不同。固定 SpecForge 路径将 draft logits 与教师 token 分布比较（`LogSoftmaxLoss`，分母 `B×T`），并可选择接受率相关的 LK 分支；hidden states 是条件，不是该路径中的 MSE 回归目标。

:::

4. 同一批 logits 分别用 EAGLE3 与 DFlash 的口径计算，为什么数值会差 2 倍？

::: details 答案

EAGLE3 的分母是全部 `B×T` 行，被 mask 的位置仍占分母；DFlash 的分母是加权 mask 的和。一半位置有效时分母分别是 8 与 4，比值恰为 2.0。迁移实现时必须换成目标库的分母。

:::

5. 特征库为什么需要 ACK，而不是写完文件就算缓存可用？

::: details 答案

写文件只表示生产者完成；消费者可能读到一半崩溃。ACK 日志是"已消费"的唯一凭据，重启后未 ACK 的记录会被重放。本机崩溃测试：第 5 条退出后重启，处理 19 条补齐 24 条，重复 0。

:::
