## 机制拆解与推导

### 三种目标，三种分母

图文因果模型先得到视觉 token，再与文本 embedding 拼接，并通过 causal self-attention 让文本位置访问视觉前缀。设 labels 中无监督位置为 -100：

$$L_{CE}=\frac{-\sum_{b,t}m_{b,t+1}\log p_\theta(y_{b,t+1}\mid z_{b,\le t})}{\sum_{b,t}m_{b,t+1}}.$$

label 的 shift 必须与 logits 对齐。视觉前缀本身没有词表 target；最后一个视觉位置可以预测第一个文本 token，和语言模型的条件前缀语义一致。若只拼接后逐位置 Linear，文本位置不能读取视觉信息，即使 loss 能 backward，也没有实现图文条件学习。

连续 flow 目标用端点 $x_0,x_1$ 构造：

$$x_t=(1-t)x_0+tx_1,\quad u_t=x_1-x_0,$$
$$L_{flow}=\frac{\sum_{b,f,d}m_{b,f}(v_\theta(x_t,t,c)_{b,f,d}-u_{b,f,d})^2}{d\sum_{b,f}m_{b,f}}.$$

模型必须实际依赖 noisy latent、时间和条件。分母是有效坐标数，不是 batch 数；改成先对每条序列取均值再平均，会改变不等长样本的权重。

对比目标使用图像与文本的归一化表征 $a_i,b_j$，相似度 $s_{ij}=a_i^Tb_j/\tau$：

$$L_{contrast}=\tfrac12[CE(s,\operatorname{arange}(B))+CE(s^T,\operatorname{arange}(B))].$$

它按样本对聚合，与按 token 或坐标归一化的目标不同。重复样本或语义等价的“负例”会改变任务含义，扩大 batch 也不仅是改变计算量。

### loss 数值不决定梯度比例

组合 $L=L_{CE}+0.5L_{flow}+0.1L_{contrast}$ 时，对共享参数 $\theta$：

$$\nabla_\theta L=\nabla_\theta L_{CE}+0.5\nabla_\theta L_{flow}+0.1\nabla_\theta L_{contrast}.$$

权重作用于梯度，loss 的数值比不能替代梯度比。例如在 $\theta=0$，$L_1=3.5+0.001\theta$、$L_2=0.015+10\theta$，loss 之比约 233，而梯度分别为 .001 和 10。给 loss 加常数能改变值而完全不改变更新。

应分别记录共享参数与各 head 的梯度范数、方向和更新量。本章逐参数记录每项 loss 的梯度范数；权重 .5/.1 是固定实验设置，没有经任务质量调优，也没有据此证明多任务平衡最优。

### 冻结、无梯度与缓存

| 控制 | 参数梯度 | 输入梯度 | 前向执行 | optimizer 状态 |
|---|---|---|---|---|
| encoder 参数 `requires_grad_(False)` | 无 | 输入需要梯度时仍可有 | 执行 | 未加入 optimizer 则无 |
| encoder 在 `no_grad()` 中运行 | 无 | 此段图被截断 | 执行 | 不自动删除既有状态 |
| encoder 输出 `detach()` 后缓存 | 无法经缓存回传 | 此路径不传回 | 命中缓存时不执行 | 解冻后仍需重新建图 |
| 解冻并添加参数组 | 可有 | 可有 | 执行 | 首次有效 step 时建立 m/v |

缓存身份至少包括数据版本、processor、增强随机性、encoder revision/dtype 与布局。冻结权重只是必要条件之一；随机裁剪变化、输入梯度需求或解冻都会使旧特征不适用。只执行 `requires_grad_(True)` 不会自动把参数加到已建好的 optimizer。

### 真实架构需要不同阶段表

| 路线 | 输入融合方式 | 主要监督与阶段边界 |
|---|---|---|
| OpenCLIP 式双 encoder | 图像/文本各自编码，在相似度矩阵相遇 | 图文对比目标；两个 encoder 的更新由 recipe 决定 |
| Qwen3-VL | 视觉特征替换文本序列中的视觉占位，另有 DeepStack 特征路径 | 文本 CE 可经融合路径到 vision/merger，是否更新还取决于冻结配置 |
| Flamingo | 语言层中的 gated cross-attention 接入视觉特征 | 视觉条件与语言序列通过专门的跨注意力模块交互 |
| Chameleon | 图像经 tokenizer 成为离散 token，与文本在早期统一序列中融合 | token-based early fusion，不能归入 Flamingo 的 cross-attention 路线 |
| diffusion / flow | noisy latent、t 与条件进入生成网络 | 噪声、速度或其它 prediction type，按配方定义 target |
| Qwen3-Omni | AuT/vision encoder、Thinker、Talker、MTP、Code2Wav 协作 | 文本理解、codec 生成与波形重建具有不同模块和目标 |

[Chameleon 原论文](https://arxiv.org/html/2405.09818v1)明确其 early-fusion token-based 设计。[Qwen3-Omni 报告](https://arxiv.org/html/2509.17765v1)分别描述 Thinker/Talker MoE、Talker 的多码本预测和因果 ConvNet Code2Wav；不能因为有统一推理入口，就把它们写成一个自回归 Transformer 或声称一次文本 SFT 更新全部模块。

语音 ASR、codec、TTS 和动作模型同样先有独立训练目标。采样率、码本、动作 horizon 与 normalizer 是接口的一部分；把 LLM 的 adapter target 列表复制到这些模型，无法代替模块与目标检查。

### optimizer 的重复参数检查

原生 `Optimizer.add_param_group` 会检查新组与已注册组是否共享同一 Parameter：组间重复抛 ValueError。组内重复是另一个分支，部分版本会警告并重复更新；必须按实际版本观察。

{{srcfold:results/local/review/20260914-chapters/source/torch__optim__optimizer.py}}

### 设计取舍

共享 backbone 可以复用表征，但每个目标的 mask、归约单位与梯度方向必须显式定义。分离 head 容易隔离输出格式，独立 head 不会仅因另一项 loss 数值大就自动失去梯度。冻结和缓存减少计算，却改变梯度可达性及数据增强自由度；解冻还会新增 optimizer 状态，并可能改变分布式 bucket 和内存峰值。本章未测分布式 bucket 重建，不能用 CPU 参数组实验代替。

## 完整教学项目：视觉适配两阶段（7.10-J）

结构沿用 MiniMind-V 的思路：冻结视觉塔、训练 projector、把视觉 token 的 embedding 替换进语言模型序列。本实现用 CLIP ViT-B/32（224²，去掉 CLS 后 49 个 patch token，视觉塔 87.46M 参数全部冻结），projector 为 LayerNorm + Linear + GELU + Linear（1,182,720 参数，形状与 MiniMind-V 的 `MMVisionProjector` 一致），语言侧复用 [7.5](7.5-rl-infra.html) 的 SFT 权重（768/8，63.91M）。与 MiniMind-V 的差别是视觉塔换成 CLIP、视觉 token 49 个而非 64 个；与 [4.6](../L4/4.6-vlm-encoder-connector.html) 的 Qwen3-VL 相比则少了 DeepStack 式多层注入与更深的 connector。

数据是本地合成的形状图案问答：224×224 画布上放 3–9 个红/绿/蓝的圆/方/三角，提问"图中有几个{颜色}{形状}？"。被提问的三个组合的计数固定取 $\{0,1,2\}$ 的一个排列，因此每张图的三个答案恰好覆盖 0/1/2 各一次，**留出集的答案分布是精确的 1/3 均分**。这一条是判据能不能用的前提：如果答案集中在某个值（例如自然分布下 0 占 59.7%），"每题都答同一个数字"就能拿到接近 60% 的分数，指标测的是先验而不是计数。语料共 1,292 张图、3,000/402/402 条 train/val/test 问答，按图像内容哈希做图像级隔离。它是合成图案语料，不是公开 VQA 数据集，结论不外推到真实图像。

判据是留出问答的贪心精确匹配（取回复中第一个数字），并在同一批题上做三种图像条件：

- `normal`：用自己的图；
- `shuffle`：按**图像**整体轮换（不是把行下标平移），保证换来的图一定不同——每条样本的 3 个问答共用一张图，行平移会让 2/3 的样本拿到原图，对照失效；
- `blank`：换成纯白图。

| arm | 可训练参数 | 步数 | lr | normal | shuffle | blank | 墙钟 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 未适配（随机 projector + SFT LLM） | 0 | — | — | 0.3308 | 0.3259 | 0.3333 | — |
| 恒定答案上限 | 0 | — | — | 0.3333 | — | — | — |
| align（仅 projector，描述目标） | 1.18M | 1500 | $5\times10^{-4}$ | 0.2065 | 0.2065 | 0.2836 | 45.9 s |
| 两阶段 sft（对齐→联合） | 65.09M | 1500 | $1\times10^{-4}$ | 0.3209 | 0.3209 | 0.3209 | 45.0 s |
| 单阶段长预算 | 65.09M | 6000 | $3\times10^{-4}$ | **0.3881** | 0.3159 | 0.3060 | 160.9 s |
| 两阶段长预算 | 65.09M | 6000 | $3\times10^{-4}$ | 0.3756 | 0.3184 | 0.3333 | 161.3 s |

四条判读：

**未适配基线与恒定答案完全重合。** 随机 projector + 已 SFT 的语言模型在三档图像条件下分别是 0.331/0.326/0.333，与恒定答案上限 0.333 同档，且换图不改变任何东西——这正是"图像完全没有进入答案"的样子。把这条基线写进协议，才能判断后面的提升是不是真的来自图像。

**1,500 步的两阶段既没超过先验，也对图像不敏感。** `normal`、`shuffle`、`blank` 三档完全相同（0.3209），说明模型对输入图像是常量函数；单独的 align 阶段更极端：`normal` 与 `shuffle` 精确相等（0.2065）且低于先验，只有 `blank` 不同（0.2836），即 projector 只编码了"有没有图"这一位信息。

**长预算下模型才开始从图像读数，而且是一次相变。** 6,000 步、lr $3\times10^{-4}$ 时验证准确率在前 4,000 步恒为 0.3333，第 5,000 步 0.3159、第 6,000 步 0.4328；留出测试上 `normal` 0.3881 比恒定上限高 5.5 个百分点，而 `shuffle` 掉回 0.3159、与 `blank` 0.3060 同档。**换图掉到先验档**才是"读图"的证据，单看 `normal` 高于上限并不够。相同的架构与数据在 1,500 步只能学到期望值，说明这个台阶卡在优化预算而不是容量上限。

**对齐阶段在预算充足时没有带来收益。** 同样 6,000 步，两阶段（0.3756）略低于单阶段（0.3881），两者的换图对照都掉回先验档。在冻结语言模型上做描述目标的对齐，在这套 3k 图 / 12k 问答的规模下信号太弱；这也解释了为什么 1,500 步的对齐产物会低于先验。

训练前声明的质量条件是：留出精确匹配高于恒定上限至少 10 个百分点，且换图对照下降至少 5 个百分点。两个长预算 arm 都通过换图条件（下降 7.2 / 5.7 个百分点），但准确率只高 5.5 / 4.2 个百分点，**没有达到声明的准确率门槛**。因此 7.10-J 记为"已执行、质量未达标"：视觉信息确实被用上了，但计数能力远未达到可作为完整视觉适配项目的水平。四个 arm 合计约 7 分钟 GPU（0.12 GPU 小时）、峰值 2,206 MiB，瓶颈是样本效率（同一批 12k 问答被重复 16 遍）而不是算力。

**同一个模型的两条配方，更新对象可以完全不同。** Cosmos 的生成分支只把生成路径与两个 connector 放进优化器，Reasoner 分支不限制参数——"同一基座的 SFT"这句话不包含任何参数范围信息，必须回到 `keys_to_select`/`freeze_filter` 这类字段。

**冻结的位置决定了它能不能被检查。** Cosmos 与 openpi 用配置表达冻结（可解析、可检查）；MiniMind-V 把视觉塔冻结写在模型类的构造里，命令行看不到——所以"读配置就能知道哪些参数会动"并不普遍成立，这也是 [7.3](7.3-training-frameworks.html) 的只读检查器的边界。

**Qwen3-TTS 的 SFT 是多字段监督。** 同一批里同时有 `codec_ids`、`codec_embedding_mask`、`codec_0_labels`、`codec_mask`，说话人嵌入来自冻结的 `speaker_encoder`——把 TTS 微调当成"给文本算 CE"会丢掉码本层级与掩码这两组分母。

**openpi 的动作视野就是监督窗口。** `action_horizon=10` 同时决定模型输出维度、损失里的动作元素数与评测的归一化统计；改它等于改目标，不是改 batch。

### 异构 batch 与缓存身份

`--section hetero` 把两件可算的事做成检查。第一件是分桶：64 条样本混合了 3 种分辨率、4 种帧数、3 种音频长度与 3 种动作视野，按"整批 padding 到最大"需要 909,568 token，而实际内容只有 202,568（**+349% 浪费**）；按 `(分辨率, 帧数)` 分成 12 个桶后只需 204,803（**+1.1%**），把 padding 浪费消掉 99.7%。第二件是缓存身份：键包含 `model_revision`、`processor_hash`、`augmentation_seed`、`crop`、`time_sampling`、`stochastic_posterior`、`trainable_state` 七个字段，改动其中任何一个都会换键——包括"参数已冻结但换了增强"这一情形。

| 检查 | 结果 |
|---|---|
| 整批 padding 相对内容 token | +349%（909,568 / 202,568） |
| 按 (分辨率, 帧数) 分桶 | +1.1%（12 个桶），浪费减少 99.7% |
| 混合流里各分支被使用的条数 | 视觉 64、视频 43、音频 24、动作 45（共 64 条） |
| 七个身份字段各自改动 | 全部换键 |
| 冻结参数 + 换增强种子 | 仍然换键 |

**"参数冻结"不是缓存可复用的充分条件**：冻结只说明权重不变，增强、crop、时间采样与 processor 都会改变输入分布，而随机 posterior（VAE 采样）还会让同一张图在不同 epoch 得到不同的 latent。把这些字段放进键，才谈得上用缓存换计算。同理，混合流里只有 24/64 条带音频、45/64 条带动作用域，**未使用分支必须显式跟踪**：否则某个 rank 拿到全文本 batch 时，其他 rank 还在等一次永远不会发生的 collective。

### 跨阶段失败定位（7.10-I）

多模态训练最贵的错误不是"loss 不降"，而是"loss 正常下降、监督接在了错的地方"。`labs/L7/multimodal_failure_localization.py` 用四个小实现给出每个错误的**可观测差别**与**定位判据**：

| 故障 | 症状 | 可观测差别（实测） | 先查什么 |
|---|---|---|---|
| 图像仍在编码，答案 mask 写错 | 两种 mask 下 loss 都下降 | 只监督回答 5 个位置时 loss 2.1784、把 prompt 也算进去 9 个位置时 2.1725；图像梯度范数 0.0409 / 0.0170，**都非零** | 打印被监督位置数（5 vs 9）。梯度非零只证明图像进了计算图，不能证明监督位置对 |
| 音频 codec 对不上 | 训练正常，合成时长系统性偏移 | 训练帧率 12.5 Hz → 2.0 s 得 25 帧，加载的 codec 25 Hz → 50 帧（**2.0×**）；越界 id 在严格查表下 IndexError，在 clamp 实现下静默取到别的行 | 断言 `max(id) < codebook_size` 且 `frames == round(duration·frame_rate)`；loss 对 2 倍时长错位完全不敏感 |
| flow 的 prediction_type 用错 | 换个目标 loss 依然下降 | velocity 目标与**符号相反**的 velocity 目标 loss 地板相同（0.9374 / 0.9375），但用后者走一步欧拉得到的样本均值 −0.0055，数据均值 0.9714 | 先用"完美模型应达到 0 loss"核对目标构造式；再比采样均值与数据均值——**两个目标可以同 loss、反方向** |
| 动作 normalizer 用错来源 | 三种归一化都能收敛 | 用错来源统计量时 MSE 0.6238，正确统计量 0.2478（**2.5×**）；存储均值/标准差与训练集的漂移 5.46 / 2.97。而"完全不归一化"在本例反而 0.0738——Adam 的逐参数缩放吸收了量纲差异 | 比对存储统计量与训练集实际统计；"必须归一化"的直觉依赖优化器与数据，但**统计量来源错误**是可判定的 |

四条判读：

**判据要挑对可观测量。** 这四个用例里 loss 曲线全部"正常"，mask 用例的梯度、flow 用例的 loss 地板甚至完全相同。可区分的信息分别落在"被监督位置数""帧数与码本范围""采样均值""统计量漂移"上——它们都不在 loss 里。

**同 loss、反方向比"loss 偏高"更危险。** flow 的符号错误给出几乎一样的 loss 地板（差 1e-4），因为 $(x_1-x_0)$ 与 $-(x_1-x_0)$ 的方差相同；只有把采样结果与数据分布对齐比较才能发现。

**"必须归一化"要按优化器说。** 上表里不做归一化反而更好，因为 Adam 对每维做自适应缩放；换成 SGD 或需要共享步长的场景结论会反过来。**能站得住的判据是"归一化统计量与训练集一致"，不是"归一化一定有益"。**

**每个模态要有固定的验证输入与指标。** 视觉看留出问答精确匹配、打乱/移除图像对照与文字能力回归；语音看 WER/说话人相似度/首包时延/码本层级对拍；扩散看留出目标误差、固定噪声的样本与多样性、采样 NFE；动作看逐维离线误差、归一化对齐与闭环成功率。这些都作为跨阶段调用的固定入口，避免"换了阶段就换一套评测"。

## 前沿

Omni、视频/世界模型和 VLA 把更多条件与产物放到同一应用中，训练仍需按模块×阶段记录输入、目标、更新参数和导出依赖。Cosmos 各 SFT 配方要按选中的生成分支分析；Qwen3-Omni 的 Thinker、Talker、Code2Wav 公开程度和训练入口分别核对。尚未复现的联合训练、分布式 bucket 行为和全流程导出保持 `UNVERIFIED`。本章三目标小例只提供监督与梯度检查的方法。

## 陷阱

只打印总 loss 会隐藏分支断图和错误分母；只看 `requires_grad` 会漏掉未进入 optimizer 的参数；只比较 loss 数值会误判梯度竞争；只看模块出现在前向图里会夸大“全模型微调”的范围。对缓存、adapter 和阶段权重，还应检查版本、参数 key、processor 与输出格式是否共同恢复。

## 自测题

1. encoder 权重冻结后，为什么 images 仍可能有梯度？

::: fold
参数不求梯度不等于停止整段 autograd。若输入 requires_grad=True，后续 loss 仍需要 encoder 对输入的导数。no_grad 或 detach 才会切断这条路径。
:::

2. 两个参数组各含同一个 Parameter，原生 AdamW 会静默更新两次吗？

::: fold
不会，组间重复在添加参数组时抛 ValueError。组内重复是独立情形，本章另外捕获该版本的警告/更新行为，不能混用。
:::

3. 图文 CE 能下降，为什么仍需改变图像再检查 logits？

::: fold
模型可能只靠文本路径拟合，图像根本没有影响文本输出。输入依赖检验与逐目标梯度表能发现这种结构错误；loss 下降本身不足以证明条件使用或任务质量。
:::
