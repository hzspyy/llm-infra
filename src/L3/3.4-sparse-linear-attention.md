## 本章回答三个问题

3.3 从 bf16 MHA 的简化模型说明了历史 KV 读取成本。本章进一步比较减少可见位置和压缩历史状态的两条路线。
GQA/MLA 走的是"每个 token 少存点"。这一章看另一条路：**少读一些 token**，
以及更激进的——**把 softmax 换掉，让状态大小与上下文无关**。

1. 只保留最近 W 个 token 会怎样？为什么不能简单地把旧的丢掉？
2. 线性 attention 把 $O(S^2)$ 变成 $O(S)$，它用什么换的？
3. 长上下文外推为什么会失败？RoPE scaling 到底改了什么？

::: warning 这一层大部分还在变动
本章没有安装和测试 NSA、MoBA 的具体实现，
Mamba 类混合架构需要专门的权重。所以本章严格分两类：
**能在这张卡上直接测的**（attention sink、滑动窗口、线性 attention 的复杂度与检索能力、
RoPE 频率表），和**只能按定义算的**。凡是算出来的都明确标注。
:::

## 一 · attention sink：真实模型里的一个反常现象

先看一个现象，它决定了滑动窗口能不能简单地做。

拿 Qwen3-1.7B 跑一段 26 token 的文本，把注意力权重取出来
（`attn_implementation="eager"` + `output_attentions=True`），
看**最后一个 query 分给第 0 个 token 多少注意力**。
如果注意力是均匀的，应该是 $1/26 \approx 0.0385$：

| 层 | 给 token 0 | 给最近 8 个 | 其余 | token 0 是均匀的几倍 |
|---:|---:|---:|---:|---:|
| 2 | 0.1045 | 0.3332 | 0.5623 | 2.7× |
| 14 | 0.4847 | 0.1888 | 0.3265 | 12.6× |
| 26 | 0.6465 | 0.1842 | 0.1693 | 16.8× |
| 27 | **0.7279** | 0.1746 | 0.0975 | **18.9×** |

**最后一层把 73% 的注意力给了第一个 token。** 那个 token 是：

```
token id 785 = 'The'
```

一个没有任何语义重要性的冠词。

按头铺开（第 14 层，16 个头给 token 0 的份额）：

```
0.527 0.402 0.621 0.523 0.438 0.629 0.268 0.734 0.449 0.027 0.844 0.363 0.352 0.145 0.980 0.453
最大 0.980  最小 0.027  中位数 0.449
```

有的头给了 **98%**，有的只给 2.7%。这不是所有头的统一行为，
而是**多数头都有、程度不一**。

### 为什么会这样

文献里的解释是：softmax 强制每行和为 1。当某个头在这一步"不想关注任何东西"时，
它没有"全都不看"这个选项——那份概率质量必须倒在某处。
于是它选了位置最固定、内容最无关紧要的第一个 token。

::: note 本章只测到了现象，没有验证机制
上述机制尚未通过本章实验验证。一个可做的对照是：
在 softmax 里额外加一个可学习的"垃圾桶"logit（即所谓 softmax-off-by-one / sink token），
看 token 0 的份额会不会转移过去。**在做这个实验之前，
把它当成一个流行的解释，不是已确立的事实。**
:::

### 对滑动窗口的直接后果

如果窗口把 token 0 划出去，那 73% 的质量无处可去，会被迫分给窗口内的 token——
本来"不想关注"的头突然被迫强烈关注某些近处的内容。这就是为什么
StreamingLLM 要**单独保留最前面几个 token**（sink token），
而不是简单地丢掉窗口外的一切。

**先有这个现象，才有那个设计。** 这是本章把 sink 放在滑动窗口之前讲的原因。

## 二 · 滑动窗口：把 KV 变成常数

full attention 的 KV 随上下文线性增长，无上界。
滑动窗口（SWA）只保留最近 $W$ 个 token 的 KV，上界就是 $W$。

按 Qwen3-1.7B 的配置算（28 层，8 KV 头，$D=128$，bf16，每 token 114688 B）：

| 上下文 | full KV | W=4096 | W=1024 |
|---:|---:|---:|---:|
| 4096 | 448.0 MB | 448.0 MB | 112.0 MB |
| 16384 | 1792.0 MB | 448.0 MB | 112.0 MB |
| 65536 | 7168.0 MB | 448.0 MB | 112.0 MB |
| 262144 | 28672.0 MB | 448.0 MB | 112.0 MB |
| 1048576 | **114688.0 MB** | **448.0 MB** | 112.0 MB |

上下文 1M 时 full 要 **114 GB**（这张卡只有 32 GB），W=4096 只要 448 MB。
但真正的关键不是那个 256 倍，是**后两列不再增长**。

decode 每步耗时实测（$B=8$, $H=8$, $D=128$）：

| 上下文 | full ms | W=4096 ms | 加速 |
|---:|---:|---:|---:|
| 4096 | 0.0909 | 0.0912 | 1.00× |
| 16384 | 0.6609 | 0.0907 | 7.29× |
| 65536 | 2.5253 | 0.0902 | 27.98× |
| 131072 | 5.5029 | 0.0910 | **60.49×** |

**W=4096 那一列是平的：0.0912 / 0.0907 / 0.0902 / 0.0910。**
上下文长了 32 倍，每步耗时纹丝不动。

这直接来自 3.3 的结论：decode 时间 = KV 字节 ÷ 带宽。
KV 字节被 $W$ 钉住，时间就被钉住。**从"随上下文线性增长"变成"常数"，
这是 SWA 唯一但足够大的卖点。**

代价当然也是明确的：窗口外的信息**完全看不到**。
实际模型（Mistral、Gemma）的做法是靠层数堆感受野——
$L$ 层滑动窗口的理论感受野是 $L \times W$——
或者**交替**使用滑动窗口层与 full attention 层，
让少数几层负责长程。

## 三 · 线性 attention：换掉 softmax

标准 attention 必须先算 $QK^\top$，因为 softmax 不可分解。
线性 attention 把 softmax 换成一个**可分解的核** $\phi(q)\cdot\phi(k)^\top$：

$$O_i = \frac{\phi(q_i) \cdot \sum_{j\le i}\phi(k_j) v_j^\top}{\phi(q_i)\cdot\sum_{j\le i}\phi(k_j)}$$

括号里那两个和**可以增量维护**：一个 $d\times d$ 矩阵和一个 $d$ 维向量。
于是 decode 时的状态大小 **与上下文长度无关**——这是它最吸引人的性质。

### 3.1 复杂度优势不会自动变成性能优势

用最朴素的 $\phi = \mathrm{elu}(x)+1$ 实现（prefill，$B{=}1$, $H{=}8$, $D{=}64$）：

| S | 标准 ms | 线性 ms | 标准/线性 | 标准峰值 MB | 线性峰值 MB |
|---:|---:|---:|---:|---:|---:|
| 512 | 0.0556 | 0.4245 | **0.13×** | 1.0 | 130.0 |
| 1024 | 0.1071 | 0.9224 | 0.12× | 2.0 | 260.0 |
| 2048 | 0.3458 | 1.8435 | 0.19× | 4.0 | 520.0 |
| 4096 | 0.8770 | 3.7624 | 0.23× | 8.0 | **1040.0** |

**"线性"的那个慢 4–8 倍，显存多 130 倍。**

本章朴素实现用 `cumsum` 把 $S$ 份 $d\times d$ 状态全物化了
（$S \times d \times d$ = 4096 × 64 × 64 × 4B × 8 头 = 1040 MB）。
真实的线性 attention 用**分块递推**，块内并行、块间串行传递状态，
不物化中间状态。

**这一格的用处正是它是负面的**：$O(S)$ 的复杂度是渐近性质，
在 $S=4096$、常数因子差几十倍的时候完全体现不出来。
拿"复杂度更低"当"更快"的论据，在这个尺度上是错的。

### 3.2 它真正换掉的东西：精确检索

做一个最小的检索任务：序列里埋一个 key-value 对，让最后一个 query 明确指向它。

```
埋在位置 37，最后一个 query 指向它
标准 attention 取回的向量 与目标的余弦相似度: 1.0000
线性 attention 取回的向量 与目标的余弦相似度: 0.2393
```

**标准 attention 精确取回（1.0000），线性只有 0.2393。**

机制是 softmax 的**指数放大**：$e^{s}$ 让最大的那一项压倒性地主导，
其余项被压到接近 0，于是输出几乎就是那一个 $v_j$。
线性核没有这个放大——状态是所有 $(k,v)$ 的**加权和**，
新信息不断叠加进同一个固定大小的状态里，旧信息被摊平。

这个合成用例显示了所选 ELU+1 核的检索退化，不能推广到所有线性 attention 或 SSM。
固定大小的状态是它的优点（与上下文无关），也是它的极限（信息容量有上界）。

**也正是混合架构流行的原因**：少数几层用 full attention 负责精确检索，
其余层用线性/SSM 负责廉价的长程传播。
（0.2 里 SGLang 的 `pool_configurator` 要处理 "Mamba 层不产生 KV" 这种情况，
就是这类架构在工程侧的账。）

## 四 · RoPE 与长上下文外推

从 Qwen3-1.7B 的 config 读到：`head_dim=128`, `rope_theta=1e+06`,
`max_position_embeddings=40960`, `rope_scaling=None`。

RoPE 把 head_dim 拆成 64 对，第 $i$ 对的角频率 $= 1/\text{base}^{2i/d}$：

| 第几对 | 角频率 | 周期(token) | |
|---:|---:|---:|---|
| 0 | 1.000e+00 | 6.3 | |
| 1 | 8.058e-01 | 7.8 | |
| 8 | 1.778e-01 | 35.3 | |
| 16 | 3.162e-02 | 198.7 | |
| 32 | 1.000e-03 | 6283.2 | |
| 62 | 1.540e-06 | 4080185.2 | 周期 > 训练长度 40960，从未转满一圈 |
| 63 | 1.241e-06 | 5063256.0 | 周期 > 训练长度 40960，从未转满一圈 |

**关键在最后两行**：周期大于训练长度的那些维度，
在训练中**从未见过完整的一圈**。推理时位置一旦超过 40960，
它们进入训练中没出现过的角度区间。

这是长上下文可能出现分布偏移的一个因素——不是含糊的"模型记不住"，
而是某些输入维度取到了训练分布外的值。

### 位置插值与频率缩放改变旋转角度

想把 40960 撑到 163840（$s=4$）：

| 方案 | 最高频周期(i=0) | 中间(i=32) | 最低频周期(i=63) |
|---|---:|---:|---:|
| 原始 | 6.28 | 6283.2 | 5063256.0 |
| PI（位置插值） | **25.13** | 25132.7 | 20253024.0 |
| NTK（base 放大） | **6.28** | 12705.4 | 20253024.0 |

**最低频那一列 PI 与 NTK 完全一样**（都 ×4）——
NTK 的 base 放大公式本来就是这么设计的，让最低频恰好对上 PI。

差别全在最高频：PI 把 $i{=}0$ 的周期从 6.28 拉到 25.13（×4），
NTK 拉到 6.28（**×1.000，几乎不变**）。

高频维度负责区分"相邻几个 token"。PI 把它也拉长 4 倍，
等于让模型分不清近处的位置；NTK 保住高频，只拉低频。
YaRN 在此基础上再按维度分段处理，并加一个注意力温度修正。

::: warning 本节只算了频率，没有测任何模型质量
哪种 scaling 更好**必须跑长上下文评测**（大海捞针、长文困惑度）。
频率表只能说明它们改了什么，不能说明改得好不好。
长上下文质量为 UNVERIFIED；需要固定的数据集、长度扫描和模型配置。
:::

## 五 · 设计取舍

### 5.1 三条路线减少的计算与存储不同

回到 3.3 那个式子：decode 每步时间 $\approx$ KV 字节 ÷ 带宽。
KV 字节 $= 2 \cdot L \cdot H_{kv} \cdot D \cdot \text{ctx} \cdot \text{dtype}$。

| 路线 | 砍哪一项 | 保留什么 | 代价 |
|---|---|---|---|
| GQA / MQA | $H_{kv}$ | 精确 attention、全上下文 | 表达能力（KV 侧） |
| MLA | $H_{kv}\cdot D$（压成低秩） | 精确 attention、全上下文 | 多一次投影（算力换带宽） |
| KV 量化（4.3） | dtype | 精确 attention、全上下文 | 数值精度 |
| **滑动窗口** | **ctx** | 精确 attention（窗口内） | **窗口外完全看不到** |
| **线性 / SSM** | **整个式子**（状态恒定） | 常数状态 | **精确检索能力**（本章 1.0 → 0.24） |

这些路线应区分为架构变化与实现优化。GQA/MLA 改变参数化与状态表示，不能把已有 MHA 模型直接替换后宣称输出不变；KV 量化改变数值，也要评估质量。滑动窗口和线性状态改变上下文的访问或汇总方式。相比之下，同一模型中的精确分块 attention 只重排求值，但仍需数值与回归检查。

这与 3.1 §7.1 讲的是同一条判据：**精确的优化传播得快，
改变语义的优化要过质量这一关。** GQA 用了几年就成了默认配置，
而线性 attention 讨论了更久仍未取代 attention，差别就在这里。

### 5.2 混合架构按层分配不同状态表示

混合架构让部分层使用 full attention，其他层使用滑动窗口或线性状态。它提供了容量、计算与质量之间的另一组选择。

本章各头分给 token 0 的权重不同，但这不能证明“只有少数层需要精确检索”，更不能据此决定删除哪些层的 full attention。层配置需要训练后的模型质量与真实负载性能共同验证。

### 5.3 attention sink 是"实现细节"变成"架构约束"的例子

sink 现象不是设计出来的，是训练出来的副产品。
但它一旦存在，就成了后续所有设计的**硬约束**：
任何丢弃前几个 token 的方案都必须处理它。

这类"涌现出来的约束"在系统里很常见，而且**只能通过观测发现，
无法从设计文档推出**。所以第一节是先看数据、再讲机制，
而不是先讲 StreamingLLM 的设计然后说"因为有 sink"。

## 七 · 陷阱

1. **复杂度更低 ≠ 更快。** 本章朴素线性 attention 在 $S{=}4096$ 上比标准慢 4.3 倍、
   显存多 130 倍。渐近优势要在足够大的 $S$ 上、且实现得当才兑现。
2. **滑动窗口不能简单地丢掉窗口外的一切。** attention sink 让最前面几个 token
   承载了大量注意力质量（本章实测 73%），丢掉它们会显著改变行为。
3. **`output_attentions=True` 需要 eager 实现。** FlashAttention 类后端
   不物化注意力矩阵，拿不到权重——这本身就是 3.1 的结论。
4. **PI 与 NTK 在最低频上完全一样**，差别在高频。只比最低频会得出"两者相同"的错误结论。
5. **频率表说明不了质量。** 判断 scaling 好坏必须跑长上下文评测。
6. **sink 的机制解释本章没有验证。** 现象是实测的，解释是文献的。
7. **线性 attention 的"状态与上下文无关"是优点也是上界。** 固定容量意味着
   信息必然被摊平（本章检索 1.0000 → 0.2393）。

## 八 · 自测题

<details markdown="1">
<summary>1. 为什么用 FlashAttention 后端就拿不到注意力权重矩阵？</summary>

因为 FlashAttention **从不物化** $S\times S$ 的注意力矩阵——
这正是它的全部意义（3.1）。它分块计算，块内的打分算完立刻用掉就丢，
只保留 $m$、$l$、$O$ 三个累加量。

所以 `output_attentions=True` 必须配 `attn_implementation="eager"`，
也就是回到 3.1 里那个朴素实现（MATH 后端）。代价是显存和速度都差很多，
只能在很短的序列上做。

这也意味着：**任何需要看注意力权重的分析（可解释性、剪枝、稀疏化研究）
都不能直接在生产路径上做。**
</details>

<details markdown="1">
<summary>2. 你把滑动窗口的 W 从 4096 减到 1024，decode 快了多少？KV 省了多少？</summary>

按 3.3 的式子，两者都应该是 4×——KV 字节和每步时间都正比于 $W$。

本章的 KV 表可以直接读：448.0 MB → 112.0 MB，正好 4×。
时间没有直接测 W=1024，但前文实测数据中 W=4096 那一列保持恒定（~0.091 ms），
说明时间主要由窗口尺寸 W 决定，因此 W 缩减至 1/4 时，时间预期也会相应降至 ~0.023 ms。

**这是一个可以预测再验证的练习**，不需要重新跑就能算出来，
正是 3.3 §一 那个"时间 = 字节 ÷ 带宽"的用处。
</details>

<details markdown="1">
<summary>3. 为什么 softmax 能做精确检索，而线性核不能？</summary>

softmax 里的 $e^{s}$ 是**指数放大**：如果某一项的打分比其余高几个单位，
$e$ 的差距就是几倍到几十倍，归一化之后它几乎独占全部权重，
输出就约等于那一个 $v_j$。本章实测余弦相似度 1.0000。

线性核 $\phi(q)\cdot\phi(k)$ 是**多项式量级**的，没有这种放大。
而且它把所有历史压进一个固定大小的状态矩阵里——
新的 $(k,v)$ 不断加进去，任何单一项的占比都被稀释。本章实测 0.2393。

指数映射会放大分数差异，使权重更集中。
本用例中替换 softmax 降低了选择性；是否在训练后的完整模型上出现同样差距，需要独立评测。
</details>

<details markdown="1">
<summary>4. 一个模型 max_position_embeddings=40960，你要让它处理 160K 上下文。直接外推为什么不行？</summary>

看频率表最后两行：周期 4080185 和 5063256 token 的那些维度，
在 40960 以内**连一圈都没转完**。训练时它们只见过角度区间的一小段。

推理时位置到 160K，这些维度的角度进入训练中从未出现的区间。
模型对这些输入没有任何学过的行为——不是"忘了"，是**没见过**。

解决方向是 scaling：把角度压回训练见过的范围。
PI 直接把位置除以 4（所有频率同等缩小）；
NTK 通过放大 base，让低频被拉长而高频基本不变（本章表里 6.28 → 6.28）。

但注意：**scaling 之后仍然需要评测。** 频率表只能提供位置变换的线索，既不是质量保证，也不是所有外推方法都必须满足的必要条件——模型在插值出来的中间位置上表现如何，只能测。
</details>

<details markdown="1">
<summary>5. GQA、KV 量化与线性 attention 能否作为同一模型的无损替换？</summary>

不能。GQA 改变投影和头共享关系，线性 attention 改变历史信息的汇总方式，KV 量化改变数值。它们都需要相应的模型或质量评测。只有在固定模型与语义下的等价求值重排，才能讨论不改变实数结果，且仍需检查浮点误差。

</details>
