## 本章回答三个问题

1. 标量 loss 如何产生每个参数各一个数的梯度？
2. 保存值和共享参数如何影响反向？
3. 梯度累积在什么条件下与直接用大 batch 等价？

L0.0 演示了一次生成过程。本章用同一个模型实现一次完整的训练：
样本怎么拼、loss 怎么算、梯度怎么回、参数怎么变。
L7 会把这套流程放大到真实规模，本章先在能手算的尺度上做一遍。

两个新词：

- **梯度（gradient）**：loss 对某个参数的偏导数。它和参数**形状完全相同**——
  每个参数一个数，表示「把这个参数调大一点，loss 会变大还是变小、变多少」。
- **反向传播（backpropagation）**：从 loss 出发，按链式法则逐层往回算梯度的过程。
  实现时会保存后续求导需要的中间结果，并沿计算图反向计算。

本章出现两个模型配置，数字不能互相搬用：

| 用途 | 配置 | 脚本 | 精度 |
|---|---|---|---|
| 演示完整训练循环 | `V=18, d=32, H=4, L=2`，26,560 参数 | `walk_train.py` | fp32 |
| 逐项对拍与反例 | `V=11, d=8, H=2, L=1, block=8`，1,056 参数 | `gradient_contract.py`、`saved_variable_probe.py` | fp64 |

对拍模型刻意做小：fp64 下手算、autograd 与中心差分三方比较需要能逐元素核对的规模。

## 机制拆解

### 一、训练样本：每个输入位置的标签是下一个 token

语言模型的训练目标是「预测下一个 token」。所以标签不需要人工标注，
对同一段 token 序列取 `x=tokens[:-1]`、`y=tokens[1:]`，使 `y[t]` 对应 `x[t]` 后面的 token：

```
原文  '风吹过山谷，云落在水面'  (11 个字符)
  位置     输入 x     标签 y   含义
   0        风        吹   看到 '风' 之后应当预测 '吹'
   1        吹        过   看到 '风吹' 之后应当预测 '过'
   2        过        山   看到 '风吹过' 之后应当预测 '山'
   …
   9        水        面   看到 '风吹过山谷，云落在水' 之后应当预测 '面'
```

一条长度 10 的样本**同时提供了 10 个训练信号**。这一点依赖 L0.0 讲的因果掩码：
位置 $t$ 只能看到 $\le t$，所以它预测 $t+1$ 时不算作弊。
掩码没写对，模型就能看到答案——L0.0 自测题 4 讨论过这个问题。

训练时每一步喂进去的都是**真实的前缀**，而不是模型自己上一步生成的字符。
这叫 **teacher forcing**（教师强制）。它让训练可以并行——
10 个位置一次算完，而不是像生成时那样必须一个一个来。

代价是训练与推理的分布不一致：训练时模型看到的前缀总是对的，
推理时前缀是它自己生成的，可能已经错了。这个差距叫 exposure bias，
是 RL 后训练要处理的问题之一（L7.6）。

### 二、从 logits 到一个标量：分母必须是有效 token 数

一次前向得到 `logits: [1, 10, 18]`——10 个位置，每个位置 18 个分数。
把它和标签对上，逐位置算交叉熵：

$$\ell_t = -\log p_t[y_t],\qquad p_t = \operatorname{softmax}(\text{logits}_t)$$

$\ell_t$ 的含义是：模型给正确答案分配的概率越低，惩罚越大。
$p=1$ 时 $\ell=0$，$p \to 0$ 时 $\ell \to \infty$。

实测：

```
per_token_loss   (10,)   前6个: [+2.8736, +3.0997, +3.3885, +2.9945, +2.6051, +2.1830]
loss = per_token_loss.mean() = 2.995676

验证位置 0：正确字符 '吹'，p=0.056493，-log p=2.873633（脚本算出 2.873632）
未训练时模型接近均匀分布，预期 loss ≈ ln(V) = ln(18) = 2.8904，实测 2.9957
```

**$\ln V$ 是一个重要的理论基准线。** 当模型对所有字符给出等概率预测（各 $1/V$）时，
交叉熵损失恰好为 $\ln V$。在实际训练中，随机初始化并不会带来绝对均匀的分布；
若初始 loss 明显偏离这一基准，通常需要核查权重初始化尺度、输入数据分布或标签对齐是否正确。

$e^{\text{loss}}$ 叫**困惑度（perplexity）**，可以理解成「模型在多少个选项之间犹豫」。
$\ln V$ 对应的困惑度正好是 $V$。

真实训练里一个 batch 内各条样本长度不同，要 padding 对齐，padding 位置用
`ignore_index=-100` 排除。**分母只能数有效 token**：

$$L = \frac{1}{N_{\text{valid}}}\sum_{t\,:\,y_t \ne -100} \ell_t$$

对拍实验把长度 3 和 7 的两条样本 padding 到 7，逐 token loss 与分母分别保存。
从保存的逐 token 数组重新求和再除以 $N_{\text{valid}}=10$，与脚本报告的 loss
在三个 seed 上**误差为 0.0**（`derived.json` 的 `loss_reconstruction_max_error`）。
这一步不是形式检查：只要分母误取成 padding 后的 14，loss 就被稀释成原来的 $10/14\approx71\%$，
而曲线仍然平滑下降。

### 三、梯度：链式法则、残差与共享权重

先在一个能手算的例子上把链式法则写清楚。取

$$f(a,b) = (ab + a)^2,\qquad a=2,\ b=3$$

设 $u = ab + a = a(b+1)$，则 $f = u^2$。链式法则说：

$$\frac{\partial f}{\partial a} = \frac{\partial f}{\partial u}\cdot\frac{\partial u}{\partial a}
= 2u \cdot (b+1),\qquad
\frac{\partial f}{\partial b} = 2u \cdot a$$

代入 $u = 2\times3+2 = 8$：$\partial f/\partial a = 2\times8\times4 = 64$，
$\partial f/\partial b = 2\times8\times2 = 32$，与 autograd 一致。

**反向传播就是把这个过程自动化。** 每个算子知道自己的局部导数，
框架按图的逆序把它们连乘起来。L2.6b 打印过完整的反向图。

回到模型。最靠近 loss 的是 logits，它的梯度有一个简洁形式：

$$\frac{\partial L}{\partial \text{logits}_t} = \frac{p_t - \text{onehot}(y_t)}{N}$$

其中 $N$ 是参与平均的 token 数。把这个式子展开看：

- 对**正确**的那个字符，梯度是 $(p-1)/N < 0$。
  梯度为负意味着「增大这个 logit 会让 loss 变小」，所以更新时它会被推高。
- 对**其余**字符，梯度是 $p/N > 0$，会被压低。
- $p$ 越接近 1，$(p-1)$ 越接近 0，梯度越小——**已经答对的地方不再推动**。

交叉熵与末端 softmax 合并后才有这个形式。只有当预测分布接近标签时梯度才趋近零；
自信地预测错误类别时，相关分量仍接近 $\pm 1/N$。
这与 attention 内部单独 softmax 的饱和行为不同，不能互相套用。

#### 残差与共享权重：同一个参数的两条路径

真实模型里一个参数常常在前向中出现多次。构造一个同时含**共享权重**和**残差**的最小例子
（$x\in\mathbb{R}^{2\times3}$，$W\in\mathbb{R}^{3\times3}$，两处都用同一个 $W$）：

$$h = xW^{\top},\qquad z = hW + x,\qquad L = \operatorname{CE}(z,\,y)$$

逐步求导。记 $\mathrm{d}z = \partial L/\partial z = (\operatorname{softmax}(z) - \text{onehot}(y))/B$：

$$\mathrm{d}h = \mathrm{d}z\,W^{\top}$$

$$\boxed{\ \mathrm{d}W = \mathrm{d}h^{\top}x + h^{\top}\mathrm{d}z\ },\qquad
\boxed{\ \mathrm{d}x = \mathrm{d}h\,W + \mathrm{d}z\ }$$

两个方框是本节的重点：

- **共享权重的梯度是各次使用的梯度之和。** $W$ 在 $h=xW^\top$ 和 $z=hW$ 中各出现一次，
  $\mathrm{d}W$ 就是两项相加。autograd 实现这件事靠的正是「`.grad` 累加」：
  反向图里有两条边指向同一个叶子节点，第二条边到达时把结果加上去，而不是覆盖。
  tied embedding（`lm_head.weight` 与 `tok_emb.weight` 同一对象）走的是同一条路径。
- **残差在梯度里表现为一条恒等路径。** $z = hW + x$ 对 $x$ 求导多出 $+\mathrm{d}z$ 这一项，
  它不经过任何矩阵乘。深层网络中主路径的雅可比连乘可能把梯度压得很小，
  这条恒等路径不衰减地把梯度送到前面——这就是残差连接在反向侧的作用。

**三方对拍**（CPU、fp64、seed=0/1/2，中心差分 $\varepsilon=10^{-6}$）：

| seed | loss | 手算 vs autograd（$\mathrm{d}W$） | 手算 vs autograd（$\mathrm{d}x$） | 中心差分 vs autograd |
|---|---|---|---|---|
| 0 | 1.710311 | 0.0 | 1.110e-16 | 1.489e-10 |
| 1 | 0.858574 | 1.388e-17 | 1.388e-17 | 1.088e-10 |
| 2 | 1.393234 | 0.0 | 2.776e-17 | 1.495e-10 |

**三条路径的容差必须分别设定。** 手算与 autograd 做的是同一组浮点运算的不同排列，
误差落在 fp64 舍入量级（$10^{-17}$）。中心差分则不同：它的误差由两项组成——
截断误差 $O(\varepsilon^2)\approx 10^{-12}$，以及相减抵消带来的舍入误差
$O(\epsilon_{\text{mach}}/\varepsilon) = 2.2\times10^{-16}/10^{-6} \approx 2.2\times10^{-10}$。
实测 $1.5\times10^{-10}$ 正好落在后者，说明**中心差分本身的精度上限就在 $10^{-10}$ 附近**，
脚本的容差因此取 $10^{-7}$。把中心差分的容差设成 $10^{-12}$ 只会得到假阳性。

每个梯度都能追溯到本轮前向的输入：`manual.json` 保存了每个 seed 的 $x$、$W$、标签、
loss、三条路径的完整 $\mathrm{d}W$ 与 $\mathrm{d}x$ 矩阵。

### 四、梯度累积在什么条件下等价

「把大 batch 拆成几个小 batch，各自 `backward()` 再一次 `step()`」是显存不够时的标准做法。
它与直接用大 batch **不自动等价**，等价条件是**每个 microbatch 除以同一个全局有效 token 数**。

对拍实验固定两条样本（有效长度 3 和 7，全局 $N_{\text{valid}}=10$），
用同一份初始权重、同一个 AdamW（lr=1e-3、betas=(0.9,0.999)、weight_decay=0.01）跑四种写法，
记录更新前后的参数、梯度与 Adam 状态：

| 写法 | loss 的算法 | 每个 token 的实际权重 |
|---|---|---|
| `batch_token_mean`（参照） | 一次前向，$\sum_t \ell_t / 10$ | 一律 $1/10$ |
| `accumulate_tokens` | 逐样本前向，各自 $\sum_t \ell_t / 10$ 后 backward | 一律 $1/10$ |
| `mean_of_sample_means` | 逐样本前向，各自 $\operatorname{mean}_t(\ell_t)/2$ 后 backward | 短样本 $1/6$，长样本 $1/14$ |
| `unshifted_labels` | 一次前向，但标签未移位 | 一律 $1/10$，目标错了 |

实测结果（三个 seed，1,056 个参数元素；相对差以本轮梯度的最大绝对值为分母）：

| 写法 | seed | 最大梯度差 | 相对差 | 梯度符号翻转 | 最大参数位移 | 位移中位数 |
|---|---|---|---|---|---|---|
| `accumulate_tokens` | 0 / 1 / 2 | 5.6e-17 / 1.1e-16 / 6.9e-17 | ~0 | 0 / 0 / 0 | 6.9e-18 / 2.2e-16 / 2.8e-17 | 0 |
| `mean_of_sample_means` | 0 / 1 / 2 | 0.1525 / 0.1625 / 0.1275 | 0.558 / 0.554 / 0.459 | 100 / 103 / 106 | 2.000e-3 | 6.2e-10 / 3.9e-10 / 4.5e-10 |
| `unshifted_labels` | 0 / 1 / 2 | 0.3296 / 0.4341 / 0.5086 | 1.205 / 1.479 / 1.833 | 449 / 514 / 448 | 2.000e-3 | 8.9e-9 / 8.8e-8 / 1.3e-8 |

三条结论：

**1. 按 token 累积与直接大 batch 逐位等价。** 梯度、参数与 Adam 的 `exp_avg`、`exp_avg_sq`
差异都在 $10^{-16}$ 量级，属于求和顺序不同带来的舍入。等价的前提写在分母上：
每个 microbatch 都除以全局的 10，而不是各自的 3 和 7。

**2. microbatch 数相同不等于有效 batch 相同。** `mean_of_sample_means` 同样是两个 microbatch、
同样的两条样本、同样一次 `step()`，但它给短样本的每个 token 权重 $1/6$、长样本 $1/14$，
是参照写法的 1.67 倍和 0.71 倍。梯度最大差达到本轮梯度尺度的 **46%–56%**，
约 **10%** 的参数元素梯度符号被翻转。样本长度越不均匀，这个偏差越大。

**3. 这个错误看不出来。** `mean_of_sample_means` 的 loss 是 2.629302，参照是 2.583219，
差 1.8%，混在正常波动里。更关键的是**第一步的参数位移几乎相同**：
位移中位数只有 $6.2\times10^{-10}$，最大值恰好是 $2\times10^{-3}=2\eta$。
原因在下一节——AdamW 的第一步近似 $\eta\cdot\operatorname{sign}(g)$，
梯度大小被归一化掉了，只有符号翻转的那 10% 参数才产生 $2\eta$ 的分歧。
**检查归一化必须比较梯度，比较 loss 曲线或第一步的参数都不够灵敏。**

### 五、反向需要前向的哪些中间值

反向不是「再跑一遍前向」。它需要前向算出来的一些张量。
以上面的式子为例：算 $\partial L/\partial\text{logits}$ 要用到 $p$，
而 $p$ 是前向 softmax 的输出。

PyTorch 把这些值挂在计算图的节点上。从 loss 出发可以直接走这条链：

```
loss.grad_fn 链（前 6 跳）：
  NllLossBackward0 -> LogSoftmaxBackward0 -> ViewBackward0
  -> UnsafeViewBackward0 -> MmBackward0 -> ViewBackward0
```

每个 `*Backward0` 是一个反向节点，`next_functions` 指向它的上游。
这些节点及其连接构成反向计算图，完整示例见 L2.6b。

具体留住了什么可以直接测。用 `torch.autograd.graph.saved_tensors_hooks` 拦截每一次保存，
对拍模型（1 层、B=2、T=7、fp64）一次前向的实测结果：

| 类别 | 个数 | 字节 |
|---|---|---|
| 算子保存的权重视图（与参数共享存储，不额外占显存） | 11 | 7,232 |
| 前向产生的中间值 | 27 | 22,737 |
| 合计保存 | 38 | 29,969 |
| 参照：全部参数 | 1,056 个元素 | 8,448 |

区分这两类靠 `data_ptr()`：`mm` 保存的是权重的转置视图，与参数同一块存储，
不构成新的显存开销；真正随负载增长的是那 27 个中间值。
其中最大的几项是 MLP 的隐藏层 `[2,7,32]` 与激活后的 `[14,32]`，各 3,584 B，
以及 6 个 `[2,7,1]` 的 LayerNorm 均值/方差。

**这里有一个容易被忽略的量级关系**：中间值 22,737 B 是参数 8,448 B 的 **2.69 倍**，
而这还只是 1 层、7 个位置。参数字节与 batch、序列长度无关，中间值与二者成正比。
把 batch 或序列放大 10 倍，这一项也放大 10 倍。L7.1 按真实模型算这笔账，
并介绍用重算换显存的做法（activation checkpointing）。

### 六、一次参数更新改了什么

梯度和参数**形状完全相同**：

```
lm_head.weight   (18, 32)   前4个: [-0.1212, -0.0809, +0.0522, -0.1445]
  .grad          (18, 32)   前4个: [+0.0017, -0.0146, +0.0118, -0.0236]
梯度范数 |g| = 1.765255
```

**最朴素的 SGD** 就是一行：

$$w \leftarrow w - \eta\, g$$

$\eta$ 是学习率（learning rate）。实测（$\eta = 0.1$）：

```
手算与 optimizer 的最大差 = 1.490e-08
w[0,0]: -0.121226 -> -0.121391  (变化 -0.000165 = -0.1 × +0.001655)
```

本章使用 **AdamW** 对照 SGD，它多维护两个和参数等大的状态：

```
状态键：['exp_avg', 'exp_avg_sq', 'step']
exp_avg          (18, 32)   前4个: [+0.0002, -0.0015, +0.0012, -0.0024]
exp_avg_sq       (18, 32)   前4个: [+0.0000, +0.0000, +0.0000, +0.0000]
w[0,0]: -0.121226 -> -0.221225
```

- `exp_avg`（记作 $m$）是梯度的指数滑动平均，起平滑作用。
  第一步时 $m = (1-\beta_1) g = 0.1 g$，所以前 4 个数正好是梯度的 1/10。
- `exp_avg_sq`（记作 $v$）是梯度**平方**的滑动平均。第一步 $v = (1-\beta_2)g^2 = 0.001 g^2$，
  数量级是 $10^{-6}$，所以按 4 位小数打印显示成 `+0.0000`——它不是零。

更新式（省略权重衰减）：

$$w \leftarrow w - \eta\,\frac{\hat m}{\sqrt{\hat v} + \epsilon},\qquad
\hat m = \frac{m}{1-\beta_1^t},\ \hat v = \frac{v}{1-\beta_2^t}$$

第一步时偏差修正后 $\hat m \approx g$、$\sqrt{\hat v} \approx |g|$，
所以整个分式约等于 $\operatorname{sign}(g)$，位移量级由 $\eta$ 决定而不是梯度大小。

对拍模型（$\eta=10^{-3}$、weight_decay $\lambda=0.01$）把这句话量化到了每个元素：

- 梯度非零的元素，第一步位移与 $\eta$ 的比值落在 **[0.967, 1.034]**（三个 seed 合并）。
  略微超过 1 是偏差修正与 $\epsilon$ 的共同效果。
- 每个 seed 有 **32–40/1056** 个元素梯度恰好为 0：`tok_emb.weight` 里本轮未出现的
  3–4 个 token 对应的行（24–32 个），加上 `pos_emb.weight` 的第 7 行（8 个）——
  有效长度最长 7，位置 7 从未被用到。
  它们的位移不是 0，而是**只剩解耦权重衰减**：实测 $|\Delta w|$ 与 $|w|\cdot\eta\lambda$
  的最大差为 $3.2\times10^{-16}$，即精确等于 $(1-\eta\lambda)$ 的缩放。

这两条合起来解释了上一节的现象：第一步里几乎每个「活跃」参数都移动约一个 $\eta$，
与梯度是否算对无关，所以参数位移不能用来验证梯度。

**显存账本**（fp32）：

```
参数 576 个 -> 权重 2304 B + 状态 4608 B = 6912 B
```

每个 fp32 参数占 4 B 权重 + 4 B 梯度 + 8 B 优化器状态 = **16 B**，是权重的 4 倍。
一个 7B 模型光这三项就是 $7\times10^9 \times 16\ \text{B} = 112$ GB，
单卡放不下——这是 ZeRO / FSDP 存在的直接原因（L7.2）。

### 保存值的生命周期：SavedVariable 与 version counter

前一节实测的 38 个保存张量，在 C++ 侧各对应一个 `SavedVariable`。它在构造时
同时记下张量本身和它当时的**版本号**：

版本号来自 `c10::VariableVersion`——每个 tensor 的存储上挂一个计数器，
任何原地写入都会让它 `bump()` 加一：

{{srcfold:results/local/0.0b/20260913-autograd-source/c10__core__TensorImpl.h:386-418}}

反向执行时 `SavedVariable::unpack()` 把当前版本与保存时的版本比对，不同就报错：

{{src:results/local/0.0b/20260913-autograd-source/torch__csrc__autograd__saved_variable.cpp:164-190}}

这几行解释了两个现象。其一，**报错条件是「被保存的那个张量」的版本变了，不是「发生了原地写入」**。
实验用两个只差一个算子的前向验证了这一点：

| 前向 | 保存了什么 | 原地写入后版本 | backward |
|---|---|---|---|
| `y = x.exp()` | `exp` 的**输出** $y$（因为 $\partial y/\partial x = y$） | 0 → 1 | 报错 |
| `y = x.mul(2.0)` | 只需标量 2，不保存张量 | 0 → 1 | 正常，梯度 `[2.0, 2.0]` |

两例的版本号都从 0 变成 1，只有第一例报错。实际报错文本里的
`which is output 0 of Exp, is at version 1; expected version 0 instead`
直接来自上面的 `message <<` 各段，**报错信息里的算子名就是保存该值的那个算子**——
这是定位原地修改位置最快的线索。

其二，第一次 backward 之后保存值被释放，第二次 backward 因此失败。释放动作由引擎发起：

{{src:results/local/0.0b/20260913-autograd-source/torch__csrc__autograd__engine.cpp:1185-1192}}

`keep_graph_` 就是 `backward(retain_graph=True)` 传下来的开关。
释放后 `data_` 变成未定义，`unpack()` 命中这一行：

{{src:results/local/0.0b/20260913-autograd-source/torch__csrc__autograd__saved_variable.cpp:130-138}}

实测：`y = x.square().sum()` 第一次 backward 得到 `x.grad = [4.0]`；
不加 `retain_graph` 再 backward 报 `Trying to backward through the graph a second time`；
加了 `retain_graph=True` 则第二次成功，`x.grad` 变成 `[8.0]`——
**不是重算覆盖，而是累加**，与第三节说的「共享参数梯度相加」是同一个机制。

### 设计取舍

**版本计数器是低成本的正确性保险。** 反向要么把保存值复制一份（显存翻倍），
要么假设它不被修改（静默算错），要么记一个整数在使用时校验。PyTorch 选第三条：
每个存储一个 `uint32`，原地算子加一，`unpack()` 时比较。
代价是这个检查**只在保存值被真正使用时触发**——如果某个原地修改破坏的值恰好
在本次反向中用不到，不会报错，也不应该报错。它保证的是「用到的值没被改过」，
不是「没有发生过原地修改」。

**默认释放保存值，是对最常见路径的优化。** 训练循环里一个图只反向一次，
把中间值留到下一次前向纯属浪费。`retain_graph=True` 把这个选择交回调用方，
代价是显存按图的规模持续占用。多次 backward 的真实需求（高阶导数、
同一图的多个 loss）通过显式开关表达，而不是让默认路径为少数情况付费。

**`.grad` 累加而不是覆盖，是一个有代价的选择。** 它让共享参数、梯度累积和多 loss
反向都自然成立，代价是必须记得 `zero_grad()`——忘记时不会报错，只是等效学习率
逐步变大。API 的默认值在这里偏向了表达能力而非防错，
`optimizer.zero_grad(set_to_none=True)` 则是后来加入的、把 `.grad` 置为 `None`
以省下一份显存的折中。

**解耦权重衰减改变了衰减与自适应步长的相互作用。** 若把 $\lambda w$ 加进梯度，
它会一同进入 $m$ 和 $v$，使实际衰减强度依赖该参数的梯度历史；
`param.mul_(1 - lr * weight_decay)` 让衰减与梯度尺度无关。
代价是 `weight_decay` 的含义与 `Adam(weight_decay=...)` 不同，两者的超参不能直接搬用。

### 两种「停止梯度」的实测区别

`detach()` 与 `requires_grad_(False)` 经常被混用，实测结果说明它们不可互换。
同一份权重、同一批输入，只改一处：

| 参数 | 参照 | 对 block 输入 `detach()` | `fc1.weight.requires_grad_(False)` |
|---|---|---|---|
| `tok_emb.weight` | 0.120348331 | **None** | 0.120348331 |
| `blocks.0.attn.qkv.weight` | 0.140288178 | 0.140288178 | 0.140288178 |
| `blocks.0.mlp.fc1.weight` | 0.095877756 | 0.095877756 | **None** |
| `blocks.0.mlp.fc2.weight` | 0.190038530 | 0.190038530 | 0.190038530 |
| `lm_head.weight` | 0.841066633 | 0.841066633 | 0.841066633 |

- `detach()` 切断的是**路径**：上游的 `tok_emb` 从「范数 0.120」变成 `None`——
  不是变成 0，是从未被填充。下游（更靠近 loss 的一侧）一个数都没变。
- `requires_grad_(False)` 只是**跳过这一个参数**：`fc1.weight` 没有 `.grad`，
  但梯度照常穿过 `fc1` 回传，`tok_emb` 的梯度范数与参照**逐位相同**。

所以冻结主干、只训旁路时，两者的后果完全不同：多层插 LoRA 时对主干特征
`detach()` 会让浅层旁路收不到梯度，而 `requires_grad_(False)` 不会。
反过来，只想省下反向计算时，`detach()`（或 `no_grad()`）才真正省，
`requires_grad_(False)` 仅省掉该参数的权重梯度那一步。

## 前沿

本章讲的是最基本的一步。它在真实训练里会被下面这些东西包住，各自解决一个具体问题：

| 加进来的东西 | 解决什么 | 代价 | 章节 |
|---|---|---|---|
| 混合精度（bf16 计算 + fp32 状态） | 部分激活与通信字节减少；总显存需逐项核算 | 需要处理数值范围 | L4.2 / L7.1 |
| 梯度裁剪 | 偶发的大梯度会毁掉训练 | 多一次全局归约 | L7.1 |
| 学习率调度（warmup + 衰减） | 开始时参数还没「对齐」，大步长会发散 | 多一个超参 | L7.1 |
| 梯度累积 | 用小显存模拟大 batch | 更新频率降低；分母必须用全局有效 token | L7.0b |
| activation checkpointing | 不保存中间值，反向时重算 | 约 +33% 计算 | L7.1 |
| ZeRO / FSDP | 把权重、梯度、优化器状态切到多卡 | 通信 | L7.2 |
| 8-bit / paged 优化器 | 优化器状态从 8 B 降到 2 B | 数值精度 | L7.5 |

上述 fp32 配置中，优化器状态占用是权重的 2 倍，减少这些状态可以降低训练显存需求。

---

## 陷阱

**1. 忘记 `zero_grad()`。** PyTorch 的 `.grad` 是累加的。
不清零时等效学习率会逐步变大，训练往往不是立刻崩，而是过一阵才发散——很难查。

**2. 用 loss 曲线判断训练是否正确。** 标签未移位的版本 loss 曲线与正确版本几乎重合，
在对拍模型上它的 loss 甚至更低。**必须有一个不依赖 loss 的检查。**

**3. 用第一步的参数位移验证梯度。** AdamW 第一步的位移约等于 $\eta$，
与梯度大小基本无关。实测把归一化写错后，梯度最大差达同轮尺度的 56%，
参数位移中位数却只有 $6\times10^{-10}$。要验证梯度就比较梯度。

**4. 把「microbatch 数相同」当成「有效 batch 相同」。** 两个 microbatch 各自取样本内均值
再平均，与一次算 10 个 token 的均值不是一回事；样本长度不均匀时差别最大。
梯度累积的分母必须是全局有效 token 数。

**5. 混淆冻结参数与断开计算图。** `detach()` 切断路径，上游收不到梯度、下游不受影响；
`requires_grad_(False)` 只跳过该参数，梯度照常穿过它回传。
实测两者对 `tok_emb` 的影响是 `None` 与逐位相同的差别。

**6. 忽略 padding 位置的 loss。** 分母数错会让 loss 被稀释，
不同长度的 batch 之间不可比。本章的有效 token 归一化已给出可核对的做法，L7.0b 展开。

**7. 把 `exp_avg_sq` 打印出的 `0.0000` 当成零。**
它的量级是 $10^{-6}$，只是打印精度不够。调试数值问题时永远用科学计数法看。

**8. 只在一条数据上验证训练代码就上大规模。**
「能过拟合一条数据」是必要条件，不是充分条件。
它能发现部分明显错误，但不能排除全部梯度、数据管线、学习率或并行实现问题。

## 自测题

<details markdown="1">
<summary>1. 一个 7B 模型用 AdamW 训练，纯 fp32，光「权重 + 梯度 + 优化器状态」要多少显存？</summary>

**逐项算。** 设参数量 $N = 7\times10^9$。

| 项 | 每参数字节 | 合计 |
|---|---|---|
| 权重 | 4 | 28 GB |
| 梯度 | 4 | 28 GB |
| AdamW `exp_avg` | 4 | 28 GB |
| AdamW `exp_avg_sq` | 4 | 28 GB |
| **合计** | **16** | **112 GB** |

**112 GB**，而 H100 是 80 GB。单卡放不下——**而且这还没算 activation。**

**混合精度不会让它降到 1/4。** 常见的 bf16 混合精度配方是：
bf16 权重副本（2 B）+ bf16 梯度（2 B）+ fp32 主权重（4 B）+ fp32 优化器状态（8 B）
= 16 B，**和纯 fp32 一样**。省下来的是激活值和通信量，不是这三项。

（有些实现把主权重与 `exp_avg` 合并或用 8-bit 优化器，那是另一回事，见 L7.5。）

**这就是 ZeRO 的出发点**：这三项在数据并行时每张卡都存了一份完全相同的副本，
ZeRO-1/2/3 依次把优化器状态、梯度、权重切开分到各卡。L7.2 展开。
</details>

<details markdown="1">
<summary>2. 显存不够，把 batch 拆成 4 个 microbatch 累积。要改哪一行才能与原来的大 batch 等价？</summary>

**改 loss 的分母那一行。**

设四个 microbatch 的有效 token 数分别是 $n_1,\dots,n_4$，全局 $N=\sum n_i$。
大 batch 的 loss 是 $\frac{1}{N}\sum_{\text{all }t}\ell_t$，所以每个 microbatch 必须贡献

$$L_i = \frac{1}{N}\sum_{t \in \text{mb}_i}\ell_t$$

**具体改动**：把 `loss = F.cross_entropy(..., reduction='mean')` 换成
`reduction='sum'` 再除以全局的 $N$：

```python
loss = F.cross_entropy(logits, labels, reduction='sum', ignore_index=-100) / global_valid_tokens
loss.backward()      # 不 step，梯度累加
```

`global_valid_tokens` 需要在切分前先数好；分布式训练里它还要跨 rank 归约（L7.2）。

**为什么不能直接除以累积步数 $k$**：`loss.mean() / k` 只在各 microbatch 的有效 token 数
**完全相同**时才等价。长度不均匀时，短 microbatch 的每个 token 会被放大。
本章的 `mean_of_sample_means` 就是这个错误：长度 3 和 7 的两条样本，
短样本每个 token 拿到 $1/6$ 而不是 $1/10$，梯度最大差达到同轮梯度尺度的 55%。

**怎么验证改对了**：不要看 loss，也不要看第一步的参数。
用一个小模型同时跑「一次大 batch」和「累积」，比较 `p.grad`：
正确时差异应在 fp64 的 $10^{-16}$、fp32 的 $10^{-7}$ 量级。
`gradient_contract.py` 做的就是这件事。
</details>

<details markdown="1">
<summary>3. 反向报 <code>...modified by an inplace operation: [torch.FloatTensor [4, 8]] ... is at version 1; expected version 0</code>。原因是什么，去哪一行改？</summary>

**原因**：某个算子在前向时保存了一个张量用于反向，而这个张量在 backward 之前被原地修改过。
PyTorch 给每块存储挂了一个版本号（`c10::VariableVersion`，`TensorImpl.h:328`），
原地写入时 `bump()` 加一（`:390`）；`SavedVariable` 在保存时记下当时的版本
（`saved_variable.cpp:49`），`unpack()` 时比对（`:168-186`）。

**去哪一行改，看报错本身**：

1. 报错里的 `which is output N of <算子名>` 指出**保存该值的那个算子**。
   前向代码里找到这个算子的调用点——被改坏的是它的输出（或输入）。
2. 从那一点往后找带下划线的调用：`add_`、`mul_`、`clamp_`、`relu_(inplace=True)`、
   `x[...] = ...`、`copy_`。把它换成非原地写法，或在修改前 `clone()`。
3. 找不到时打开 `torch.autograd.set_detect_anomaly(True)`，报错会附上保存该值的前向调用栈。

**注意报错条件**：不是「有原地修改就报错」，而是「**被保存的那个张量**的版本变了」。
本章实测：`y = x.exp()` 之后原地改 `y` 会报错（`exp` 的反向需要输出 $y$），
`y = x.mul(2.0)` 之后做同样的原地修改不报错（只需常数 2，没保存张量），
两者的版本号都从 0 变成 1。

**常见来源**：为省显存写的 `inplace=True` 激活函数、直接在输出上做的归一化、
把 attention 的 mask 写进原张量。
</details>

<details markdown="1">
<summary>4. 第二次 <code>loss.backward()</code> 报 <code>Trying to backward through the graph a second time</code>。为什么，有哪几种改法？</summary>

**为什么**：第一次 backward 结束后引擎释放了各节点保存的中间值
（`engine.cpp:1188-1189`，条件是 `!graph_task->keep_graph_`）。
再次 backward 时 `SavedVariable::unpack()` 发现 `data_` 未定义，抛出
`ERR_BACKWARD_TWICE`（`saved_variable.cpp:136`，文本定义在 `:291`）。

**三种改法，按场景选**：

1. **本来就只该反向一次**——这是最常见的情况。检查是不是循环里复用了上一轮的 `loss`
   或某个在循环外计算的张量。改法是把前向移进循环。
2. **确实需要对同一张图反向多次**（高阶导数、共享中间结果的多个 loss）：
   `loss.backward(retain_graph=True)`，最后一次不加。代价是中间值一直占着显存。
3. **多个 loss 但可以合并**：`(loss_a + loss_b).backward()` 只走一次图，
   通常比 `retain_graph` 更省。

**顺带记住第二次 backward 的语义是累加**：本章实测 `x.square().sum()` 在 $x=2$ 处
第一次得 `[4.0]`，加 `retain_graph=True` 再来一次得 `[8.0]`。
要单独拿到第二次的梯度必须先 `zero_grad()`，或改用 `torch.autograd.grad()`。
</details>

<details markdown="1">
<summary>5. 只想训练 LoRA 旁路，冻结主干。用 <code>detach()</code> 还是 <code>requires_grad_(False)</code>？</summary>

**用 `requires_grad_(False)`，逐个参数关。**

两者切的不是同一样东西：

- `requires_grad_(False)` 作用在**参数**上：这个参数不再累积 `.grad`，
  但反向照常穿过它所在的算子，把梯度送给更上游。
- `detach()` 作用在**路径**上：它在计算图里插了一个断点，
  这个点之前的所有东西都拿不到梯度。

本章实测（同一份权重、同一批输入）：冻结 `fc1.weight` 后，`fc1.weight.grad` 是 `None`，
而 `tok_emb.weight` 的梯度范数仍是 0.120348331，与不冻结时**逐位相同**；
对 block 输入 `detach()` 后，`tok_emb.weight.grad` 直接变成 `None`。

**为什么这对 LoRA 是决定性的**：LoRA 旁路插在多层上。
若在中间某层对主干特征 `detach()`，该层之前的旁路全部收不到梯度，
训练看起来在跑、loss 也在降，实际只有靠近输出的几个旁路在更新。

**改哪里**：

```python
for p in model.parameters():
    p.requires_grad_(False)          # 先全关
for n, p in model.named_parameters():
    if "lora_" in n:
        p.requires_grad_(True)       # 再开旁路
opt = torch.optim.AdamW([p for p in model.parameters() if p.requires_grad], lr=...)
```

优化器只传入需要训练的参数——只关 `requires_grad` 而仍把全部参数交给优化器，
weight decay 之类的操作仍会改写被冻结的权重。

**什么时候才该用 `detach()`**：真的要切断梯度流，例如目标网络、
停止梯度的对比学习分支，或者确定该分支之前没有任何待训练参数、想省下反向计算。
L7.5 展开 LoRA 的完整实现与显存账。
</details>

<details markdown="1">
<summary>6. 训练时 10 个位置的预测一次算完，生成时却必须一个一个来。为什么不能反过来？</summary>

**关键在于「下一步的输入是否已知」。**

**训练时**，整条序列是已知的真实文本。位置 $t$ 的输入是真实的第 $t$ 个字符，
不依赖模型在位置 $t-1$ 的输出。所以 10 个位置的计算**互不依赖**，
可以放进同一个矩阵乘一次算完（teacher forcing）。

**生成时**，位置 $t$ 的输入是模型在位置 $t-1$ 采样出来的字符。
不先算出 $t-1$，就不知道 $t$ 该喂什么。这是一条**串行的依赖链**，没法并行。

这个差别决定了两种负载的性质完全不同：

| | 训练 / prefill | 生成 / decode |
|---|---|---|
| 一次处理的位置数 | 整条序列 | 1 个 |
| 矩阵乘的形状 | $T\times d$ 乘 $d\times d$ | $1\times d$ 乘 $d\times d$ |
| 瓶颈 | 算力 | **显存带宽** |
| 原因 | 矩阵够大，算术强度高 | 每个权重只被用一次就换下一个 |

decode 之所以是带宽瓶颈：为了算一个 token，
要把**整个模型的权重**从显存读一遍，而只做了 $O(d^2)$ 次乘加。
读 1.4 GB 权重、算 $2\times1.4\times10^9$ 次浮点运算，
算术强度约 1 FLOP/字节——远低于 GPU 的平衡点（约 200+）。

这是本书 L0.2（资源账本）、L5.1（prefill/decode 性质）的核心，
投机解码（L5.5）则尝试在一次目标模型调用中验证多个候选 token，提高权重读取的利用率。
</details>
