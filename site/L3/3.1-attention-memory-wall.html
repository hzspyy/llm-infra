3.1

从 attention 数学到内存墙

推导 online softmax 和分块 attention，分析中间张量、数值误差与执行成本。

实测机器 crater (RTX 5090 D, sm_120) · torch 2.13.0+cu130 · CUDA 13.0前置 0.0（attention 的最小实现）· 0.2（roofline 与机器平衡点）· 2.3（访存阶梯）

本章回答三个问题

0.0 里我们手写过一次 attention：算 QK⊤、加因果 mask、softmax、乘 V。 这份实现直接保存中间矩阵，便于理解和验证，但会把 S×S 的矩阵写入显存再读回。分块 attention 可以减少这部分存储和搬运。

  1. 那个 S×S 到底多大？它让朴素实现在什么规模上失效？
  2. softmax 必须先看完整行才能归一化——怎么可能分块？
  3. 分块之后结果还一样吗？是精确相等还是近似？

本章的立场

分块 attention（FlashAttention 的核心）不是一个近似算法。 它是同一个数学表达式的另一种求值顺序，结果在浮点误差内相同。 本章会把这一点从代数推到实测：自己写一个分块版本， 和 PyTorch 的 SDPA 逐元素对照验证。

一 · 那个 S×S 有多大

一层、B=1, H=32, D=128、bf16（约等于 7B 模型的一层）：

S Q/K/V 合计 S×S 一份 朴素峰值 SDPA 峰值 倍数
512 12.0 MB 16.0 MB 68.2 MB 4.1 MB 16.8×
1024 24.0 MB 64.0 MB 137.0 MB 8.1 MB 16.9×
2048 48.0 MB 256.0 MB 532.0 MB 16.3 MB 32.7×
4096 96.0 MB 1024.0 MB 2096.0 MB 32.5 MB 64.5×
8192 192.0 MB 4096.0 MB 8320.0 MB 65.0 MB 128.0×
16384 384.0 MB 16384.0 MB OOM 130.0 MB —

两条曲线的形状完全不同：

Q/K/V=3BHSD·2 字节(∝S),S×S=BHS2·2 字节(∝S2)

S=512 时 S×S 只比 Q/K/V 大一点；S=8192 时它是 Q/K/V 的 21 倍。 到 16384，光是一层的一份打分矩阵就要 16 GB，而这张卡总共 32 GB—— 朴素实现在这里直接 OOM，而 SDPA 只用了 130 MB。

注意"朴素峰值"比"S×S 一份"还大一倍多：因为 softmax 的输入 s 和输出 p 同时活着，是两份 S×S。

二 · 中间矩阵的存储与搬运成本

显存不够只是表面。真正的问题是算术强度（每搬一字节能做多少次浮点运算）， 这是 0.2 里那条 roofline 的横轴。

FLOP

两次矩阵乘，每头：

QK⊤: 2S2DPV: 2S2D合计4S2D

（因果 mask 只需算下三角，实际约一半。）

DRAM 流量

理论算术强度对比

在朴素实现中，完整的 S×S 打分矩阵必须频繁写回 DRAM 并多次重读（包括寻找行最大值、指数与求和归一化、以及与 V 矩阵相乘）。结合 Q,K,V 的基础搬运，总访存量呈现强烈的 O(S2) 依赖，导致其理论算术强度迅速饱和：

Inaive≈4S2D12S2+6SD≈D3(当 S≫D)

即使取 D=128，其算术强度上限也仅约为 42 FLOP/byte，远低于 RTX 5090 D 的机器平衡点（153 FLOP/byte），因而不可避免地深陷 memory-bound 泥潭。

而在分块实现（如 FlashAttention）中，算法利用在线 softmax 技术将计算限制在片上共享内存内完成，彻底消除了向 DRAM 回写 S×S 完整中间矩阵的开销。在理想的数据流模型下，主要的 DRAM 访问仅为读取 Q,K,V 以及回写输出 O（各 2SD 字节），其理想算术强度跃升为：

Iflash, ideal=4S2D8SD=S2

算术强度随序列长度 S 呈线性增长！当 S=4096 时，理论强度高达 2048 FLOP/byte，彻底跨过平衡点进入 compute-bound 区间。虽然实际工程中受分块重复加载与共享内存容量约束，真实强度会有所折损，但消除 O(S2) 显存落盘所释放的性能红利，正是分块 attention 相比朴素实现带来数量级加速的本质原因。

实测

S 朴素 ms SDPA ms 加速 SDPA TFLOP/s 朴素强度 分块强度
512 0.101 0.031 3.2× 68.5 37.9 256
1024 0.393 0.085 4.6× 101.5 40.2 512
2048 2.112 0.238 8.9× 144.3 41.4 1024
4096 8.513 0.792 10.7× 173.5 42.0 2048
8192 34.250 2.793 12.3× 196.8 42.3 4096

「朴素强度」那一列从 37.9 爬到 42.3 就不动了，正是推导预测的 D/3≈42.7。 「分块强度」翻倍再翻倍。加速比从 3.2× 长到 12.3×，并且还在长。

SDPA 在 S=8192 上跑到 196.8 TFLOP/s，是 L1.1 实测 bf16 上限 232 的 85%—— 它已经变成一个算力受限的算子了。这正是分块要达到的效果。

三 · softmax 怎么可能分块

这是本章的技术核心。先把问题说清楚：

softmax(x)i=exi∑jexj

分母要对整行求和。看起来必须先看完所有 xj 才能算出任何一个输出。

3.1 先解决一个更基础的问题：为什么要减最大值

数学上，给所有 x 减去同一个常数 c，结果不变：

exi−c∑jexj−c=exi/ec∑jexj/ec=exi∑jexj

分子分母的 ec 约掉了。所以减常数是恒等变换，不是近似。

在浮点计算中，不减最大值可能溢出。实测如下：

x 最大    10.0   exp(x) = [22026.46484375, 8103.083984375, 2980.9580078125]
                    朴素 softmax = [0.6652409434318542, 0.2447284758090973, 0.09003057330846786]
                    减最大值后   = [0.665241, 0.244728, 0.090031]
x 最大    88.0   exp(x) = [1.6516362661361307e+38, 6.076030347399616e+37, 2.2352465286715966e+37]
                    朴素 softmax = [0.6652409434318542, 0.2447284609079361, 0.09003056585788727]
                    减最大值后   = [0.665241, 0.244728, 0.090031]
x 最大   100.0   exp(x) = [inf, inf, inf]
                    朴素 softmax = [nan, nan, nan]
                    减最大值后   = [0.665241, 0.244728, 0.090031]
x 最大  1000.0   exp(x) = [inf, inf, inf]
                    朴素 softmax = [nan, nan, nan]
                    减最大值后   = [0.665241, 0.244728, 0.090031]

float32 能表示的最大值约 3.4×1038。看 88.0 那一行： e88=1.65×1038 已经贴着上限，再大一点就溢出—— 100.0 那行三项全部变成 inf，inf/inf 得到 nan，整行结果全毁。

注意 88.0 那行朴素写法还是对的（0.66524…），和减最大值的结果一致。 这正是危险之处：它在临界点之前完全正常，越过之后一次性全毁，中间没有过渡。

反方向也一样。x = [-800, -801, -802]：

exp(x) = [0.0, 0.0, 0.0]  -> 全部下溢成 0
朴素 softmax = [nan, nan, nan]   (0/0)
减最大值后   = [0.665241, 0.244728, 0.090031]

减最大值之后，最大那一项恰好是 e0=1，其余都在 (0,1]—— 既不上溢也不会全部下溢。这个写法叫 safe softmax， 是所有实际实现的起点。

代价是它需要先扫一遍求最大值。于是教科书写法是三遍：

第1遍 m = max(x)
第2遍 p = exp(x - m)
第3遍 l = Σp
      y = p / l

3.2 online softmax：一遍就够

关键在于最大值可以边走边更新，已经累加的部分和可以事后修正。

设已经处理完前 k 个元素，手上有

mold=max(x1..xk),lold=∑i≤kexi−mold

来了新元素 xnew：

mnew=max(mold,xnew)

lnew=lold·emold−mnew+exnew−mnew

为什么那个修正因子是对的：lold 里每一项的基准是 mold， 现在基准要换成 mnew，每一项都要乘 emold/emnew=emold−mnew。 求和是线性的，所以这个因子可以提到外面，整个 lold 乘一次就行。

而且 mnew≥mold，所以这个因子 ≤1——它永远不会放大， 数值上是安全的。

逐元素跑一遍（x 是 8 个随机数）：

   步     x_new      m_old      m_new       修正因子        l_new
    0    -0.9247       -inf    -0.9247   0.000000     1.000000
    1     1.4142    -0.9247     1.4142   0.097496     1.097496
    2    -0.1425     1.4142     1.4142   1.000000     1.303931
    ...
    7     2.5141     4.6230     4.6230   1.000000     1.212988

一遍之后 m=4.622988  l=1.212988
三遍写法   m=4.622988  l=1.212988
m 相同: True   l 相同: True
最终结果与三遍写法的 max|err| = 0.000e+00

看第 1 行：新元素 1.4142 比旧的最大值 −0.9247 大， 所以基准要抬高，修正因子 e−0.9247−1.4142=0.0975， 把之前累积的 1.0 缩成 0.0975 再加上新项。 第 2 行新元素没超过当前最大值，修正因子是 1.0，什么都不用改。

本次输入的两种实现恰好得到零差异；重排浮点运算不保证一般输入逐位相同。

3.3 按块做

逐元素只是块大小为 1 的特例。块大小 B 时：

mblk=max(块内),lblk=∑块内ex−mblk

mnew=max(mold,mblk),lnew=loldemold−mnew+lblkemblk−mnew

块大小 2:  m=4.622988  l=1.212988   与三遍写法一致: True
块大小 4:  m=4.622988  l=1.212987   与三遍写法一致: True
块大小 8:  m=4.622988  l=1.212988   与三遍写法一致: True

块大小 4 那行末位差了 1（1.212987 vs 1.212988）——这是浮点加法不满足结合律 的正常表现（2.4 里讨论过），不是算法错误。

四 · 把 V 的加权和也放进同一遍

softmax 只是中间步骤，真正要的是 O=softmax(s)V。 再加一个累加器就行：

Onew=Oold·emold−mnew+esblk−mnewVblk

关键：中间只累加未归一化的和，除法留到最后一次做。 因为除以 l 是逐元素的线性操作，可以推迟；而如果每块都除一次， 就要在基准改变时把除过的结果再乘回去，麻烦且损精度。

一个 S=12、D=4、块大小 4 的完整过程：

  块     m_old     m_new        修正      l_run  o_run（未归一化）
   0      -inf   -0.0989  0.000000    2.88054  [-0.6853, 0.9778, 0.1907, 2.0945]
   1   -0.0989    0.8751  0.377547    3.32266  [-0.4288, -1.0139, 1.0599, 1.8531]
   2    0.8751    0.8751  1.000000    5.36555  [0.1595, -1.0876, 0.5023, 1.0567]

归一化后 o = [0.02972, -0.2027, 0.09362, 0.19694]
参照     o = [0.02972, -0.2027, 0.09362, 0.19694]
max|err| = 1.490e-08

第 1 块把 o_run 整个乘了 0.3775——因为第 1 块里出现了更大的打分， 基准抬高了，之前累积的贡献要按同样的比例缩小。 第 2 块的最大值没超过，修正因子 1.0，o_run 只是累加。

峰值额外存储：一块的打分 + m、l 各一个标量 + O 的 D 个数。 与 S 无关。 S 变成 100 万也是这么多。

五 · 自己写一遍，与 SDPA 对照验证

把上面的东西写成多头版本（labs/L3/online_softmax.py 的 flash_like）， 只用基本张量运算，不调任何 attention 库：

190     def flash_like(Q, K, V, block=64, causal=True):
191         """分块 attention。Q/K/V: [B, H, S, D]。只用基本张量运算。"""
192         B, H, S, D = Q.shape
193         scale = D ** -0.5
194         O = torch.zeros_like(Q)
195         # 外层遍历 Q 的块（FA2 的顺序），内层遍历 K/V 的块
196         for q0 in range(0, S, block):
197             q1 = min(q0 + block, S)
198             Qb = Q[:, :, q0:q1]                          # [B,H,bq,D]
199             m = torch.full((B, H, q1 - q0), float("-inf"), device=Q.device,
200                            dtype=Q.dtype)
201             l = torch.zeros((B, H, q1 - q0), device=Q.device, dtype=Q.dtype)
202             acc = torch.zeros_like(Qb)
203             for k0 in range(0, S, block):
204                 k1 = min(k0 + block, S)
205                 if causal and k0 > q1 - 1:               # 整块都在未来，跳过
206                     continue
207                 Kb, Vb = K[:, :, k0:k1], V[:, :, k0:k1]
208                 s = (Qb @ Kb.transpose(-1, -2)) * scale  # [B,H,bq,bk]
209                 if causal:
210                     qi = torch.arange(q0, q1, device=Q.device).view(-1, 1)
211                     ki = torch.arange(k0, k1, device=Q.device).view(1, -1)
212                     s = s.masked_fill(ki > qi, float("-inf"))
213                 m_blk = s.amax(dim=-1)                   # [B,H,bq]
214                 m_new = torch.maximum(m, m_blk)
215                 corr = torch.exp(m - m_new)
216                 corr = torch.nan_to_num(corr, nan=0.0)   # 首块 m=-inf
217                 p = torch.exp(s - m_new.unsqueeze(-1))
218                 p = torch.nan_to_num(p, nan=0.0)         # 整行被 mask 掉时
219                 l = l * corr + p.sum(dim=-1)
220                 acc = acc * corr.unsqueeze(-1) + p @ Vb
221                 m = m_new
labs/L3/online_softmax.py 第 190–221 行在完整文件中打开 →

和 PyTorch 的 SDPA 逐元素比：

B=1 H=2 S=128 D=32 causal=True  max|err| = 2.384e-07   一致
B=2 H=4 S=256 D=64 causal=False max|err| = 4.768e-07   一致

块大小不影响结果：

block=  16   max|err| vs SDPA = 4.172e-07
block=  32   max|err| vs SDPA = 3.576e-07
block=  64   max|err| vs SDPA = 3.576e-07
block= 128   max|err| vs SDPA = 3.576e-07
block= 256   max|err| vs SDPA = 3.576e-07

10−7 是 fp32 的舍入量级（2−23≈1.2×10−7）。 分块在实数算术下等价；实际块大小还会影响舍入顺序，应按 dtype、输入尺度和长度设定容限。

因果 mask 在分块下的两个细节

flash_like 里有两处容易写错：

  1. 整块都在未来时直接跳过（if causal and k0 > q1 - 1: continue）。 这不只是优化——如果不跳过，整块被 mask 成 −∞， exp(-inf - (-inf)) 会得到 nan。
  2. 首块的 mold=−∞，修正因子 e−∞−m=0 是对的， 但 −∞−(−∞) 是 nan。代码里用 nan_to_num 处理， 真实 kernel 里通常把首块单独展开成一个不带修正的分支。

这两处都是"数学上没有、浮点上必须处理"的地方。

六 · SDPA 背后有几个后端

F.scaled_dot_product_attention 是一个调度器，不是一个实现。 B=1, H=32, S=4096, D=128, bf16, causal：

后端 ms 峰值 MB
FLASH_ATTENTION 0.793 32.5
EFFICIENT_ATTENTION 1.677 32.0
MATH（就是朴素实现） 21.770 4928.1
CUDNN_ATTENTION 0.739 32.0
不指定（默认） 0.789 —
  • MATH 后端与 naive_attention 不是同一实现：慢 27.5×，多用 152× 显存。 它存在的意义是参照实现——覆盖比专用后端更广的输入，但仍有 dtype、设备和接口限制， 也用来给别的后端对答案。2.0 里那张分发表上的 CompositeExplicitAutograd 就是这种角色。
  • 默认选了 0.789 ms，和 FLASH（0.793）最接近。
  • CUDNN 这次略快（0.739），但差距在 7% 以内， 单次测量不足以断言谁更好（M2 会讲怎么测才算数）。

MATH 的 21.77 ms 比第二节的朴素实现（8.51 ms）还慢 2.6 倍

两条路径的耗时差异尚未定位，以下仅列候选原因。 可能的方向：MATH 后端要处理更一般的 mask 与 dtype 提升路径， 可能多了一次 fp32 上转或额外的 mask 张量。 这是一个待查项，不要用它来说明任何结论。 判据：用 nsys 抓两条路径的 kernel 序列对比（2.6 的方法）。

七 · 设计取舍

7.1 为什么是"重排求值顺序"，而不是"近似"

面对 attention 的二次复杂度，设计空间里至少有三类做法：

方案 做法 代价
A. 近似 稀疏化、低秩、线性 attention 改变结果；要重新训练或接受质量下降
B. 换硬件 更大的片上存储 不在你手里
C. 重排求值顺序 分块 + online softmax 结果不变；实现复杂度上升

FlashAttention 选 C。这个选择最关键的性质是结果不变—— 它通常无需重新训练模型，但仍须验证 mask、dtype、数值误差和端到端回归，不能省略正确性检查。

这也解释了为什么 3.4 要讲的那些稀疏/线性方法（方案 A）至今没有取代 attention： 它们必须证明质量，而 C 类只需要证明数值一致。

判断依据： 当你要优化一个被广泛依赖的东西时， "能不能保证行为完全不变"这一条，往往比性能数字更能决定它会不会被采用。

7.2 online softmax 的代价在哪

天下没有免费的重排。分块版本付出的是：

  • 重复计算：修正因子 emold−mnew 每块都要算一次乘一遍， O 累加器要被反复缩放。这些在朴素实现里不存在。
  • 实现复杂度：上面那两个 nan 陷阱只是开始； 真实 kernel 还要处理 SRAM 容量、warp 分工、bank conflict（2.6）。
  • 反向更麻烦：反向要重算 s（因为没存），这是用算力换显存的又一次交易—— 和 7.0 要讲的 activation checkpointing 是同一个思路。

这些代价能被接受，是因为被换掉的东西（O(S2) 的 DRAM 往返） 在 S 大时是压倒性的。S 小的时候这笔交易并不划算—— 本章实测 S=512 时只有 3.2×，而 S=8192 时是 12.3×。

7.3 SDPA 为什么是一个调度器

PyTorch 没有把 FlashAttention 直接做成 attention 的唯一实现， 而是留了一个多后端的选择层。理由能从上表读出来： 每个后端都有它跑不了的情况（head_dim 限制、dtype 限制、mask 形状限制、 硬件架构限制），而 MATH 提供较通用的回退路径，但也需满足接口约束。

代价是"我不知道它选了哪个"，所以才需要 sdpa_kernel 这样的显式上下文 来做 A/B——这正是本章第六节做的事。0.3 里那条"同一个 Python 调用 不保证两张卡跑同样的机器码"，在这里是同一个道理。

190     def flash_like(Q, K, V, block=64, causal=True):
191         """分块 attention。Q/K/V: [B, H, S, D]。只用基本张量运算。"""
192         B, H, S, D = Q.shape
193         scale = D ** -0.5
194         O = torch.zeros_like(Q)
195         # 外层遍历 Q 的块（FA2 的顺序），内层遍历 K/V 的块
196         for q0 in range(0, S, block):
197             q1 = min(q0 + block, S)
198             Qb = Q[:, :, q0:q1]                          # [B,H,bq,D]
199             m = torch.full((B, H, q1 - q0), float("-inf"), device=Q.device,
200                            dtype=Q.dtype)
201             l = torch.zeros((B, H, q1 - q0), device=Q.device, dtype=Q.dtype)
202             acc = torch.zeros_like(Qb)
203             for k0 in range(0, S, block):
204                 k1 = min(k0 + block, S)
205                 if causal and k0 > q1 - 1:               # 整块都在未来，跳过
206                     continue
207                 Kb, Vb = K[:, :, k0:k1], V[:, :, k0:k1]
208                 s = (Qb @ Kb.transpose(-1, -2)) * scale  # [B,H,bq,bk]
209                 if causal:
210                     qi = torch.arange(q0, q1, device=Q.device).view(-1, 1)
211                     ki = torch.arange(k0, k1, device=Q.device).view(1, -1)
212                     s = s.masked_fill(ki > qi, float("-inf"))
213                 m_blk = s.amax(dim=-1)                   # [B,H,bq]
214                 m_new = torch.maximum(m, m_blk)
215                 corr = torch.exp(m - m_new)
216                 corr = torch.nan_to_num(corr, nan=0.0)   # 首块 m=-inf
217                 p = torch.exp(s - m_new.unsqueeze(-1))
218                 p = torch.nan_to_num(p, nan=0.0)         # 整行被 mask 掉时
219                 l = l * corr + p.sum(dim=-1)
220                 acc = acc * corr.unsqueeze(-1) + p @ Vb
221                 m = m_new
222             O[:, :, q0:q1] = acc / l.clamp(min=1e-20).unsqueeze(-1)
223         return O

九 · 陷阱

  1. 不减最大值的 softmax 会在 x>88（fp32）时溢出成 nan， 而且是整行全毁。bf16 的指数范围和 fp32 一样，但尾数更短，问题一样在。
  2. 分块时首块的 m=−∞ 会产生 nan（−∞−(−∞)）。
  3. 因果 mask 下整块都在未来时必须跳过，否则整块 −∞ 同样产生 nan。
  4. 中间不要做除法。归一化留到最后，否则基准改变时还要把除过的乘回来。
  5. 不要把分块当近似。 它是精确重排，误差只有浮点舍入量级（本章 10−7，fp32）。 如果你测出来误差远大于这个，是实现错了，不是"分块的固有误差"。
  6. 算加速比要说明 S。 本章从 3.2×（S=512）到 12.3×（S=8192）， 引用单个数字没有意义。
  7. 统计因果 attention 的 FLOP 时，应按实际计算区域计数。 若沿用完整矩阵的计算量，这组结果会被高估为 393 TFLOP/s，超过该卡的 232 TFLOP/s 实测参照。 凡是算出来超过 roofline 的数字，先查自己的公式。
  8. torch.cuda.max_memory_allocated() 测的是 PyTorch 的 allocated， 不是 reserved（2.0 §4.3）。测峰值前要 reset_peak_memory_stats()。

十 · 自测题

1. 为什么不能把分块 attention 的算术强度一律写成 S/2？

S/2 来自非因果 FLOP 为 4S2D、Q/K/V/O 各读写一次共 8SD 字节的理想假设。实际 kernel 的片上容量有限，query tile 可能重复读取 K/V，因果 mask 也改变工作量。因此需要注明模型，实际 DRAM 流量需计数器验证。

2. 修正因子 exp(m_old - m_new) 为什么可以提到求和外面？为什么它永远不会放大？

lold=∑iexi−mold。要把基准换成 mnew， 每一项都要变成 exi−mnew=exi−mold·emold−mnew。 每项乘的是同一个常数，而求和是线性的，所以可以提到外面乘一次。

不会放大是因为 mnew=max(mold,mblk)≥mold， 所以指数 mold−mnew≤0，因子 ≤1。

这一条很重要：它保证了 online 版本的数值稳定性不比三遍写法差。 如果基准可能下降，累积值就会被放大，多轮之后可能溢出。

3. 有人说"FlashAttention 用精度换了速度"。这个说法错在哪？

错在把"重排求值顺序"当成"近似"。分块 attention 计算的是同一个数学表达式， 只是改变了求值顺序与中间结果的存放位置。

本章实测：自己写的分块版本与 SDPA 的 max|err| 是 10−7 量级， 正是 fp32 的机器精度（2−23≈1.2×10−7）； 块大小从 16 变到 256，误差不变。

浮点加法不满足结合律，所以换顺序确实会改变末位（本章块大小 4 那行 l 的末位差了 1）。但这与"用精度换速度"是两回事—— 朴素实现换个累加顺序也会有同样量级的差异（2.4 讨论过）。

真正用精度换速度的是量化（4.3）和低精度累加（4.2），不是分块。

4. 你实现了一个分块 attention，S=1024 时和 SDPA 差 1e-2。可能是哪里错了？

10−2 远大于 fp32 的舍入量级 10−7，所以是实现错误，不是数值噪声。 按可能性排：

  • 忘了修正 O 累加器：只修正了 l 没修正 O，或者反过来。 两者必须用同一个修正因子。
  • 中途做了归一化：每块都除以当时的 l，基准改变后没乘回来。
  • 因果 mask 的边界：块内的 mask 用了全局索引还是块内索引，差一位。
  • 修正因子用了 emnew−mold（符号反了）： 这会放大而不是缩小，误差通常更大且随 S 增长。

诊断办法：把 S 调到很小（比如 8，一块就装下），如果这时是精确的， 说明单块路径没问题，错在跨块的修正上；再用两块（S=16）逐步打印 m、l、O，和三遍写法逐块对。

5. 什么时候分块 attention 反而不划算？

S 很小的时候。分块要付出重复计算（每块一次修正因子、O 反复缩放） 和更复杂的访存模式，而省下的 O(S2) 往返在 S 小时本来就不大。

本章实测：S=512 只有 3.2×，S=8192 是 12.3×。再往小走， 加上 kernel launch 开销（L1.4 实测 2.68 µs），收益会进一步被摊薄。

decode 阶段是个特例：那时 Q 只有 1 个 token，S×S 退化成 1×S， 根本没有二次项。所以 decode 需要的是完全不同的优化—— split-K、GQA、paged 布局，这是 3.3 的内容。
