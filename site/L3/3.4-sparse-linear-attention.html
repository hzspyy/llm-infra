3.4

稀疏、线性与混合架构

从真实模型里把 attention sink 量出来（最后一层 73% 的注意力给了第一个 token），再讲滑动窗口为什么不能简单丢弃。滑动窗口 decode 耗时随上下文完全不变；线性 attention 的精确检索能力从 1.0000 掉到 0.2393；RoPE 频率表说明外推失败的确切机制。

实测机器 crater (RTX 5090 D, sm_120) · torch 2.13.0+cu130 · Qwen3-1.7B数据日期 2026-09-10前置 3.1（online softmax）· 3.3（decode 的账）· 0.2（资源账本）

本章回答三个问题

3.3 给出的结论是：decode 的算术强度恒为 1，唯二的出路是读得更快或读得更少。 GQA/MLA 走的是"每个 token 少存点"。这一章看另一条路：少读一些 token， 以及更激进的——把 softmax 换掉，让状态大小与上下文无关。

  1. 只保留最近 W 个 token 会怎样？为什么不能简单地把旧的丢掉？
  2. 线性 attention 把 O(S2) 变成 O(S)，它用什么换的？
  3. 长上下文外推为什么会失败？RoPE scaling 到底改了什么？

这一层大部分还在变动

NSA、MoBA 这些 2025 年的稀疏方案还没有可直接使用的实现， Mamba 类混合架构需要专门的权重。所以本章严格分两类： 能在这张卡上直接测的（attention sink、滑动窗口、线性 attention 的复杂度与检索能力、 RoPE 频率表），和只能按定义算的。凡是算出来的都明确标注。

一 · attention sink：真实模型里的一个反常现象

先看一个现象，它决定了滑动窗口能不能简单地做。

拿 Qwen3-1.7B 跑一段 33 token 的文本，把注意力权重取出来 （attn_implementation="eager" + output_attentions=True）， 看最后一个 query 分给第 0 个 token 多少注意力。 如果注意力是均匀的，应该是 1/33=0.0303：

层 给 token 0 给最近 8 个 其余 token 0 是均匀的几倍
2 0.1045 0.3332 0.5623 2.7×
14 0.4847 0.1888 0.3265 12.6×
26 0.6465 0.1842 0.1693 16.8×
27 0.7279 0.1746 0.0975 18.9×

最后一层把 73% 的注意力给了第一个 token。 那个 token 是：

token id 785 = 'The'

一个没有任何语义重要性的冠词。

按头铺开（第 14 层，16 个头给 token 0 的份额）：

0.527 0.402 0.621 0.523 0.438 0.629 0.268 0.734 0.449 0.027 0.844 0.363 0.352 0.145 0.980 0.453
最大 0.980  最小 0.027  中位数 0.449

有的头给了 98%，有的只给 2.7%。这不是所有头的统一行为， 而是多数头都有、程度不一。

为什么会这样

文献里的解释是：softmax 强制每行和为 1。当某个头在这一步"不想关注任何东西"时， 它没有"全都不看"这个选项——那份概率质量必须倒在某处。 于是它选了位置最固定、内容最无关紧要的第一个 token。

本章只测到了现象，没有验证机制

上面那段解释我没有做实验验证。要验证它，可以做的实验是： 在 softmax 里额外加一个可学习的"垃圾桶"logit（即所谓 softmax-off-by-one / sink token）， 看 token 0 的份额会不会转移过去。在做这个实验之前， 把它当成一个流行的解释，不是已确立的事实。

对滑动窗口的直接后果

如果窗口把 token 0 划出去，那 73% 的质量无处可去，会被迫分给窗口内的 token—— 本来"不想关注"的头突然被迫强烈关注某些近处的内容。这就是为什么 StreamingLLM 要单独保留最前面几个 token（sink token）， 而不是简单地丢掉窗口外的一切。

先有这个现象，才有那个设计。 这是本章把 sink 放在滑动窗口之前讲的原因。

二 · 滑动窗口：把 KV 变成常数

full attention 的 KV 随上下文线性增长，无上界。 滑动窗口（SWA）只保留最近 W 个 token 的 KV，上界就是 W。

按 Qwen3-1.7B 的配置算（28 层，8 KV 头，D=128，bf16，每 token 114688 B）：

上下文 full KV W=4096 W=1024
4096 448.0 MB 448.0 MB 112.0 MB
16384 1792.0 MB 448.0 MB 112.0 MB
65536 7168.0 MB 448.0 MB 112.0 MB
262144 28672.0 MB 448.0 MB 112.0 MB
1048576 114688.0 MB 448.0 MB 112.0 MB

上下文 1M 时 full 要 114 GB（这张卡只有 32 GB），W=4096 只要 448 MB。 但真正的关键不是那个 256 倍，是后两列不再增长。

decode 每步耗时实测（B=8, H=8, D=128）：

上下文 full ms W=4096 ms 加速
4096 0.0909 0.0912 1.00×
16384 0.6609 0.0907 7.29×
65536 2.5253 0.0902 27.98×
131072 5.5029 0.0910 60.49×

W=4096 那一列是平的：0.0912 / 0.0907 / 0.0902 / 0.0910。 上下文长了 32 倍，每步耗时纹丝不动。

这直接来自 3.3 的结论：decode 时间 = KV 字节 ÷ 带宽。 KV 字节被 W 钉住，时间就被钉住。从"随上下文线性增长"变成"常数"， 这是 SWA 唯一但足够大的卖点。

代价当然也是明确的：窗口外的信息完全看不到。 实际模型（Mistral、Gemma）的做法是靠层数堆感受野—— L 层滑动窗口的理论感受野是 L×W—— 或者交替使用滑动窗口层与 full attention 层， 让少数几层负责长程。

三 · 线性 attention：换掉 softmax

标准 attention 必须先算 QK⊤，因为 softmax 不可分解。 线性 attention 把 softmax 换成一个可分解的核 ϕ(q)·ϕ(k)⊤：

Oi=ϕ(qi)·∑j≤iϕ(kj)vj⊤ϕ(qi)·∑j≤iϕ(kj)

括号里那两个和可以增量维护：一个 d×d 矩阵和一个 d 维向量。 于是 decode 时的状态大小 与上下文长度无关——这是它最吸引人的性质。

3.1 复杂度优势不会自动变成性能优势

用最朴素的 ϕ=elu(x)+1 实现（prefill，B=1, H=8, D=64）：

S 标准 ms 线性 ms 标准/线性 标准峰值 MB 线性峰值 MB
512 0.0556 0.4245 0.13× 1.0 130.0
1024 0.1071 0.9224 0.12× 2.0 260.0
2048 0.3458 1.8435 0.19× 4.0 520.0
4096 0.8770 3.7624 0.23× 8.0 1040.0

"线性"的那个慢 4–8 倍，显存多 130 倍。

原因是我这个朴素写法用 cumsum 把 S 份 d×d 状态全物化了 （S×d×d = 4096 × 64 × 64 × 4B × 8 头 = 1040 MB）。 真实的线性 attention 用分块递推，块内并行、块间串行传递状态， 不物化中间状态。

这一格的用处正是它是负面的：O(S) 的复杂度是渐近性质， 在 S=4096、常数因子差几十倍的时候完全体现不出来。 拿"复杂度更低"当"更快"的论据，在这个尺度上是错的。

3.2 它真正换掉的东西：精确检索

做一个最小的检索任务：序列里埋一个 key-value 对，让最后一个 query 明确指向它。

埋在位置 37，最后一个 query 指向它
标准 attention 取回的向量 与目标的余弦相似度: 1.0000
线性 attention 取回的向量 与目标的余弦相似度: 0.2393

标准 attention 精确取回（1.0000），线性只有 0.2393。

机制是 softmax 的指数放大：es 让最大的那一项压倒性地主导， 其余项被压到接近 0，于是输出几乎就是那一个 vj。 线性核没有这个放大——状态是所有 (k,v) 的加权和， 新信息不断叠加进同一个固定大小的状态里，旧信息被摊平。

这就是纯线性/SSM 架构在"大海捞针"类任务上吃亏的直接原因。 固定大小的状态是它的优点（与上下文无关），也是它的极限（信息容量有上界）。

也正是混合架构流行的原因：少数几层用 full attention 负责精确检索， 其余层用线性/SSM 负责廉价的长程传播。 （0.2 里 SGLang 的 pool_configurator 要处理 "Mamba 层不产生 KV" 这种情况， 就是这类架构在工程侧的账。）

四 · RoPE 与长上下文外推

从 Qwen3-1.7B 的 config 读到：head_dim=128, rope_theta=1e+06, max_position_embeddings=40960, rope_scaling=None。

RoPE 把 head_dim 拆成 64 对，第 i 对的角频率 =1/base2i/d：

第几对 角频率 周期(token)
0 1.000e+00 6.3
1 8.058e-01 7.8
8 1.778e-01 35.3
16 3.162e-02 198.7
32 1.000e-03 6283.2
62 1.540e-06 4080185.2 周期 > 训练长度 40960，从未转满一圈
63 1.241e-06 5063256.0 周期 > 训练长度 40960，从未转满一圈

关键在最后两行：周期大于训练长度的那些维度， 在训练中从未见过完整的一圈。推理时位置一旦超过 40960， 它们进入训练中没出现过的角度区间。

这就是长上下文外推失败的直接机制——不是含糊的"模型记不住"， 而是某些输入维度取到了训练分布外的值。

三种 scaling 改了什么

想把 40960 撑到 163840（s=4）：

方案 最高频周期(i=0) 中间(i=32) 最低频周期(i=63)
原始 6.28 6283.2 5063256.0
PI（位置插值） 25.13 25132.7 20253024.0
NTK（base 放大） 6.28 12705.4 20253024.0

最低频那一列 PI 与 NTK 完全一样（都 ×4）—— NTK 的 base 放大公式本来就是这么设计的，让最低频恰好对上 PI。

差别全在最高频：PI 把 i=0 的周期从 6.28 拉到 25.13（×4）， NTK 拉到 6.28（×1.000，几乎不变）。

高频维度负责区分"相邻几个 token"。PI 把它也拉长 4 倍， 等于让模型分不清近处的位置；NTK 保住高频，只拉低频。 YaRN 在此基础上再按维度分段处理，并加一个注意力温度修正。

本节只算了频率，没有测任何模型质量

哪种 scaling 更好必须跑长上下文评测（大海捞针、长文困惑度）。 频率表只能说明它们改了什么，不能说明改得好不好。 本轮没有做这个评测——它需要长文本数据集和相当的算力预算。

五 · 设计取舍

5.1 三条路线砍的是账本里不同的项

回到 3.3 那个式子：decode 每步时间 ≈ KV 字节 ÷ 带宽。 KV 字节 =2·L·Hkv·D·ctx·dtype。

路线 砍哪一项 保留什么 代价
GQA / MQA Hkv 精确 attention、全上下文 表达能力（KV 侧）
MLA Hkv·D（压成低秩） 精确 attention、全上下文 多一次投影（算力换带宽）
KV 量化（4.3） dtype 精确 attention、全上下文 数值精度
滑动窗口 ctx 精确 attention（窗口内） 窗口外完全看不到
线性 / SSM 整个式子（状态恒定） 常数状态 精确检索能力（本章 1.0 → 0.24）

前三条不改变 attention 的语义，只改变存什么、存多精细—— 所以它们可以叠加使用，而且不需要重新论证模型能力。 后两条改变了模型能看到什么，必须重新训练并评估质量。

这与 3.1 §7.1 讲的是同一条判据：精确的优化传播得快， 改变语义的优化要过质量这一关。 GQA 用了几年就成了默认配置， 而线性 attention 讨论了更久仍未取代 attention，差别就在这里。

5.2 混合架构是这个取舍的显式解

既然精确检索只在少数几层、少数几个头上真正需要（第一节那张表里 各头差异从 0.027 到 0.980），那就不必让每一层都付全额代价。

混合架构的逻辑是：把稀缺资源（精确的全上下文 attention） 只花在需要它的地方。少数层用 full attention，其余层用滑动窗口或线性状态。

这是一个可复用的判断：当一个能力的需求分布很不均匀时， 统一供给是浪费。 先量出分布（像第一节那样），再决定怎么分配。

5.3 attention sink 是"实现细节"变成"架构约束"的例子

sink 现象不是设计出来的，是训练出来的副产品。 但它一旦存在，就成了后续所有设计的硬约束： 任何丢弃前几个 token 的方案都必须处理它。

这类"涌现出来的约束"在系统里很常见，而且只能通过观测发现， 无法从设计文档推出。所以第一节是先看数据、再讲机制， 而不是先讲 StreamingLLM 的设计然后说"因为有 sink"。

147def section_C():
148    title("[C] 线性 attention：把 softmax 换掉之后")
149
150    print("  标准 attention：O = softmax(QK^T/√d) V，必须先算 QK^T（S×S）。")
151    print("  线性 attention：把 softmax 换成一个可分解的核 φ(q)·φ(k)^T，于是")
152    print("      O_i = φ(q_i) · Σ_{j<=i} φ(k_j) v_j^T  /  (φ(q_i) · Σ_{j<=i} φ(k_j))")
153    print("  括号里那两个和是**可以增量维护的状态**（一个 d×d 矩阵 + 一个 d 向量）。")
154    print("  于是：不需要 S×S，decode 时状态大小与上下文长度**无关**。")
155
156    def linear_attn(Q, K, V):
157        """最简单的 φ = elu(x)+1 版本，因果。O(S·d²)。"""
158        phi_q = F.elu(Q) + 1
159        phi_k = F.elu(K) + 1
160        # 累积状态：KV[i] = Σ_{j<=i} φ(k_j) v_j^T,  Z[i] = Σ_{j<=i} φ(k_j)
161        kv = torch.einsum("bhsd,bhse->bhsde", phi_k, V).cumsum(dim=2)
162        z = phi_k.cumsum(dim=2)
163        num = torch.einsum("bhsd,bhsde->bhse", phi_q, kv)
164        den = torch.einsum("bhsd,bhsd->bhs", phi_q, z).clamp(min=1e-6)
165        return num / den.unsqueeze(-1)
166
167    sub("复杂度对照（prefill，B=1 H=8 D=64）")
168    B, H, D = 1, 8, 64
169    print(f"  {'S':>7} {'标准 ms':>10} {'线性 ms':>10} {'标准/线性':>10} "
170          f"{'标准峰值MB':>11} {'线性峰值MB':>11}")
171    for S in [512, 1024, 2048, 4096]:
172        Q = torch.randn(B, H, S, D, device="cuda", dtype=torch.float32)
173        K = torch.randn(B, H, S, D, device="cuda", dtype=torch.float32)
174        V = torch.randn(B, H, S, D, device="cuda", dtype=torch.float32)
175        torch.cuda.reset_peak_memory_stats(); base = torch.cuda.memory_allocated()
176        t_std = timeit(lambda: F.scaled_dot_product_attention(Q, K, V, is_causal=True), n=10)
177        m_std = (torch.cuda.max_memory_allocated() - base) / MB
178        torch.cuda.reset_peak_memory_stats(); base = torch.cuda.memory_allocated()
179        t_lin = timeit(lambda: linear_attn(Q, K, V), n=10)
180        m_lin = (torch.cuda.max_memory_allocated() - base) / MB
181        print(f"  {S:>7} {t_std:>10.4f} {t_lin:>10.4f} {t_std / t_lin:>9.2f}× "
182              f"{m_std:>10.1f} {m_lin:>10.1f}")
183        del Q, K, V
184        torch.cuda.empty_cache()
185    print("\n  注意：这个朴素线性实现用 cumsum 物化了 S 份 d×d 状态，")
186    print("  所以它的显存反而更大、也没有更快。**真实的线性 attention 用**")
187    print("  **分块递推，不物化中间状态。** 这里量的是「朴素写法」，")
188    print("  用来说明复杂度优势不会自动变成性能优势。")
189
190    sub("线性 attention 换掉了什么：精确检索")
191    print("  做一个最简单的检索任务：序列里埋一个 key-value 对，最后去查它。")
192    S, D = 256, 64
193    torch.manual_seed(0)
194    Q = torch.zeros(1, 1, S, D, device="cuda")
195    K = torch.randn(1, 1, S, D, device="cuda")
196    V = torch.randn(1, 1, S, D, device="cuda")
197    target = 37
198    Q[0, 0, -1] = K[0, 0, target] * 8.0        # 让最后一个 query 明确指向 target
199    std = F.scaled_dot_product_attention(Q, K, V, is_causal=True)[0, 0, -1]
200    lin = linear_attn(Q, K, V)[0, 0, -1]
201    want = V[0, 0, target]
202    print(f"  埋在位置 {target}，最后一个 query 指向它")
203    print(f"  标准 attention 取回的向量 与目标的余弦相似度: "
204          f"{F.cosine_similarity(std, want, dim=0).item():.4f}")
205    print(f"  线性 attention 取回的向量 与目标的余弦相似度: "
206          f"{F.cosine_similarity(lin, want, dim=0).item():.4f}")
207    print("\n  softmax 的指数放大让最大的那一项主导，可以做到近乎精确的检索；")
208    print("  线性核没有这个放大，状态是所有 (k,v) 的加权和，信息被摊平了。")
209    print("  这就是纯线性架构在「大海捞针」类任务上吃亏的原因，")
210    print("  也是混合架构（几层 full attention + 多层线性/SSM）流行的原因。")

建议的消融

  1. 验证 sink 的机制（第一节标为未验证的那条）：在注意力 softmax 里 加一个固定的额外 logit（相当于一个"垃圾桶"），看 token 0 的份额会不会下降。 这需要改 HF 的 attention 实现，是本章最有价值的一个练习。
  2. 把 [A] 换成一段以标点开头或以罕见 token 开头的文本， 看 sink 是否仍落在位置 0。这能区分"位置效应"与"token 内容效应"。
  3. [C] 的线性实现改成分块递推（块内并行、块间传状态）， 看能不能把显存从 1040 MB 降回 O(d2)、时间降到标准之下。 这是"复杂度优势能否兑现"的实操检验。
  4. [D] 里把 rope_theta 从 1e6 换成 1e4（老模型的常见值）， 重算那张表——看训练长度内"从未转满一圈"的维度会多多少。

七 · 陷阱

  1. 复杂度更低 ≠ 更快。 本章朴素线性 attention 在 S=4096 上比标准慢 4.3 倍、 显存多 130 倍。渐近优势要在足够大的 S 上、且实现得当才兑现。
  2. 滑动窗口不能简单地丢掉窗口外的一切。 attention sink 让最前面几个 token 承载了大量注意力质量（本章实测 73%），丢掉它们会显著改变行为。
  3. output_attentions=True 需要 eager 实现。 FlashAttention 类后端 不物化注意力矩阵，拿不到权重——这本身就是 3.1 的结论。
  4. PI 与 NTK 在最低频上完全一样，差别在高频。只比最低频会得出"两者相同"的错误结论。
  5. 频率表说明不了质量。 判断 scaling 好坏必须跑长上下文评测。
  6. sink 的机制解释本章没有验证。 现象是实测的，解释是文献的。
  7. 线性 attention 的"状态与上下文无关"是优点也是上界。 固定容量意味着 信息必然被摊平（本章检索 1.0000 → 0.2393）。

八 · 自测题

1. 为什么用 FlashAttention 后端就拿不到注意力权重矩阵？

因为 FlashAttention 从不物化 S×S 的注意力矩阵—— 这正是它的全部意义（3.1）。它分块计算，块内的打分算完立刻用掉就丢， 只保留 m、l、O 三个累加量。

所以 output_attentions=True 必须配 attn_implementation="eager"， 也就是回到 3.1 里那个朴素实现（MATH 后端）。代价是显存和速度都差很多， 只能在很短的序列上做。

这也意味着：任何需要看注意力权重的分析（可解释性、剪枝、稀疏化研究） 都不能直接在生产路径上做。

2. 你把滑动窗口的 W 从 4096 减到 1024，decode 快了多少？KV 省了多少？

按 3.3 的式子，两者都应该是 4×——KV 字节和每步时间都正比于 W。

本章的 KV 表可以直接读：448.0 MB → 112.0 MB，正好 4×。 时间没有直接测 W=1024，但 [B] 表里 W=4096 那一列是平的（~0.091 ms）， 说明时间确实只由 W 决定，所以 W 减到 1/4，时间也应到 ~0.023 ms。

这是一个可以预测再验证的练习，不需要重新跑就能算出来， 正是 3.3 §一 那个"时间 = 字节 ÷ 带宽"的用处。

3. 为什么 softmax 能做精确检索，而线性核不能？

softmax 里的 es 是指数放大：如果某一项的打分比其余高几个单位， e 的差距就是几倍到几十倍，归一化之后它几乎独占全部权重， 输出就约等于那一个 vj。本章实测余弦相似度 1.0000。

线性核 ϕ(q)·ϕ(k) 是多项式量级的，没有这种放大。 而且它把所有历史压进一个固定大小的状态矩阵里—— 新的 (k,v) 不断加进去，任何单一项的占比都被稀释。本章实测 0.2393。

一句话：指数放大是 attention 能做"选择"而不只是"平均"的原因。 换掉 softmax 就换掉了这个能力。

4. 一个模型 max_position_embeddings=40960，你要让它处理 160K 上下文。直接外推为什么不行？

看频率表最后两行：周期 4080185 和 5063256 token 的那些维度， 在 40960 以内连一圈都没转完。训练时它们只见过角度区间的一小段。

推理时位置到 160K，这些维度的角度进入训练中从未出现的区间。 模型对这些输入没有任何学过的行为——不是"忘了"，是没见过。

解决方向是 scaling：把角度压回训练见过的范围。 PI 直接把位置除以 4（所有频率同等缩小）； NTK 通过放大 base，让低频被拉长而高频基本不变（本章表里 6.28 → 6.28）。

但注意：scaling 之后仍然需要评测。 频率落回训练区间是必要条件， 不是充分条件——模型在插值出来的中间位置上表现如何，只能测。

5. 为什么 GQA 几年内成了默认配置，而线性 attention 讨论更久却没取代 attention？

因为两者要过的关不一样。

GQA 只改"存多少 KV 头"，attention 的计算语义完全不变。 它的收益可以从账本直接算出来（3.3 实测线性可预测）， 风险局限在 KV 侧的表达能力，容易评估。

线性 attention 改变了模型能看到什么——固定大小的状态注定摊平信息 （本章检索 1.0000 → 0.2393）。它必须在完整的能力评测上证明自己， 而"在大多数任务上接近"不足以让人放弃"在检索任务上精确"。

这是 3.1 §7.1 那条判据的又一次应用：精确的优化传播得快， 改变语义的优化要过质量这一关，而质量这一关很贵也很慢。

混合架构之所以是当前的主流答案，正因为它试图两头都要： 少数层保留精确能力，多数层享受廉价状态。
