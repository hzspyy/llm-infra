PyTorch 运行时：内存、流与异步生命周期

连接 Python 引用、allocator 块状态、CUDA stream/event 和图内存池，解释张量何时失去引用、存储何时可复用、GPU 何时完成使用。

环境：RTX 5090 D，PyTorch 2.13.0；CPU mini 只演示状态规则，不作为 GPU 完成语义的证据。

本章回答的三个问题

  1. Python 引用释放、allocator 可复用、GPU 完成为什么不是同一个时刻？
  2. wait_stream 与 record_stream 分别解决哪一类跨流错误？
  3. 怎样从 snapshot 和统计计数器区分活跃块、等待回收、段内空洞与图私有池？

心智模型

del x 只去掉一个 Python 引用。其它别名或 autograd 保存值仍可持有 storage。最后一个持有者释放后，allocator 的复用策略还取决于创建流和其它使用流；GPU 是否完成是另一件事。

三个生命周期与两种依赖

同流：CPU 复用可以早于 GPU 完成

在同一流中执行分配、计算和再次分配，GPU 命令按提交顺序消费内存。没有额外使用流时，native allocator 的 free 可以立即把块放回对应创建流的缓存；之后同流的新写入排在旧读取之后，不需要每次释放都查询 event。

x = torch.randn(2000, 2000, device="cuda")
y = x * 2
del x
z = torch.empty(2000, 2000, device="cuda")
# 即使地址被重用，同流上的新写入也在先前读取之后执行。

memory_allocated() 衡量当前张量分配的块字节；memory_reserved() 是 allocator 持有的段字节。差值还可能包含等待其它流完成的块，不等于立即可复用空间，更不等于全部都是碎片。

跨流：数据就绪与存储寿命分别处理

producer = torch.cuda.Stream()
consumer = torch.cuda.Stream()
with torch.cuda.stream(producer):
    x = torch.randn(1024, device="cuda")
    y = x * 2
with torch.cuda.stream(consumer):
    consumer.wait_stream(producer)  # 等待 y 的生产
    z = y * 3
    y.record_stream(consumer)       # 防止在 consumer 用完之前复用 y 的 storage
del y

只调用 record_stream 不会让 consumer 等待 producer；只建立生产依赖，也不自动把 consumer 的后续使用告诉 allocator。如果调用方掌握完整生命周期，可以在释放前让创建流等待使用流，例如 producer.wait_stream(consumer)，再释放 y；这样后续创建流上的复用也有正确顺序。无需把所有设备工作同步到 CPU。

官方 record_stream 说明明确区分了这两条保证。

两类竞态的实测

stream_races.py 分别移除执行依赖与使用流记录；两组错误不能混成“跨流不安全”一个开关。

条件 观察
缺少 wait_stream 20 次中 19 次读到旧值
建立 wait_stream 同组 20 次未读到旧值
缺少 record_stream 且提前释放 20 次都观察到地址复用与错误读值
补全寿命依赖 同组未发生提前复用或错误读值

完整时间与值见跨流原始输出。成功次数不能单独证明没有竞态；安全性来自明确的 happens-before 关系。

Snapshot 与碎片口径

字段或计数器 含义 使用限制
active_allocated 块仍被张量占用 snapshot 的 block state
active_awaiting_free 张量已释放，仍等待其它使用流 不能计入可用 free block
inactive 块可供复用 可能属于仍有活跃块的 segment
inactive_split_bytes.all.current native allocator 的非可释放 split 字节统计 来自 memory_stats；不统计 expandable segment
segment_pool_id 段所属池，区分普通池与图私有池 同时记录图的 pool() 身份
is_expandable 段是否使用可扩展映射 直接观察，不能由段数猜测

inactive_split 不是 snapshot 的 state 名。若要在所有模式下观察空洞，可另算“仍含活跃/等待块的 segment 中的 inactive 字节”，但它与 native 的不可释放 split 计数不是同一指标：expandable 的部分映射可回收，不能把两种定义混用。

设计取舍

同流缓存利用已经存在的执行顺序，减少主机同步；跨流跟踪以 event、轮询和延迟复用换取调用方便利。手工把使用流同步回创建流可以少做跟踪，但同步点过早会减少重叠。

普通池与图私有池分开保证捕获地址在 replay 期间有效；“私有”并不排除 expandable 映射。自定义 allocator 的 user pool、内部构建开关与不同 PyTorch 版本须另核对。统计既要说明分配器 backend，也要说明字段的适用范围。

工程实现：最小块池与 snapshot 提取

最小块池将 owner stream、pending event、split/merge 与复用事件显式打印。它演示延迟回收规则，不能代替 native allocator 的全部优化。

 11 class BlockState(Enum):
 12     FREE = "free"
 13     ALLOCATED = "allocated"
 14     PENDING = "pending"
 15 
 16 @dataclass
 17 class Block:
 18     """内存块"""
 19     id: int
 20     size: int
 21     offset: int  # 在 segment 中的偏移
 22     state: BlockState
 23     stream_id: Optional[int] = None  # 分配时的流
 24     event_id: Optional[int] = None   # 释放时记录的 event

 33 class MiniBlockAllocator:
 34     """最小块池 allocator"""
 35 
 36     def __init__(self, segment_size: int = 2 * 1024 * 1024):
 37         self.segment_size = segment_size
 38         self.segments: List[Segment] = []
 39         self.free_blocks: List[Block] = []
 40         self.allocated_blocks: Dict[int, Block] = {}  # block_id -> block
 41         self.pending_blocks: List[Block] = []
 42 
 43         self.next_segment_id = 0
 44         self.next_block_id = 0
 45         self.next_event_id = 0
 46 
 47         # 模拟的 CUDA event 完成状态
 48         self.completed_events = set()
 49 
 50         # 统计
 51         self.total_allocated = 0
 52         self.total_reserved = 0
 53         self.num_cudaMalloc_calls = 0
 54 
 55     def malloc(self, size: int, stream_id: int) -> int:
 56         """分配内存块，返回 block_id"""
 57 
 58         # 1. 尝试从 free_blocks 找合适的块
 59         for block in self.free_blocks:
 60             if block.size >= size:
 61                 # 找到合适的块，复用
 62                 self.free_blocks.remove(block)
 63                 block.state = BlockState.ALLOCATED
 64                 block.stream_id = stream_id
 65                 self.allocated_blocks[block.id] = block
 66                 self.total_allocated += block.size
 67                 return block.id
 68 
 69         # 2. 没有合适的 free block，需要扩展
 70         # 检查现有 segment 是否有空间
 71         for segment in self.segments:
 72             # 计算已用空间
 73             used = sum(b.size for b in segment.blocks)
 74             if segment.size - used >= size:
 75                 # 有空间，切出新块
 76                 offset = used
 77                 block = Block(
 78                     id=self.next_block_id,
 79                     size=size,
 80                     offset=offset,
 81                     state=BlockState.ALLOCATED,
 82                     stream_id=stream_id
 83                 )
 84                 self.next_block_id += 1
 85                 segment.blocks.append(block)
 86                 self.allocated_blocks[block.id] = block
 87                 self.total_allocated += size
 88                 return block.id
 89 
 90         # 3. 需要分配新 segment
 91         segment = self._allocate_segment(max(self.segment_size, size))
 92 
 93         # 从新 segment 切出块
 94         block = Block(
 95             id=self.next_block_id,
 96             size=size,
 97             offset=0,
 98             state=BlockState.ALLOCATED,
 99             stream_id=stream_id
100         )
101         self.next_block_id += 1
102         segment.blocks.append(block)
103         self.allocated_blocks[block.id] = block
104         self.total_allocated += size
105 
106         return block.id
107 
108     def free(self, block_id: int, current_stream_id: int):
109         """释放内存块"""
110 
111         block = self.allocated_blocks.get(block_id)
112         if not block:
113             raise ValueError(f"Block {block_id} not found or already freed")
114 
115         # 标记为 pending
116         block.state = BlockState.PENDING
117 
118         # 记录 event（如果在不同流，需要等待）
119         if block.stream_id != current_stream_id:
120             block.event_id = self.next_event_id
121             self.next_event_id += 1
122 
123         # 移动到 pending 队列
124         del self.allocated_blocks[block_id]
125         self.pending_blocks.append(block)
126         self.total_allocated -= block.size
127 
128     def synchronize(self):
129         """模拟 synchronize：所有 event 完成"""
130         # 标记所有 event 为完成
131         for block in self.pending_blocks:
132             if block.event_id is not None:
133                 self.completed_events.add(block.event_id)
134 
135         # 处理 pending 队列
136         self._process_pending()
137 
138     def process_events(self, completed_event_ids: List[int]):
139         """处理完成的 event"""
140         self.completed_events.update(completed_event_ids)
141         self._process_pending()
142 
143     def _process_pending(self):
144         """检查 pending 队列，将已完成的移到 free"""
145         remaining = []
146 
147         for block in self.pending_blocks:
148             # 检查是否可以移到 free
149             if block.event_id is None or block.event_id in self.completed_events:
150                 # 可以复用
151                 block.state = BlockState.FREE
152                 block.stream_id = None
153                 block.event_id = None
154                 self.free_blocks.append(block)
155             else:
156                 # 仍在等待
157                 remaining.append(block)
158 
159         self.pending_blocks = remaining
160 
161     def _allocate_segment(self, size: int) -> Segment:
162         """分配新 segment（模拟 cudaMalloc）"""
163         segment = Segment(
164             id=self.next_segment_id,
165             size=size,
166             blocks=[]
167         )
168         self.next_segment_id += 1
169         self.segments.append(segment)
170         self.total_reserved += size
171         self.num_cudaMalloc_calls += 1
172         return segment
173 
174     def stats(self) -> dict:
175         """返回统计信息"""
176         return {
177             "allocated": self.total_allocated,
178             "reserved": self.total_reserved,
179             "num_segments": len(self.segments),
180             "num_free_blocks": len(self.free_blocks),
181             "num_allocated_blocks": len(self.allocated_blocks),
182             "num_pending_blocks": len(self.pending_blocks),
183             "num_cudaMalloc_calls": self.num_cudaMalloc_calls,
184             "fragmentation_pct": (self.total_reserved - self.total_allocated) / self.total_reserved * 100 if self.total_reserved > 0 else 0
185         }
186

323 # 上面的 MiniBlockAllocator 只做"整块分配"，看不到切分与合并。
324 # 这一节补三件事：
325 #   1. 每次分配记录 owner stream 与 pending event，释放后仍保留 owner；

328 #
329 # 术语与 torch 对齐，不能混用：
330 #   allocated      已分配出去的请求字节（用户持有引用）
331 #   reserved       向驱动要来的总字节（含空闲段与空闲块）
332 #   active         allocated 的块（含被切分后的剩余部分）
333 #   inactive_split 已释放、但因为是被切出来的"碎片"而无法直接合并的块
334 #   inactive       已释放、可整块复用的完整块
335 #   pending        已释放但 GPU 可能还在用（等 event）的块
336 # =====================================================================

341 class LifecyclePool:
342     def __init__(self, segment_size: int = 20 * 1024 * 1024):
343         self.segment_size = segment_size
344         self.segments: List[Segment] = []
345         self.next_block_id = 0
346         self.next_event_id = 0
347         self.events: List[dict] = []
348         self.completed_events = set()
349 
350     # ---- 内部工具 ----
351     def _new_segment(self, size: int) -> Segment:
352         seg = Segment(id=len(self.segments), size=size, blocks=[])
353         self.segments.append(seg)
354         self.events.append({"op": "cudaMalloc", "segment": seg.id, "bytes": size})
355         return seg
356 
357     def _insert(self, seg: Segment, block: Block):
358         seg.blocks.append(block)
359         seg.blocks.sort(key=lambda b: b.offset)
360 
361     def _merge(self, seg: Segment):
362         """把相邻的 FREE 块合并（真实 allocator 在 free 后做同样的事）。"""
363         seg.blocks.sort(key=lambda b: b.offset)
364         out = []
365         for b in seg.blocks:
366             if out and out[-1].state == BlockState.FREE and b.state == BlockState.FREE \
367                     and out[-1].offset + out[-1].size == b.offset:
368                 out[-1].size += b.size
369                 self.events.append({"op": "merge", "into": out[-1].id,
370                                     "absorbed": b.id, "size": out[-1].size})
371             else:
372                 out.append(b)
373         seg.blocks = out
374 
375     # ---- 分配 ----
376     def malloc(self, size: int, stream_id: int) -> Block:
377         size = max(size, MIN_SPLIT)
378         # 先找能装下的空闲块（best fit）
379         best = None
380         for seg in self.segments:
381             for b in seg.blocks:
382                 if b.state == BlockState.FREE and b.size >= size:
383                     if best is None or b.size < best.size:
384                         best = b
385         if best is not None:
386             seg = next(s for s in self.segments if best in s.blocks)
387             if best.size - size >= MIN_SPLIT:
388                 rest = Block(id=self.next_block_id, size=best.size - size,
389                              offset=best.offset + size, state=BlockState.FREE)
390                 self.next_block_id += 1
391                 best.size = size
392                 self._insert(seg, rest)
393                 self.events.append({"op": "split", "block": best.id,
394                                     "kept": size, "rest": rest.id,
395                                     "rest_size": rest.size})
396             best.state = BlockState.ALLOCATED
397             best.stream_id = stream_id
398             best.event_id = None
399             self.events.append({"op": "reuse", "block": best.id,
400                                 "size": size, "stream": stream_id})
401             return best
402         # 没有合适的：开新段（按 20 MiB 向上取整，和真实大块池一致）
403         seg = self._new_segment(max(self.segment_size, size))
404         blk = Block(id=self.next_block_id, size=size, offset=0,
405                     state=BlockState.ALLOCATED, stream_id=stream_id)
406         self.next_block_id += 1
407         if seg.size - size >= MIN_SPLIT:
408             rest = Block(id=self.next_block_id, size=seg.size - size, offset=size,
409                          state=BlockState.FREE)
410             self.next_block_id += 1
411             self._insert(seg, rest)
412             self.events.append({"op": "split", "block": blk.id, "kept": size,
413                                 "rest": rest.id, "rest_size": rest.size})
414         self._insert(seg, blk)
415         self.events.append({"op": "malloc", "block": blk.id, "size": size,
416                             "stream": stream_id})
417         return blk
418 
419     # ---- 释放：进入 pending，等 event ----
420     def free(self, block: Block, current_stream_id: int, gpu_pending: bool):
421         """gpu_pending=False 表示当前流就是最后使用它的流，可以不记 event。"""
422         block.state = BlockState.PENDING
423         if gpu_pending:
424             block.event_id = self.next_event_id
425             self.next_event_id += 1
426         self.events.append({"op": "free", "block": block.id,
427                             "owner_stream": block.stream_id,
428                             "event": block.event_id})
429 
430     def complete(self, event_id: int):
431         self.completed_events.add(event_id)
432         for seg in self.segments:
433             for b in seg.blocks:
434                 if b.state == BlockState.PENDING and \
435                         (b.event_id is None or b.event_id in self.completed_events):
436                     b.state = BlockState.FREE
437                     self.events.append({"op": "reusable", "block": b.id,
438                                         "owner_stream": b.stream_id})
439             self._merge(seg)
440 
441     # ---- 统计：术语与 torch 对齐 ----
442     def stats(self) -> dict:
443         allocated = active = inactive_split = inactive = pending = 0
444         for seg in self.segments:
445             for b in seg.blocks:
446                 if b.state == BlockState.ALLOCATED:
447                     allocated += b.size
448                     active += b.size
449                 elif b.state == BlockState.PENDING:
450                     pending += b.size
451                 elif b.state == BlockState.FREE:
452                     if b.offset > 0:          # 被切出来的剩余块
453                         inactive_split += b.size
454                     else:
455                         inactive += b.size
456         reserved = sum(s.size for s in self.segments)
457         return {"allocated": allocated, "active": active, "reserved": reserved,
458                 "inactive": inactive, "inactive_split": inactive_split,
459                 "pending": pending,
460                 "segments": len(self.segments),
461                 "cudaMalloc_calls": sum(1 for e in self.events if e["op"] == "cudaMalloc")}

图私有池与运行库工作区

直接匹配 g.pool() 和 segment_pool_id，native 的图池占 54 MiB；expandable 为 42 MiB，对应段的 is_expandable 为 true。释放所有图句柄和静态张量后，进程仍分别保留 64/80 MiB reserved；本次再清除 cuBLAS workspace 后均回到 0。这支持对这些进程残留的解释，不是“删图永不归还”的一般规律。

trace-first 的轨迹发生在图建立前，其轨迹峰值与无图一致；不能将它与 graph-first 的轨迹峰值混称为相同驻留状态。CUDA Graph 的提交节省与容量变化要分别测量。

前沿

可扩展映射、图池共享与基于图拓扑的跨流复用都在改变容量和同步成本。新增接口先核对版本、池类型和实际路径。多图 bucket 可以按明确约束共享 pool，不能无条件用“图数 × 单图峰值”估算所有场景。真实引擎的变长分配与 OOM 行为仍应连接 5.2/5.4 的请求负载，合成轨迹不替代服务容量验证。

陷阱

  • del 不是 GPU barrier，也不保证所有 storage 引用已经释放。
  • record_stream 管寿命，wait_stream/event 管执行顺序；它们不能互换。
  • reserved−allocated 还可能含等待回收的块，不能全部算作可用缓存或碎片。
  • memory_allocated() 在尚未初始化 CUDA 时返回空统计的零值，不会为了读这个值初始化 CUDA；峰值归零也不等于清空缓存。
  • 非零残留必须按活跃对象、pool 与运行库 workspace 归因；仅观察 Python 图对象的删除不足以解释所有显存。

自测题

  1. 同流的新张量为什么能在旧 kernel 完成前拿到同一地址？
展开

allocator 将块交给相同创建流，GPU 的新写入排在旧使用之后；CPU 分配发生得早，不代表 GPU 写入越过了旧读取。

  1. 为什么“调用 record_stream 后输出仍错”不矛盾？
展开

它防止 storage 提前复用，但不负责等待数据生产；consumer 仍需等待 producer。

  1. expandable 的 inactive_split 计数为零，能得出没有碎片吗？
展开

不能。这个 native 计数器不统计 expandable 段。需查看实际块状态与映射回收条件，并标明所用空洞/不可释放量的定义。

  1. 如何证明 graph-first 测到了存活图与请求轨迹共存？
展开

轨迹执行期间保留图、静态输入输出和 stream 句柄；在轨迹前后按 pool ID 保存 snapshot。只先 capture、随后删除图再跑轨迹不满足这个条件。
