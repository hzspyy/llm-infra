
==============================================================================
两 rank 的真实失败（gloo，CPU，带超时）
==============================================================================
  A 两 rank 走不同分支 → RuntimeError: Expected to have finished reduction in the prior iteration before starting a new one. This error indicates that your module has parameters that were not used in producing loss. You can enable unused parameter detection b
    DDP 假定每次迭代所有参数都参与；未参与的参数没有梯度可归约，
    reducer 在下一次前向发现上一次归约没完成。
    可选项：find_unused_parameters=True（每步多一次图遍历），
    或者让两 rank 执行同一组分支。
  B teacher requires_grad=True，经 DDP 前向
     结果：RuntimeError: Expected to have finished reduction in the prior iteration before starting a new one. This error indicates that your module has parameters that were n
     两 rank 的 student 梯度最大差：未比较（这一轮已经报错）
  B teacher requires_grad=False，经 DDP 前向
     结果：正常完成
     两 rank 的 student 梯度最大差：0.000e+00（0 表示确实做了归约）
  B 绕过 DDP 直接调用 model.module(x)
     结果：正常完成
     两 rank 的 student 梯度最大差：1.482e+00（非零说明两 rank 各算各的）
     teacher 在 no_grad 下前向，永远拿不到梯度；requires_grad 忘了关，
     它就进了 DDP 的归约集合，reducer 因此等不到这部分梯度。
     更隐蔽的是第三行：绕过 DDP 的 forward 不会报错，但梯度根本没有同步，
     两 rank 从此各训各的。
  C 两 rank 的 collective 次序相反 → RuntimeError: [/__w/pytorch/pytorch/third_party/gloo/gloo/transport/tcp/unbound_buffer.cc:78] Timed out waiting 15000ms for recv operation to complete
    同名 collective 按调用顺序配对，次序不一致时可能配错，也可能一直等下去。
    条件分支里的 collective 必须保证所有 rank 都执行、且顺序一致。
