4.1

Transformer 层解剖与从零实现

用 Qwen3 权重实现前向计算，与 Hugging Face 实现逐层比较归一化、位置编码和注意力。

实测机器 crater (RTX 5090 D, sm_120) · torch 2.13.0+cu130 · Qwen3-1.7B前置 0.0（最小模型）· 2.0（stride）· 3.3（GQA）· 4.0（权重文件）

本章回答三个问题

0.0 手写过一个玩具 Transformer。这一章把同样的事情做在真实权重上： 直接从 .safetensors 读 Qwen3-1.7B 的张量，只用 torch 的基本算子写一遍前向， 然后逐层和 HuggingFace 对齐。

  1. 从 token id 到 logits，每一步的张量是什么形状、什么 dtype、什么 stride？
  2. 我的实现和 HF 的差多少？只比最终 logits 够不够？
  3. 参数量和 FLOP 能不能从 config 精确算出来？

本章的数值对齐目标

每一层的输出都要和 HF 对上，不只是最终 logits。 中间某一层错了、后面被 norm 拉回来、logits 看起来还行——这种情况很常见， 只比最后一步会漏掉。

实测结果：29 个对照点全部逐位相同（max|diff| = 0.000000）。

一 · 配置里每个数字的含义

hidden_size                2048
intermediate_size          6144
num_hidden_layers          28
num_attention_heads        16
num_key_value_heads        8
head_dim                   128
rms_norm_eps               1e-06
rope_theta                 1000000
vocab_size                 151936
tie_word_embeddings        True
hidden_act                 silu

GQA 分组数 g = nq/nkv = 16/8 = 2
hidden_size = nq×head_dim = 2048 ✓

注意 hidden_size = nq × head_dim 这条不是恒等式，只是这个模型恰好成立。 有些模型（例如某些 MLA 变体）两者不等，实现时不能默认 head_dim = H/nq—— config 里给了 head_dim 就用它。

二 · 一层里的每个张量

B=1, S=7 的一次前向，每个中间量的 shape / dtype / stride：

token ids                        (1, 7)            int64     stride=(7, 1)                连续
embed_tokens 权重                 (151936, 2048)    bfloat16  stride=(2048, 1)             连续
x = emb[ids]                     (1, 7, 2048)      bfloat16  stride=(14336, 2048, 1)      连续   <- gather，不是矩阵乘
rope cos                         (7, 128)          bfloat16  stride=(128, 1)              连续
rope sin                         (7, 128)          bfloat16  stride=(128, 1)              连续

--- attention 分支 ---
input_layernorm 之后              (1, 7, 2048)      bfloat16  stride=(14336, 2048, 1)      连续
q = h @ Wq^T                     (1, 7, 2048)      bfloat16  stride=(14336, 2048, 1)      连续
k = h @ Wk^T                     (1, 7, 1024)      bfloat16  stride=(7168, 1024, 1)       连续   <- 只有 q 的一半宽（GQA）
v = h @ Wv^T                     (1, 7, 1024)      bfloat16  stride=(7168, 1024, 1)       连续
q.view(B,S,nq,hd).transpose(1,2) (1, 16, 7, 128)   bfloat16  stride=(14336, 128, 2048, 1) 不连续 <- 2.0 说过
k 同上                            (1, 8, 7, 128)    bfloat16  stride=(7168, 128, 1024, 1)  不连续
QK-Norm 之后的 q                  (1, 16, 7, 128)   bfloat16  stride=(14336, 128, 2048, 1) 不连续 <- 权重形状 (128,)
RoPE 之后的 q                     (1, 16, 7, 128)   bfloat16  stride=(14336, 128, 2048, 1) 不连续
attention 输出                    (1, 16, 7, 128)   bfloat16  stride=(14336, 128, 2048, 1) 不连续
reshape 回 [B,S,nq*hd]            (1, 7, 2048)      bfloat16  stride=(14336, 2048, 1)      连续   <- reshape 静默拷贝了
o_proj 权重                       (2048, 2048)      bfloat16  stride=(2048, 1)             连续

--- MLP 分支 ---
post_attention_layernorm 之后     (1, 7, 2048)      bfloat16  stride=(14336, 2048, 1)      连续
gate_proj 输出                    (1, 7, 6144)      bfloat16  stride=(43008, 6144, 1)      连续
up_proj 输出                      (1, 7, 6144)      bfloat16  stride=(43008, 6144, 1)      连续
silu(gate)*up                    (1, 7, 6144)      bfloat16  stride=(43008, 6144, 1)      连续
down_proj 权重                    (2048, 6144)      bfloat16  stride=(6144, 1)             连续

下面几项影响张量布局和计算：

  • transpose(1,2) 之后 stride 变成 (14336, 128, 2048, 1)，不连续。 其寻址方式可用 2.0 §1 的 stride 公式解释。
  • reshape 回 [B,S,nq*hd] 之后又连续了。 因为源张量不连续， reshape 静默做了一次拷贝（2.0 §2 的陷阱 1）。 这里是必要的：o_proj 那次 GEMM 需要连续输入。
  • k 只有 q 的一半宽（1024 vs 2048），因为 8 个 KV 头 vs 16 个 query 头。
  • QK-Norm 的权重是 (128,)，作用在 head_dim 上，不是 hidden 上。

三 · 三个容易写错的算子

RMSNorm

RMSNorm(x)=x1d∑ixi2+ϵ⊙w

比 LayerNorm 少一次归约——不减均值，也没有 bias。

62 def rms_norm(x, weight, eps):
63     """RMSNorm：不减均值，只除以均方根。比 LayerNorm 少一次归约。"""
64     dt = x.dtype
65     x = x.float()
66     var = x.pow(2).mean(-1, keepdim=True)
67     x = x * torch.rsqrt(var + eps)
68     return (x.to(dt) * weight)
labs/L4/qwen3_from_scratch.py 第 62–68 行在完整文件中打开 →

两个实现细节决定了能不能对上 HF：

  1. 中间必须升到 fp32。bf16 只有 8 位尾数，平方和累加会丢精度。 HF 也是这么做的，所以不升 fp32 就对不上。
  2. x.to(dt) * weight，先转回 bf16 再乘权重——顺序不同结果就不同。

RoPE

inv = 1.0 / (base ** (torch.arange(0, head_dim, 2).float() / head_dim))
freqs = torch.outer(pos, inv)                 # [S, head_dim/2]
emb = torch.cat([freqs, freqs], dim=-1)       # [S, head_dim]  <- HF 的排布

关键在最后一行：HF 把 freqs 重复两遍拼起来， 配合 rotate_half（把后一半取负移到前面）。 这等价于把 head_dim 拆成前后两半配对，而不是相邻两个配对。

另一种常见排布是相邻配对（[x0,x1], [x2,x3], ...）， 数学上等价但权重不通用——用错排布可能不报错，却会改变输出。 3.4 §四 的频率表就是这里的 inv。

SwiGLU

MLP(x)=Wdown(silu(Wgatex)⊙Wupx)

三个矩阵而不是两个。gate 和 up 形状相同、都是 [6144, 2048]， 但不能互换：silu 只作用在 gate 那一路。

我以为实现错了。查下去发现是比较方式错了： HF 的 output_hidden_states 最后一个元素已经过了 final norm， 而我的列表最后一个是第 27 层的原始输出。 两者的均方根一个是 1.16、一个是 24.12——差 20 倍， 但那是两个不同的量，本来就不该相等。

对齐之后 29 个全部逐位相同。在怀疑实现之前，先确认你比的是同一个东西。 （同一类错误在 4.0 §5 也出现过一次：那次是我预期错了。）

注意「均方根」那一列

从 0.026 一路涨到 24.12，放大了将近 1000 倍。 这是 pre-norm 残差流的正常形态：每层都往残差流里加东西， 而残差本身不被归一化，所以幅度单调增长。 最后靠 final norm 一次拉回到 1.16。

这条曲线是诊断训练问题的常用信号——如果某一层的跳变特别大， 通常那一层有问题。

  • embedding 占全模型 18.1%。小模型上这个比例特别高， 这也是 4.0 §5 里小模型倾向用 tie 的原因。

上面逐项加起来 = 3,440,902,144

差 247,808，来自 embedding 是 gather 不是矩阵乘（0 FLOP） 以及 norm 的那些小张量。 "2× 参数量"这条经验规则的误差在这里是 0.007%。

它不含 attention 本身（QK⊤ 与 PV），因为那一项是 O(S2)， 与序列长度有关——0.2 的账本和 3.1 的推导都在处理这一项。

六 · 设计取舍

6.1 为什么 MLP 是 75% 而 attention 只有 25%

attn=2H(nqhd)+2H(nkvhd)≈4H2·1+g−12,MLP=3HI

Qwen3-1.7B 里 I=3H，所以 MLP =9H2 而 attn ≈3H2。 这个比例是被 intermediate_size 的选择决定的，不是 Transformer 的固有性质。

I/H = 3 是 SwiGLU 时代的常见取值（因为 SwiGLU 用三个矩阵， 要保持总参数量与两矩阵的 I/H=4 相当，3×3=9≈2×4=8）。

含义：想减参数量，动 MLP 比动 attention 有效得多； 而想减 KV cache / decode 带宽，只能动 attention 侧（3.3）。 两个目标压在不同的地方，这是 MoE（4.4）能成立的前提—— 它专门稀疏化那 75%。

6.2 QK-Norm：一个很小的张量，漏了就全错

q_norm/k_norm 各 128 个参数，整个模型里 28×256 = 7168 个， 占参数量的 0.0004%。但漏掉它，模型输出完全错。

这类"参数量可忽略、语义不可忽略"的组件在现代模型里越来越多 （QK-Norm、attention sink 参数、各种 gate）。它们的共同特点是： 从参数量清单上看不出重要性，只能从结构上看。

对写加载器/推理引擎的人来说，这意味着不能靠"覆盖了 99% 的参数量" 来判断实现完整。判据只能是逐层数值对齐——也就是本章第四节做的事。

6.3 逐层对齐用于定位误差来源

只比最终 logits 有两个漏洞：

  1. 误差可能被 final norm 掩盖。 残差流的幅度到最后一层是 24， final norm 会把它压回 1.16——一个 5% 的中间误差在这里会被大幅压缩。
  2. argmax 相同不代表实现正确。 top-1 在多数位置上很稳， 一个有 bug 的实现照样能在短文本上给出相同的 argmax。

逐层对齐能定位到具体哪一层，而且一旦某层对上了， 就可以把该层之前的所有实现视为正确，二分下去很快。

验证重实现时应逐层比较中间张量，以定位最终输出可能掩盖的误差；反向计算还需单独检查梯度，见 2.8。

 62 def rms_norm(x, weight, eps):
 63     """RMSNorm：不减均值，只除以均方根。比 LayerNorm 少一次归约。"""
 64     dt = x.dtype
 65     x = x.float()

 68     return (x.to(dt) * weight)

 71 def rope_tables(seq, head_dim, base, device, dtype):
 72     inv = 1.0 / (base ** (torch.arange(0, head_dim, 2, device=device).float() / head_dim))
 73     pos = torch.arange(seq, device=device).float()
 74     freqs = torch.outer(pos, inv)                 # [S, head_dim/2]
 75     emb = torch.cat([freqs, freqs], dim=-1)       # [S, head_dim]  HF 的排布
 76     return emb.cos().to(dtype), emb.sin().to(dtype)
 77 
 78 
 79 def rotate_half(x):
 80     h = x.shape[-1] // 2
 81     return torch.cat([-x[..., h:], x[..., :h]], dim=-1)
 82 
 83 
 84 def apply_rope(x, cos, sin):
 85     # x: [B, H, S, D]   cos/sin: [S, D]
 86     return x * cos[None, None] + rotate_half(x) * sin[None, None]

 89 class Layer:
 90     def __init__(self, w, i, cfg):
 91         p = f"model.layers.{i}."
 92         self.wq = w[p + "self_attn.q_proj.weight"]
 93         self.wk = w[p + "self_attn.k_proj.weight"]
 94         self.wv = w[p + "self_attn.v_proj.weight"]
 95         self.wo = w[p + "self_attn.o_proj.weight"]
 96         self.qn = w[p + "self_attn.q_norm.weight"]
 97         self.kn = w[p + "self_attn.k_norm.weight"]
 98         self.n1 = w[p + "input_layernorm.weight"]
 99         self.n2 = w[p + "post_attention_layernorm.weight"]
100         self.gate = w[p + "mlp.gate_proj.weight"]
101         self.up = w[p + "mlp.up_proj.weight"]
102         self.down = w[p + "mlp.down_proj.weight"]
103         self.cfg = cfg
104 
105     def forward(self, x, cos, sin, trace=False):
106         c = self.cfg
107         B, S, H = x.shape
108         nq, nkv, hd = c["nq"], c["nkv"], c["hd"]
109         eps = c["eps"]
110 
111         # ---- attention 分支 ----
112         h = rms_norm(x, self.n1, eps)
113         q = h @ self.wq.T
114         k = h @ self.wk.T
115         v = h @ self.wv.T
116         q = q.view(B, S, nq, hd).transpose(1, 2)          # [B, nq, S, hd]
117         k = k.view(B, S, nkv, hd).transpose(1, 2)
118         v = v.view(B, S, nkv, hd).transpose(1, 2)
119         # QK-Norm：在 head_dim 上做 RMSNorm（Qwen3 特有）
120         q = rms_norm(q, self.qn, eps)
121         k = rms_norm(k, self.kn, eps)
122         q = apply_rope(q, cos, sin)
123         k = apply_rope(k, cos, sin)
124         o = torch.nn.functional.scaled_dot_product_attention(
125             q, k, v, is_causal=True, enable_gqa=True)
126         o = o.transpose(1, 2).reshape(B, S, nq * hd)
127         x = x + o @ self.wo.T
128 
129         # ---- MLP 分支 ----
130         h = rms_norm(x, self.n2, eps)
131         g = h @ self.gate.T
132         u = h @ self.up.T
133         x = x + (torch.nn.functional.silu(g) * u) @ self.down.T
134         if trace:
135             return x, dict(after_norm1=h, q=q, k=k, v=v, attn_out=o, gate=g, up=u)
136         return x

建议的消融（每一条都会破坏对齐，先预测在第几层出现、误差多大）

  1. 去掉 QK-Norm（把 rms_norm(q4, lay.qn, eps) 注释掉）。 预测：第 0 层就开始偏，且逐层放大。
  2. RoPE 换成相邻配对（改 rotate_half 的切法）。 预测：短序列上误差小，长序列上迅速变大——因为位置越大角度差越明显。
  3. RMSNorm 不升 fp32（去掉 x.float()）。 预测：误差在 bf16 舍入量级，逐层累积但不发散。这一条最有教学价值： 它是"能跑、看起来对、但不是逐位相同"的典型。
  4. gate 和 up 互换。预测：完全错。这验证 SwiGLU 的不对称性。
  5. 把 intermediate_size 那一项按 §6.1 的公式重算一遍， 换成 I/H = 4、两矩阵 MLP，看 attention 占比会变成多少。

八 · 陷阱

  1. head_dim 不一定等于 hidden_size / num_attention_heads。 config 给了就用。
  2. RoPE 的两种排布数学等价但权重不通用。 用错排布不报错，输出静默错误。
  3. RMSNorm 中间不升 fp32 会对不上 HF。 bf16 尾数只有 8 位。
  4. HF 的 hidden_states 最后一个已含 final norm。 直接和你的层输出比会看到巨大误差。
  5. 只比最终 logits 不足以验收。 final norm 会压缩中间误差。
  6. transpose 之后 reshape 会静默拷贝（2.0）。这里是必要的，但要知道它发生了。
  7. QK-Norm 这类张量参数量可忽略、语义不可忽略。 别用参数量覆盖率判断实现完整性。
  8. gate 与 up 不可互换，silu 只作用在 gate 一路。

九 · 自测题

1. 你重实现了一个模型，最终 logits 的 argmax 和 HF 完全一致。能说明实现正确吗？

不能。两个理由：

  1. final norm 会压缩中间误差。 本章实测残差流的幅度从 0.026 涨到 24.12， 最后被 norm 压回 1.16。一个 5% 的中间层误差在这里会被大幅衰减。
  2. argmax 很稳。 在多数位置上 top-1 的 logit 领先第二名不少， 一个有 bug 的实现照样能在短文本上给出相同的 argmax。

验证时应逐层比较中间张量（本章第四节）， 这样还能直接定位到出错的层。

2. 一个 1.7B 模型，MLP 和 attention 各占多少参数？这个比例是固定的吗？

本章实测：每层 MLP 75.0%、attention 25.0%。

不是固定的，它由 intermediate_size / hidden_size 决定。 Qwen3-1.7B 是 I/H=6144/2048=3，SwiGLU 三个矩阵，所以 MLP =9H2； attention（GQA g=2）约 3H2。

如果换成两矩阵 MLP、I/H=4，MLP 就是 8H2，比例会变。

含义：减参数量要动 MLP，减 KV cache 要动 attention—— 两个目标压在不同的地方。这是 MoE 只稀疏化 MLP 的原因。

3. RMSNorm 里为什么要升到 fp32？不升会怎样？

因为要算 ∑xi2，在 d=2048 上累加。bf16 只有 8 位尾数（相对精度 2−8≈0.4%）， 累加 2048 项会有明显的舍入累积，而且平方会放大动态范围。

不升 fp32 的后果是：能跑、结果看起来合理、但和 HF 对不上位。 误差在 bf16 舍入量级，逐层累积但通常不发散——所以它是最难发现的一类 bug。

本章的实现升了 fp32，所以 29 个对照点全部逐位相同。 这也说明 HF 内部同样升了 fp32——逐位相同不只验证了公式， 也验证了数值路径一致。

4. QK-Norm 只占参数量的 0.0004%，为什么漏掉会让模型完全失效？

因为它改变的是数值尺度而不是加一点偏移。RMSNorm 把 q、k 每个头归一化到 单位均方根，之后的 q·k 打分分布完全不同。

模型是在"打分已经被归一化"的前提下训练的。去掉这一步， 打分的方差会随训练学到的权重尺度自由漂移，softmax 之后可能过度尖锐或过度平坦。

一般规律：参数量与重要性无关。 判断实现是否完整不能靠 "覆盖了多少参数"，只能靠逐层数值对齐。 现代模型里这类小而关键的组件越来越多（QK-Norm、各种 gate、sink 参数）。

5. "每 token 前向 FLOP ≈ 2 × 参数量" 这条规则的误差来自哪里？

本章实测：2× 参数量 = 3,441,149,952，逐项加起来 = 3,440,902,144， 差 247,808，即 0.007%。

差额来自两处： - embedding 是 gather 不是矩阵乘，0 FLOP，但它的参数被算进了"参数量"。 （本章 tie=True，embedding 那 311M 参数在 lm_head 那里确实做了矩阵乘， 所以没有全额漏掉。） - norm 的那些小张量是逐元素乘，不是 2×。

更重要的是这条规则不含 attention 本身（QK⊤ 和 PV）。 那一项是 O(S2)，短序列可忽略、长序列会主导—— 0.2 的账本和 3.1 的推导处理的正是这一项。

所以：算权重搬运和 GEMM 用这条规则很准； 算长上下文的总计算量，必须单独加 attention 项。
