4.1

Transformer 层解剖与从零实现

用 Qwen3 权重实现前向计算，与 Hugging Face 实现逐层比较归一化、位置编码和注意力。

实测机器 crater (RTX 5090 D, sm_120) · torch 2.13.0+cu130 · Qwen3-1.7B / SmolLM3-3B-Base前置 0.0（最小模型）· 2.0（stride）· 3.3（GQA）· 4.0（权重文件）· 4.2（数值与确定性）

本章回答的三个问题

0.0 手写过一个玩具 Transformer。这一章把同样的事情做在真实权重上：直接从 .safetensors 读张量，只用 torch 的基本算子写一遍前向，然后逐层与 HuggingFace 对齐。除参数量与 FLOP 的解析模型外，全部实现写在 labs/L4/transformer_layers.py。

  1. 从 token id 到 logits，每一步的张量是什么形状、dtype 和 stride？
  2. 自写实现与 HuggingFace 参照对拍时——仅比对最终 logits 是否充分？偏离时如何精确定位到故障阶段？
  3. 带 KV cache 的增量解码与一次性 prefill 是不是同一个结果？padding、位置偏移和缓存接口各有什么坑？

心智模型：一层的十三个阶段、两种前向方式与两种位置设计

机制拆解

配置里每个数字的含义

Qwen3-1.7B 的 config.json：

hidden_size                2048          intermediate_size          6144
num_hidden_layers          28            num_attention_heads        16
num_key_value_heads        8             head_dim                   128
rms_norm_eps               1e-06         rope_theta                 1000000
vocab_size                 151936        tie_word_embeddings        True
hidden_act                 silu

三件事直接决定形状：

  • num_attention_heads / num_key_value_heads = 16 / 8 = 2：GQA 的分组数 g=2，每个 KV 头被两个 query 头共用（3.3 的账）。
  • head_dim 与 hidden_size / nq 是两个字段：这里恰好都是 128，但实现必须按 head_dim 切分。q_proj 的输出宽度是 nq × head_dim，k/v_proj 是 nkv × head_dim。
  • tie_word_embeddings=True：输出层复用 embedding 矩阵，参数量只算一份（文件里可能仍存两份，见 4.0）。

一层里的十三个阶段

对同一份权重、同一段输入，把一层的计算拆成 13 个可单独比较的阶段。前 6 个的形状与 stride：

阶段 形状 stride 说明
embed (1, 10, 2048) (20480, 2048, 1) 一次 gather，不是矩阵乘
input_layernorm (1, 10, 2048) (20480, 2048, 1) RMSNorm，内部升 fp32
q_proj (1, 10, 2048) (20480, 2048, 1) 16×128
k_proj (1, 10, 1024) (10240, 1024, 1) 8×128，只有 q 的一半
q view+transpose+q_norm (1, 16, 10, 128) (20480, 128, 2048, 1) 连续维是最后一维，transpose 没搬数据
RoPE(q) (1, 16, 10, 128) (20480, 128, 2048, 1) 逐元素乘加，不改变 stride

q 的 stride (20480, 128, 2048, 1) 是不连续的直接证据：第 0 维步长仍是 20480（10×2048），第 1 维只有 128。这也解释了为什么 attention 输出必须 transpose(1, 2).reshape(...)——reshape 在非连续张量上会隐式拷贝（2.0 讨论过）。

后 7 个阶段（attention(SDPA)、o_proj+residual、post_attention_layernorm、gate_proj、up_proj、silu(gate)*up、down_proj+residual）形状回到 (1, 10, 2048) 或 MLP 的 (1, 10, 6144)。

这 13 个阶段与 HF 的对应模块逐位相同（max|diff| 全为 0.0）。 "逐位相同"在 bf16 下是可达的：只要算子顺序、dtype 与调用路径一致，就不需要"精度不够所以差不多"这种解释。

三个容易写错的算子

RMSNorm。 HF 的实现是"升 fp32 算均方根、乘 weight、再降回原 dtype"：

xf = x.float()
var = xf.pow(2).mean(-1, keepdim=True)
return (xf * torch.rsqrt(var + eps)).to(x.dtype) * weight

三个坑：eps 加在方差上而不是标准差上；归约必须升 fp32（bf16 里累加平方和会丢精度）；weight 的形状——q_norm/k_norm 是 [head_dim]，作用在每个头内部，不是 [hidden]。

RoPE。 HF 用"前后对半"配对：rotate_half(x) = cat([-x[..., h:], x[..., :h]])，不是相邻配对。改成交错配对后首个差异出现在 RoPE(q) 阶段（12.72），而形状完全不变——只看形状发现不了。频率表也要一致：inv = 1/(base ** (arange(0, hd, 2)/hd))，再把 freqs 复制一份拼成 [S, hd]。

SwiGLU。 down_proj(silu(gate_proj(h)) * up_proj(h))：先 silu 再逐元素乘，两个投影的中间宽度都等于 intermediate_size。漏掉 silu 或写成相加都不改形状。

如何定位"第一个不同"

数值完全对齐时"首差定位"没有对象。把常见错误注入进去，这张定位表的价值就出来了：

注入的错误 首个超出 1 ulp 的阶段 差异
漏掉 QK-Norm q view+transpose+q_norm 20.61
q_proj 权重不转置 q_proj 4.851
RoPE 改成交错配对 RoPE(q) 12.72
q/k 的 norm 权重互换 q view+transpose+q_norm 445.98
RMSNorm 内部用 bf16 累加 q view+transpose+q_norm 0.125
eps 写成 0 input_layernorm 0.0078

判据是"超过该阶段 1 ulp"（2−8× 该阶段最大绝对值）。后两个变体的差异只有 0.125 与 0.0078，在最终 logits 上早就被淹没了。

KV cache：prefill 与 decode 是同一份语义的两种调用

带 cache 的实现里，k/v 每步追加成 [B, nkv, P+S, hd]。三条不变量：

  • 因果只在多 token 前向时生效。 单 token 解码看全部历史（is_causal=False），prefill 才需要因果。把 is_causal 写成"cache 是否为 None"，会让带空 cache 的 prefill 变成非因果——实测这一步就能把末位 logits 差拉到 19.8。
  • 位置来自 position_ids/cache_position，不是缓存长度。 显式传位置时，"prefill 前 P 个 token 再解码第 P 个位置"与"全序列同位置"差 0.19–0.31（bf16 形状效应）；把 position 写成 0 时差 3.875。
  • cache 有效长度等于已处理的 token 数。 46 token 的 prefill 后长度为 46，与 HF 的 DynamicCache 形状 [1, 8, 46, 128] 一致；解码一步后两边都是 47。

与 HF 的 cache 接口对拍是这一节最强的验证："prefill 45 个 token + 解码 1 个 token"这条路径上，解码 logits 与 HF 逐位相同（0.0）；同一次 prefill 的末位差 0.0625。差别只在 prefill 那一半，说明 cache 的追加与索引语义与官方实现一致。

padding 隔离：内容无关，但 NaN 例外

左 padding 到不同长度后，末位（真实 token）的 logits 与未 padding 的结果差 0.28–0.31。这不是 padding 内容的影响，而是序列长度改变后 GEMM 的归约切分变了（4.2 的同一条机制）。验证方法是把 padding 位置的 embedding 换成另一组随机值：

左 pad  1：与未 padding 差 3.125e-01；换成另一组随机 embedding 后 0.000e+00
左 pad  7：与未 padding 差 3.125e-01；换成另一组随机 embedding 后 0.000e+00
左 pad 31：与未 padding 差 2.812e-01；换成另一组随机 embedding 后 0.000e+00
右 pad 8：真实末位 logits 与未 padding 的差 1.875e-01
反例：不带 attention mask 的左 padding 7，末位 logits 差 5.336e+00

padding 的内容对有效输出逐位无影响（0.0），去掉 mask 才会让它有影响（5.34）——这是 mask 生效的直接证据。

一个例外值得单独记：把 padding 位置的 embedding 置成 NaN，有效输出也变成 NaN。加性 mask 用 −∞ 屏蔽，而 softmax 的分数是 q·k+m；NaN 参与的点积仍是 NaN，NaN + (-inf) = NaN，于是整行被污染。−∞ 掩码挡的是"看到"，挡不住"数值污染"。

位置设计的另一种选择：NoPE

SmolLM3-3B-Base 在 36 层里有 9 层不加 RoPE，模式由 config 的一个整数决定：

no_rope_layer_interval = 4
no_rope_layers[i] = int((i+1) % 4 != 0)      # 1 = 有 RoPE，0 = 无
→ 无 RoPE 的层号：3, 7, 11, 15, 19, 23, 27, 31, 35

HF 的接入点只有一行判断（modeling_smollm3.py:200 与 :222）：self.use_rope = config.no_rope_layers[layer_idx]，为真才调用 apply_rotary_pos_emb。其余结构（同样的 KV cache、同样的 MLP、同样的 norm 位置）不变。

这与 3.4 的 Qwen3.5 是两类不同的架构差异，不能混为一谈：

SmolLM3 的 NoPE 层 Qwen3.5 的线性层
改的是 位置信息来源（部分层不编码位置） 状态类型（attention → 门控递推状态）
缓存 仍是标准 KV cache，逐层形状相同 每层持有固定大小的递推状态，与序列长度无关
代价 那些层只能靠内容区分顺序 状态容量固定，长程依赖靠压缩

接入 NoPE 的改动很小：给实现加一个 no_rope_layers 列表，在 RoPE 那一步加判断。两种验证都做到了逐位相同：

  • 小模型（真实层模式 + 随机权重）：四种模式（每 4 层一次、全 RoPE、每 2 层一次、全 NoPE）逐层最大相对差 0.00e+00，final norm 也是 0.00e+00。
  • 真实 3B 权重：抽查 embedding 与第 0/1/3/4/7/11 层的隐藏状态——全部逐位相同（max|diff| = 0.0），其中第 3 层正是 NoPE 层。隐藏状态量级从 1.9 涨到 396，说明这不是"数值小所以看不出来"。

设计取舍

为什么 MLP 占 75% 的参数。 每层 attention 投影 12,583,168 个参数（25.0%），MLP 的 3×2048×6144 = 37,748,736（75.0%），每层合计 50,336,000。这个比例成立的条件是 intermediate_size ≈ 3 × hidden_size（这里 6144 = 3×2048），换个比例就变。它决定了"想压缩模型时该先动哪里"，也解释了为什么量化工作（4.3）主要盯着 MLP 权重。

为什么 QK-Norm 值得一个独立阶段。 q_norm/k_norm 各自只有 128 个参数，占整层参数量的 0.0005%，但漏掉它们会让首差出现在 norm 阶段、差异 20.61，而形状完全正常。参数量与重要性无关——判断一个算子的地位要看它对数值的影响。

为什么 cache 语义要单独验收。 prefill 与 decode 是同一个 layer 函数的不同分支；把因果标志、位置来源、cache 追加顺序搞错，都会得到"看起来能跑"的结果：token 照样一个个出来，只是与一次性 prefill 不一致。本章让两条路径在同一次运行中严格对拍，并引入 HuggingFace 的 DynamicCache 作为第三方参照——缺少独立第三方参照时，"自写 prefill 与 decode 一致"可能只是两套实现存在同构的系统性偏差。

为什么 NoPE 的代价不是"少算一点"。 去掉 RoPE 的层里，位置信息只能通过内容与残差间接获得，这等于把一部分顺序信息交给训练去学。因此接入 NoPE 的正确方式不是"删掉 RoPE 那几行"，而是按 config 的层模式精确对齐——四种模式的逐层对拍就是这件事的验收。

工程实现 · 自己写一遍

labs/L4/transformer_layers.py 用一个 Mini 类承载全部实现，权重按 HF 命名读取，因此同一份代码既能跑 Qwen3（有 QK-Norm），也能跑 SmolLM3（有 NoPE）：

class Mini:
    def __init__(self, weights, cfg, device="cuda", dtype=None):
        self.has_qk_norm = "model.layers.0.self_attn.q_norm.weight" in weights
        nrl = cfg.get("no_rope_layers")          # HF 约定：1 = 有 RoPE
        self.no_rope = ([not bool(v) for v in nrl] if nrl is not None
                        else [False] * cfg["L"])

    def layer(self, i, x, cos, sin, cache=None, mask=None, trace=None):
        h = self.rms_norm(x, self.w[p + "input_layernorm.weight"], self.eps)
        q = (h @ self.w[p + "self_attn.q_proj.weight"].T).view(B, S, nq, hd).transpose(1, 2)
        k = (h @ self.w[p + "self_attn.k_proj.weight"].T).view(B, S, nkv, hd).transpose(1, 2)
        v = (...)
        if self.has_qk_norm:                      # Qwen3 有，SmolLM3 没有
            q = self.rms_norm(q, self.w[p + "self_attn.q_norm.weight"], self.eps)
        if not self.no_rope[i]:                   # SmolLM3 每 4 层跳过
            q, k = self.apply_rope(q, cos, sin), self.apply_rope(k, cos, sin)
        if cache is not None:
            if cache[i] is not None:
                k = torch.cat([cache[i][0], k], dim=2)
                v = torch.cat([cache[i][1], v], dim=2)
            cache[i] = (k, v)
        o = F.scaled_dot_product_attention(q, k, v, is_causal=(S > 1), enable_gqa=True)
        ...

三处是"接入新模型"的最小改动面：

  1. has_qk_norm：按权重表里有没有 q_norm/k_norm 决定。少了这一步，跑 SmolLM3 会 KeyError，跑 Qwen3 会静默漏掉 QK-Norm。
  2. no_rope：按 config 的 no_rope_layers 决定哪些层跳过 RoPE。注意 HF 的语义是 1 = 有 RoPE，取反很容易搞错（本章开发过程中踩过一次，C2 的相对差立刻从 0.0 变成 7.65e-3）。
  3. cache 与 positions：cache[i] 为 None 表示这一层还没有历史；位置由显式的 positions 决定，缺省从 cache 长度推断。

位置偏移的关键代码：

def rope_tables(positions, hd, base, device, dtype):
    inv = 1.0 / (base ** (torch.arange(0, hd, 2, device=device).float() / hd))
    freqs = positions.float()[..., None] * inv[None, None, :]
    emb = torch.cat([freqs, freqs], -1)
    return emb.cos().to(dtype), emb.sin().to(dtype)

positions 是 [B, S] 的绝对位置：解码时传 [[P]]，prefill 时传 arange(P, P+S)。若用"元素序号"代替绝对位置，缓存增长后频率就会错位。

 68 # ---------------------------------------------------------------- 手写实现
 69 class Mini:
 70     """按 HF 命名读权重的最小实现：可选 QK-Norm、可选逐层 NoPE、可选 KV cache。"""
 71 
 72     def __init__(self, weights, cfg, device="cuda", dtype=None):
 73         self.w = weights
 74         self.cfg = cfg
 75         self.dev = device
 76         self.dtype = dtype or weights["model.embed_tokens.weight"].dtype
 77         self.nq, self.nkv, self.hd = cfg["nq"], cfg["nkv"], cfg["hd"]
 78         self.H, self.I, self.L = cfg["H"], cfg["I"], cfg["L"]
 79         self.eps, self.base = cfg["eps"], cfg["base"]
 80         self.has_qk_norm = "model.layers.0.self_attn.q_norm.weight" in weights
 81         # HF 约定：no_rope_layers[i] = 1 表示这一层**有** RoPE，0 表示无
 82         nrl = cfg.get("no_rope_layers")
 83         self.no_rope = ([not bool(v) for v in nrl] if nrl is not None
 84                         else [False] * self.L)
 85 
 86     # ---- 基本算子 ----
 87     @staticmethod
 88     def rms_norm(x, weight, eps):
 89         dt = x.dtype
 90         xf = x.float()
 91         var = xf.pow(2).mean(-1, keepdim=True)
 92         return (xf * torch.rsqrt(var + eps)).to(dt) * weight
 93 
 94     @staticmethod
 95     def rope_tables(positions, hd, base, device, dtype):
 96         """positions: [B, S] 绝对位置 -> cos/sin [B, S, hd]。"""
 97         inv = 1.0 / (base ** (torch.arange(0, hd, 2, device=device).float() / hd))
 98         freqs = positions.float()[..., None] * inv[None, None, :]
 99         emb = torch.cat([freqs, freqs], dim=-1)
100         return emb.cos().to(dtype), emb.sin().to(dtype)
101 
102     @staticmethod
103     def rotate_half(x):
104         h = x.shape[-1] // 2
105         return torch.cat([-x[..., h:], x[..., :h]], dim=-1)
106 
107     @classmethod
108     def apply_rope(cls, x, cos, sin):
109         # x: [B,H,S,D]  cos/sin: [B,S,D]
110         return x * cos[:, None] + cls.rotate_half(x) * sin[:, None]
111 
112     def layer(self, i, x, cos, sin, cache=None, mask=None, trace=None):
113         p = f"model.layers.{i}."
114         w = self.w
115         B, S, _ = x.shape
116         h = self.rms_norm(x, w[p + "input_layernorm.weight"].to(self.dev), self.eps)
117         q = h @ w[p + "self_attn.q_proj.weight"].to(self.dev).T
118         k = h @ w[p + "self_attn.k_proj.weight"].to(self.dev).T
119         v = h @ w[p + "self_attn.v_proj.weight"].to(self.dev).T
120         q = q.view(B, S, self.nq, self.hd).transpose(1, 2)
121         k = k.view(B, S, self.nkv, self.hd).transpose(1, 2)
122         v = v.view(B, S, self.nkv, self.hd).transpose(1, 2)
123         if self.has_qk_norm:
124             q = self.rms_norm(q, w[p + "self_attn.q_norm.weight"].to(self.dev), self.eps)
125             k = self.rms_norm(k, w[p + "self_attn.k_norm.weight"].to(self.dev), self.eps)
126         if trace is not None:
127             trace["q_pre_rope"] = q
128         if not self.no_rope[i]:
129             q = self.apply_rope(q, cos, sin)
130             k = self.apply_rope(k, cos, sin)
131         if trace is not None:
132             trace["q"] = q
133             trace["k"] = k
134             trace["v"] = v
135         if cache is not None:
136             past = cache[i]
137             if past is not None:
138                 k = torch.cat([past[0], k], dim=2)
139                 v = torch.cat([past[1], v], dim=2)
140             cache[i] = (k, v)
141         if mask is None:
142             # 因果只在多 token 前向时生效：单 token 解码（S=1）看全部历史
143             o = torch.nn.functional.scaled_dot_product_attention(
144                 q, k, v, is_causal=(S > 1), enable_gqa=True)
145         else:
146             o = torch.nn.functional.scaled_dot_product_attention(
147                 q, k, v, attn_mask=mask, enable_gqa=True)
148         o = o.transpose(1, 2).reshape(B, S, self.nq * self.hd)
149         x = x + o @ w[p + "self_attn.o_proj.weight"].to(self.dev).T
150         if trace is not None:
151             trace["attn_out"] = o
152             trace["after_attn_residual"] = x
153         h = self.rms_norm(x, w[p + "post_attention_layernorm.weight"].to(self.dev), self.eps)
154         g = h @ w[p + "mlp.gate_proj.weight"].to(self.dev).T
155         u = h @ w[p + "mlp.up_proj.weight"].to(self.dev).T
156         if trace is not None:
157             trace["gate"], trace["up"] = g, u
158         x = x + (torch.nn.functional.silu(g) * u) @ w[p + "mlp.down_proj.weight"].to(self.dev).T
159         return x
160 
161     def forward(self, ids, cache=None, positions=None, mask=None, trace=None,
162                 layers=None, final_norm=True):
163         ids = ids.to(self.dev)
164         B, S = ids.shape
165         if positions is None:
166             P = cache[0][0].shape[2] if (cache is not None and cache[0] is not None) else 0
167             positions = torch.arange(P, P + S, device=self.dev)[None].expand(B, S)
168         x = self.w["model.embed_tokens.weight"].to(self.dev)[ids]
169         cos, sin = self.rope_tables(positions, self.hd, self.base, self.dev, x.dtype)
170         n = self.L if layers is None else layers
171         for i in range(n):
172             x = self.layer(i, x, cos, sin, cache=cache, mask=mask, trace=trace)
173         if final_norm:
174             x = self.rms_norm(x, self.w["model.norm.weight"].to(self.dev), self.eps)
175         return x
176 
177     def logits(self, x):
178         head = self.w.get("lm_head.weight", self.w["model.embed_tokens.weight"])
179         return x @ head.to(self.dev).T

362     def interleaved_rope(x, cos, sin):
363         """错误变体：按相邻配对旋转，而不是 HF 的前后对半。"""

365         x2 = x[..., 1::2]

373     def pipeline(corrupt=None):

455 def _mask(B, S, P, pad_valid, device):
456     """因果 + padding 的加性 mask；pad_valid: [B, P+S] bool，True 表示有效。"""
457     import torch
458     qpos = torch.arange(P, P + S, device=device)
459     kpos = torch.arange(P + S, device=device)
460     allow = kpos[None, :] <= qpos[:, None]                 # [S, P+S]
461     m = torch.zeros(B, 1, S, P + S, device=device)
462     m.masked_fill_(~allow, float("-inf"))
463     if pad_valid is not None:
464         m = m.masked_fill(~pad_valid[:, None, None, :], float("-inf"))
465     return m

前沿

位置编码正在从"每层都有"变成"按层分配"。 SmolLM3 每 4 层去一次 RoPE，配合 5e6 的 rope_theta；这条路线与"每层都加"的 Qwen3 是两种取舍。更激进的一侧是 3.4 讲的 Qwen3.5：线性层干脆换掉 attention 状态本身（递推状态取代 KV cache）。把它们放在同一张坐标上看，位置设计与状态类型是两个独立的轴：NoPE 只动位置，线性层动状态，而 DeepStack 式的视觉特征注入（4.6）动的又是输入。本章把这些差异收敛成三个开关（has_qk_norm、no_rope、cache/positions），新模型接入时改的是开关而不是重写前向。

逐阶段对拍正在成为接入新架构的标准流程。 13 个阶段与 6 个错误变体给出了一套可复用的诊断表：先逐阶段对齐，再在错误注入下确认定位能力，最后才是端到端生成。相比"跑一条 prompt 看输出像不像"，这套流程能在 0.0078 的差异量级上定位到算子——而那个量级在最终 logits 上完全看不出来。它与 4.2 的"首差定位到层"是同一个方法在两种尺度上的应用。

KV cache 的接口开始被显式建模。 本章用 HF 的 DynamicCache 作第三方参照，验证了"prefill + 一步解码"路径上逐位相同。工程系统里这一步的价值在于：缓存语义一旦与参照不一致，长上下文（3.3）、前缀复用（5.2）、投机解码回滚（5.5）与多轮会话（9.3）都会继承同一个错误，而且很难从输出上发现。把这些语义固化成可对拍的接口，是后续几章实验的前提。

陷阱

  1. 只比最终 logits 不够。 漏掉 QK-Norm 时首差在 norm 阶段是 20.61，但 eps=0 与 bf16 累加两个变体只有 0.0078 与 0.125。
  2. head_dim 不等于 hidden_size / nq。 q_proj 的宽度是 nq × head_dim。
  3. q_norm/k_norm 作用在 head_dim 上，形状是 [128] 而不是 [2048]；顺序是 view → norm → transpose。
  4. RoPE 是前后对半配对，不是相邻配对。 交错后形状完全不变，数值差 12.72。
  5. eps 加在方差上；RMSNorm 的归约要升 fp32。
  6. 单 token 解码不能用因果 mask。 写成"cache 为 None 才因果"会让带空 cache 的 prefill 变成非因果，末位 logits 差 19.8。
  7. 位置来自 position_ids/cache_position，不是缓存长度。 写成 0 的差是 3.875。
  8. padding 的内容不影响有效输出，但 NaN 会。 加性 −∞ mask 挡不住 NaN 污染（NaN + (-inf) = NaN）。
  9. 未施加 attention mask 的 padding 会污染计算结果（误差 5.34），不可将'已传入填充 token'误认为'掩码已正确生效'。
  10. is_causal=True 与显式因果 mask 是两条路径。 数学等价，但 bf16 下不保证逐位相同（4.2 的开关一节）。
  11. HF 的 no_rope_layers 语义是 1 = 有 RoPE。 取反会让 NoPE 层与 RoPE 层互换，逐层对拍立刻暴露。
  12. interval=1 意味着全部 NoPE，不是全部 RoPE；全 RoPE 要显式给列表。
  13. rotary_emb 在 Transformers 4.45+ 挂在模型顶层，不在单个 attention 模块内部，需按当前结构寻址。
  14. 参数量占比不代表重要性。 q_norm/k_norm 只占 0.0005%，漏掉就是全错。

自测题

1. 你写的一层实现形状全对、最终 logits 也"差不多"，但逐阶段对拍在 `RoPE(q)` 阶段差 12.7。最可能是什么错？

RoPE 的配对方式错了。HF 用前后对半：rotate_half(x) = cat([-x[..., h:], x[..., :h]])；相邻配对会得到形状相同但数值完全不同的结果，实测差 12.72。

另外两种"形状对、数值错"的 RoPE 错误：频率表用错 base（Qwen3 是 1e6，SmolLM3 是 5e6），以及把 freqs 拼成 [S, hd] 时只取一半（应该复制一份）。

定位方法就是阶段表：RoPE(q) 之前（q view+transpose+q_norm）完全一致，之后开始不同，说明问题就在这一步，不必去查投影或 norm。

2. 为什么"prefill 45 个 token 再解码 1 个"与"一次性 prefill 46 个 token"的 logits 不完全相同？这是实现错误吗？

不是。两条路径的差别在 prefill 的形状：前者用 S=45 的 GEMM 与注意力，后者用 S=46。形状改变会让 cuBLAS/Triton 选择不同的 tile 与归约切分，末位结果随之变化——这就是 4.2 测到的形状不变性问题。

本章的判据是同一条路径与 HF 对拍：在"prefill 45 + 解码 1"这条路径上，解码 logits 与 HF 的 DynamicCache 逐位相同（0.0），说明缓存语义正确。跨路径的 0.0625–0.25 差异属于浮点求值顺序，不是实现错误。

要点是把"两种前向方式的一致性"与"实现正确性"分开：前者只能保证到 bf16 容差，后者可以用第三方实现验证到逐位。

3. 左 padding 的长度从 1 变到 31，末位 logits 差 0.28–0.31；把 padding 的 embedding 换成随机值后差 0.0。这两件事矛盾吗？

不矛盾，它们测的是两件事。

  • 换成随机 embedding → 0.0：说明 padding 的内容完全不参与有效输出，mask 起作用了。
  • 改 padding 长度 → 0.28–0.31：说明序列形状变了。padding 让序列变长，GEMM 与注意力的归约切分随之变化，末位不同（4.2 的机制）。

所以正确的结论是："padding 内容不影响有效输出；padding 长度通过形状影响末位，量级与任何形状变化一致。"把这两句合成"padding 无影响"，就会在需要逐位复现的场景里出错。

附带一条：去掉 mask 后两者差 5.34，这才是 padding 真正泄漏进有效输出的样子。

4. padding 位置的 embedding 置成 NaN，为什么有效输出也变成 NaN？−∞ 掩码不是挡住了吗？

挡不住。加性 mask 的语义是"在 softmax 的分数上加 −∞"，而分数本身是 q·k：

scoreij=qi·kjd+mij,mij=−∞ （被屏蔽）

如果 kj 含 NaN，qi·kj 就是 NaN，而 NaN + (-inf) = NaN，softmax 一行里出现一个 NaN 会让整行归一化失效。屏蔽的是权重，不是数值传播路径。

要真正隔离，得在计算之前处理：把 padding 位置的 k/v 置零（并把 mask 做成乘法 0），或者干脆不把 padding 送进 attention（按长度切片）。本章把这一条记录为反例，没有在实现里加特殊处理。

5. SmolLM3 的 NoPE 层与 Qwen3.5 的线性层都属于"架构差异"，为什么本章把它们分开处理？

因为它们改的是不同的东西，验证方式也不同。

  • SmolLM3 的 NoPE：只去掉部分层的位置编码，状态类型不变——仍是逐层 KV cache，形状与其他层一样。验证方式是逐层数值对拍（本章做到逐位相同）。
  • Qwen3.5 的线性层（3.4）：状态类型改变——用固定大小的门控递推状态替代 KV cache，序列压缩成状态。验证时不仅要看数值，还要看状态形状、随序列长度的增长方式、前缀复用语义（5.13 的 RecurrentGemma 实验就是这一类）。

如果把它们都当成"少算一点"的实现细节，就会漏掉后者带来的容量与状态管理问题。本章实现里的对应开关也不同：NoPE 是 no_rope 列表，线性层需要换掉整个 attention 分支与缓存结构。

6. 解析模型算出 1,720,574,976 个参数，与文件里的张量逐项相符。为什么 `tie_word_embeddings=True` 时文件里会多一份 `lm_head`？

因为 config.json 描述的是模型结构，不是文件内容。tie=True 表示前向时 lm_head 复用 embedding 矩阵，但导出脚本仍可能把权重单独写一份。本章的对照里，解析模型与"文件里实际"都是 1,720,574,976——差 0 的前提是把文件里那份冗余的 lm_head 排除掉。

这只是一种常见的打包习惯，不是规格要求：4.0 测到的 Qwen3-1.7B 就多存了 593.5 MiB（占文件 15.3%）。所以数参数量按 config，报文件大小读文件头，两者混用必然对不上。
