多模态与生成模型训练编排

把视觉、ASR、codec/TTS、扩散/视频、Omni 与 VLA 的独立基础训练接到多目标、冻结/解冻、特征缓存、异构 batch 和阶段产物。

本章回答的三个问题

  1. 视觉、语言、语音和连续生成模型怎样组成阶段训练，哪些模块真正收到梯度？
  2. 多个 loss 的监督位置、归一化分母和权重怎样共同决定一次更新？
  3. 冻结、解冻、特征缓存与 optimizer 参数组怎样保持一致？

心智模型：沿 loss 追踪参数

输入模态多，不代表训练目标多；模块参与前向，也不代表它会更新。对每个 loss，先追踪输入依赖和可微路径，再检查 requires_grad、optimizer 参数组及实际参数变化。

图中是本章 CPU 教学模型。它把三个目标放入一个可检查的系统，用于验证监督和更新契约；真实 Qwen3-VL、Cosmos、Omni 的模块组成与训练阶段需分别读源码和配方。

机制拆解与推导

三种目标，三种分母

图文因果模型先得到视觉 token，再与文本 embedding 拼接，并通过 causal self-attention 让文本位置访问视觉前缀。设 labels 中无监督位置为 -100：

LCE=−∑b,tmb,t+1logpθ(yb,t+1∣zb,≤t)∑b,tmb,t+1.

label 的 shift 必须与 logits 对齐。视觉前缀本身没有词表 target；最后一个视觉位置可以预测第一个文本 token，和语言模型的条件前缀语义一致。若只拼接后逐位置 Linear，文本位置不能读取视觉信息，即使 loss 能 backward，也没有实现图文条件学习。

连续 flow 目标用端点 x0,x1 构造：

xt=(1−t)x0+tx1,ut=x1−x0,

Lflow=∑b,f,dmb,f(vθ(xt,t,c)b,f,d−ub,f,d)2d∑b,fmb,f.

模型必须实际依赖 noisy latent、时间和条件。分母是有效坐标数，不是 batch 数；改成先对每条序列取均值再平均，会改变不等长样本的权重。

对比目标使用图像与文本的归一化表征 ai,bj，相似度 sij=aiTbj/τ：

Lcontrast=12[CE(s,arange(B))+CE(sT,arange(B))].

它按样本对聚合，与按 token 或坐标归一化的目标不同。重复样本或语义等价的“负例”会改变任务含义，扩大 batch 也不仅是改变计算量。

loss 数值不决定梯度比例

组合 L=LCE+0.5Lflow+0.1Lcontrast 时，对共享参数 θ：

∇θL=∇θLCE+0.5∇θLflow+0.1∇θLcontrast.

权重作用于梯度，loss 的数值比不能替代梯度比。例如在 θ=0，L1=3.5+0.001θ、L2=0.015+10θ，loss 之比约 233，而梯度分别为 .001 和 10。给 loss 加常数能改变值而完全不改变更新。

应分别记录共享参数与各 head 的梯度范数、方向和更新量。本章逐参数记录每项 loss 的梯度范数；权重 .5/.1 是固定实验设置，没有经任务质量调优，也没有据此证明多任务平衡最优。

冻结、无梯度与缓存

控制 参数梯度 输入梯度 前向执行 optimizer 状态
encoder 参数 requires_grad_(False) 无 输入需要梯度时仍可有 执行 未加入 optimizer 则无
encoder 在 no_grad() 中运行 无 此段图被截断 执行 不自动删除既有状态
encoder 输出 detach() 后缓存 无法经缓存回传 此路径不传回 命中缓存时不执行 解冻后仍需重新建图
解冻并添加参数组 可有 可有 执行 首次有效 step 时建立 m/v

缓存身份至少包括数据版本、processor、增强随机性、encoder revision/dtype 与布局。冻结权重只是必要条件之一；随机裁剪变化、输入梯度需求或解冻都会使旧特征不适用。只执行 requires_grad_(True) 不会自动把参数加到已建好的 optimizer。

真实架构需要不同阶段表

路线 输入融合方式 主要监督与阶段边界
OpenCLIP 式双 encoder 图像/文本各自编码，在相似度矩阵相遇 图文对比目标；两个 encoder 的更新由 recipe 决定
Qwen3-VL 视觉特征替换文本序列中的视觉占位，另有 DeepStack 特征路径 文本 CE 可经融合路径到 vision/merger，是否更新还取决于冻结配置
Flamingo 语言层中的 gated cross-attention 接入视觉特征 视觉条件与语言序列通过专门的跨注意力模块交互
Chameleon 图像经 tokenizer 成为离散 token，与文本在早期统一序列中融合 token-based early fusion，不能归入 Flamingo 的 cross-attention 路线
diffusion / flow noisy latent、t 与条件进入生成网络 噪声、速度或其它 prediction type，按配方定义 target
Qwen3-Omni AuT/vision encoder、Thinker、Talker、MTP、Code2Wav 协作 文本理解、codec 生成与波形重建具有不同模块和目标

Chameleon 原论文明确其 early-fusion token-based 设计。Qwen3-Omni 报告分别描述 Thinker/Talker MoE、Talker 的多码本预测和因果 ConvNet Code2Wav；不能因为有统一推理入口，就把它们写成一个自回归 Transformer 或声称一次文本 SFT 更新全部模块。

语音 ASR、codec、TTS 和动作模型同样先有独立训练目标。采样率、码本、动作 horizon 与 normalizer 是接口的一部分；把 LLM 的 adapter target 列表复制到这些模型，无法代替模块与目标检查。

 466     # Currently needed by Adam and AdamW
 467     def _accelerator_graph_capture_health_check(self) -> None:
 468         # Note [torch.compile x capturable]
 469         # If we are compiling, we try to take the capturable path automatically by
 470         # setting the flag to True during tracing. Due to this, we skip all the checks
 471         # normally required for determining whether we can use CUDA/XPU graphs and
 472         # shunt the responsibility to torch.inductor. This saves time during tracing
 473         # since the checks are slow without sacrificing UX since inductor will warn
 474         # later if CUDA/XPU graphs cannot be enabled, e.g.,
 475         # https://github.com/pytorch/pytorch/blob/d3ba8901d8640eb16f88b2bfef9df7fa383d4b47/torch/_inductor/compile_fx.py#L390.
 476         # Thus, when compiling, inductor will determine if cudagraphs
 477         # can be enabled based on whether there is input mutation or CPU tensors.
 478         if torch.compiler.is_compiling():
 479             return
 480 
 481         # Determine available accelerator device
 482         accelerator = torch.accelerator.current_accelerator(check_available=True)
 483 
 484         if accelerator and accelerator.type in {"cuda", "xpu"}:
 485             capturing = torch.accelerator.current_stream().is_capturing()
 486 
 487             if capturing and not all(
 488                 group["capturable"] for group in self.param_groups
 489             ):
 490                 raise RuntimeError(
 491                     f"Attempting {accelerator.type.upper()} graph capture of step() for an instance of "
 492                     + self.__class__.__name__
 493                     + " but param_groups' capturable is False."
 494                 )
 495 
 496             if (
 497                 (not getattr(self, "_warned_capturable_if_run_uncaptured", False))
 498                 and all(group["capturable"] for group in self.param_groups)
 499                 and (not capturing)
 500             ):
 501                 warnings.warn(
 502                     "This instance was constructed with capturable=True or some of all the param_groups came with capturable=True, "
 503                     f"but step() is running without {accelerator.type.upper()} graph capture. If you never intend to graph-capture this "
 504                     "instance, capturable=True can impair performance, and you should set capturable=False.",
 505                     stacklevel=2,
 506                 )
 507                 self._warned_capturable_if_run_uncaptured = True
 508

 514     def _optimizer_step_code(self) -> None:
 515         """Entry point for `torch.profile.profiler`.
 516 
 517         When python tracing is enabled the profiler will hook into this
 518         function at the CPython level to inspect the optimizer's parameters and
 519         param groups. It is called after `step()` since many optimizers
 520         lazily initialize state.
 521 
 522         This is a workaround due to lack of a proper step hook on the optimizer,
 523         and will be removed if it exists.
 524         """
 525 
 526     @staticmethod
 527     def profile_hook_step(func: Callable[_P, R]) -> Callable[_P, R]:
 528         @functools.wraps(func)
 529         def wrapper(*args: _P.args, **kwargs: _P.kwargs) -> R:
 530             self, *_ = args
 531             self = cast(Optimizer, self)
 532             profile_name = f"Optimizer.step#{self.__class__.__name__}.step"
 533             with torch.autograd.profiler.record_function(profile_name):
 534                 # call optimizer step pre hooks
 535                 for pre_hook in chain(
 536                     _global_optimizer_pre_hooks.values(),
 537                     self._optimizer_step_pre_hooks.values(),
 538                 ):
 539                     result = pre_hook(self, args, kwargs)
 540                     if result is not None:
 541                         if isinstance(result, tuple) and len(result) == 2:
 542                             args, kwargs = result  # type: ignore[assignment]
 543                         else:
 544                             raise RuntimeError(
 545                                 f"{func} must return None or a tuple of (new_args, new_kwargs), but got {result}."
 546                             )
 547 
 548                 # pyrefly: ignore [invalid-param-spec]
 549                 out = func(*args, **kwargs)
 550                 self._optimizer_step_code()
 551 
 552                 # call optimizer step post hooks
 553                 for post_hook in chain(
 554                     self._optimizer_step_post_hooks.values(),
 555                     _global_optimizer_post_hooks.values(),
 556                 ):
 557                     post_hook(self, args, kwargs)
 558 
 559                 return out
 560 
 561         return wrapper

 699     @torch._disable_dynamo
 700     def state_dict(self) -> StateDict:
 701         r"""Return the state of the optimizer as a :class:`dict`.
 702 
 703         It contains two entries:
 704 
 705         * ``state``: a Dict holding current optimization state. Its content
 706             differs between optimizer classes, but some common characteristics
 707             hold. For example, state is saved per parameter, and the parameter
 708             itself is NOT saved. ``state`` is a Dictionary mapping parameter ids
 709             to a Dict with state corresponding to each parameter.
 710         * ``param_groups``: a List containing all parameter groups where each
 711             parameter group is a Dict. Each parameter group contains metadata
 712             specific to the optimizer, such as learning rate and weight decay,
 713             as well as a List of parameter IDs of the parameters in the group.
 714             If a param group was initialized with ``named_parameters()`` the names
 715             content will also be saved in the state dict.
 716 
 717         NOTE: The parameter IDs may look like indices but they are just IDs
 718         associating state with param_group. When loading from a state_dict,
 719         the optimizer will zip the param_group ``params`` (int IDs) and the
 720         optimizer ``param_groups`` (actual ``nn.Parameter`` s) in order to
 721         match state WITHOUT additional verification.
 722 
 723         A returned state dict might look something like:
 724 
 725         .. code-block:: text
 726 
 727             {
 728                 'state': {
 729                     0: {'momentum_buffer': tensor(...), ...},
 730                     1: {'momentum_buffer': tensor(...), ...},
 731                     2: {'momentum_buffer': tensor(...), ...},
 732                     3: {'momentum_buffer': tensor(...), ...}
 733                 },
 734                 'param_groups': [
 735                     {
 736                         'lr': 0.01,
 737                         'weight_decay': 0,
 738                         ...
 739                         'params': [0]
 740                         'param_names' ['param0']  (optional)
 741                     },
 742                     {
 743                         'lr': 0.001,
 744                         'weight_decay': 0.5,
 745                         ...
 746                         'params': [1, 2, 3]
 747                         'param_names': ['param1', 'layer.weight', 'layer.bias'] (optional)
 748                     }
 749                 ]
 750             }
 751 
 752         """
 753         for pre_hook in self._optimizer_state_dict_pre_hooks.values():
 754             pre_hook(self)
 755 
 756         # Save order indices instead of Tensors
 757         param_mappings: dict[int, int] = {}
 758         start_index = 0
 759 
 760         def pack_group(group: dict[str, Any]) -> dict[str, Any]:
 761             nonlocal start_index
 762             packed = {k: v for k, v in group.items() if k != "params"}
 763             param_mappings.update(
 764                 {
 765                     id(p): i
 766                     for i, p in enumerate(group["params"], start_index)
 767                     if id(p) not in param_mappings
 768                 }
 769             )
 770             packed["params"] = [param_mappings[id(p)] for p in group["params"]]
 771             start_index += len(packed["params"])
 772             return packed
 773 
 774         param_groups = [pack_group(g) for g in self.param_groups]
 775         # Remap state to use order indices as keys
 776         packed_state = {
 777             (param_mappings[id(k)] if isinstance(k, torch.Tensor) else k): v
 778             for k, v in self.state.items()
 779         }
 780 
 781         state_dict = {
 782             "state": packed_state,
 783             "param_groups": param_groups,
 784         }
 785 
 786         for post_hook in self._optimizer_state_dict_post_hooks.values():
 787             hook_result = post_hook(self, state_dict)
 788             if hook_result is not None:
 789                 state_dict = hook_result
 790         return state_dict

 792     @staticmethod
 793     def _process_value_according_to_param_policy(
 794         param: torch.Tensor,
 795         value: torch.Tensor,
 796         param_id: int,
 797         param_groups: list[dict[str, Any]],
 798         key: str | None = None,
 799     ) -> torch.Tensor:
 800         # Floating-point types are a bit special here. They are the only ones
 801         # that are assumed to always match the type of params.
 802         # Make sure state['step'] is not casted https://github.com/pytorch/pytorch/issues/74424
 803         # UNLESS fused or capturable, see note [special device hosting for step]
 804         fused = False
 805         capturable = False

 810                 fused = pg.get("fused", False)
 811                 capturable = pg.get("capturable", False)
 812                 break
 813         if key == "step":
 814             if capturable or fused:
 815                 return value.to(dtype=torch.float32, device=param.device)
 816             else:
 817                 return value
 818         else:
 819             if param.is_floating_point():
 820                 return value.to(dtype=param.dtype, device=param.device)
 821             else:
 822                 return value.to(device=param.device)

设计取舍

共享 backbone 可以复用表征，但每个目标的 mask、归约单位与梯度方向必须显式定义。分离 head 容易隔离输出格式，独立 head 不会仅因另一项 loss 数值大就自动失去梯度。冻结和缓存减少计算，却改变梯度可达性及数据增强自由度；解冻还会新增 optimizer 状态，并可能改变分布式 bucket 和内存峰值。本章未测分布式 bucket 重建，不能用 CPU 参数组实验代替。

完整教学项目：视觉适配两阶段（7.10-J）

结构沿用 MiniMind-V 的思路：冻结视觉塔、训练 projector、把视觉 token 的 embedding 替换进语言模型序列。本实现用 CLIP ViT-B/32（224²，去掉 CLS 后 49 个 patch token，视觉塔 87.46M 参数全部冻结），projector 为 LayerNorm + Linear + GELU + Linear（1,182,720 参数，形状与 MiniMind-V 的 MMVisionProjector 一致），语言侧复用 7.5 的 SFT 权重（768/8，63.91M）。与 MiniMind-V 的差别是视觉塔换成 CLIP、视觉 token 49 个而非 64 个；与 4.6 的 Qwen3-VL 相比则少了 DeepStack 式多层注入与更深的 connector。

数据是本地合成的形状图案问答：224×224 画布上放 3–9 个红/绿/蓝的圆/方/三角，提问"图中有几个{颜色}{形状}？"。被提问的三个组合的计数固定取 {0,1,2} 的一个排列，因此每张图的三个答案恰好覆盖 0/1/2 各一次，留出集的答案分布是精确的 1/3 均分。这一条是判据能不能用的前提：如果答案集中在某个值（例如自然分布下 0 占 59.7%），"每题都答同一个数字"就能拿到接近 60% 的分数，指标测的是先验而不是计数。语料共 1,292 张图、3,000/402/402 条 train/val/test 问答，按图像内容哈希做图像级隔离。它是合成图案语料，不是公开 VQA 数据集，结论不外推到真实图像。

判据是留出问答的贪心精确匹配（取回复中第一个数字），并在同一批题上做三种图像条件：

  • normal：用自己的图；
  • shuffle：按图像整体轮换（不是把行下标平移），保证换来的图一定不同——每条样本的 3 个问答共用一张图，行平移会让 2/3 的样本拿到原图，对照失效；
  • blank：换成纯白图。

四条判读：

同一个模型的两条配方，更新对象可以完全不同。 Cosmos 的生成分支只把生成路径与两个 connector 放进优化器，Reasoner 分支不限制参数——"同一基座的 SFT"这句话不包含任何参数范围信息，必须回到 keys_to_select/freeze_filter 这类字段。

异构 batch 与缓存身份

--section hetero 把两件可算的事做成检查。第一件是分桶：64 条样本混合了 3 种分辨率、4 种帧数、3 种音频长度与 3 种动作视野，按"整批 padding 到最大"需要 909,568 token，而实际内容只有 202,568（+349% 浪费）；按 (分辨率, 帧数) 分成 12 个桶后只需 204,803（+1.1%），把 padding 浪费消掉 99.7%。第二件是缓存身份：键包含 model_revision、processor_hash、augmentation_seed、crop、time_sampling、stochastic_posterior、trainable_state 七个字段，改动其中任何一个都会换键——包括"参数已冻结但换了增强"这一情形。

前沿

Omni、视频/世界模型和 VLA 把更多条件与产物放到同一应用中，训练仍需按模块×阶段记录输入、目标、更新参数和导出依赖。Cosmos 各 SFT 配方要按选中的生成分支分析；Qwen3-Omni 的 Thinker、Talker、Code2Wav 公开程度和训练入口分别核对。尚未复现的联合训练、分布式 bucket 行为和全流程导出保持 UNVERIFIED。本章三目标小例只提供监督与梯度检查的方法。

陷阱

只打印总 loss 会隐藏分支断图和错误分母；只看 requires_grad 会漏掉未进入 optimizer 的参数；只比较 loss 数值会误判梯度竞争；只看模块出现在前向图里会夸大“全模型微调”的范围。对缓存、adapter 和阶段权重，还应检查版本、参数 key、processor 与输出格式是否共同恢复。

自测题

  1. encoder 权重冻结后，为什么 images 仍可能有梯度？
展开

参数不求梯度不等于停止整段 autograd。若输入 requires_grad=True，后续 loss 仍需要 encoder 对输入的导数。no_grad 或 detach 才会切断这条路径。

  1. 两个参数组各含同一个 Parameter，原生 AdamW 会静默更新两次吗？
展开

不会，组间重复在添加参数组时抛 ValueError。组内重复是独立情形，本章另外捕获该版本的警告/更新行为，不能混用。

  1. 图文 CE 能下降，为什么仍需改变图像再检查 logits？
展开

模型可能只靠文本路径拟合，图像根本没有影响文本输出。输入依赖检验与逐目标梯度表能发现这种结构错误；loss 下降本身不足以证明条件使用或任务质量。
