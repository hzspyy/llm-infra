蒸馏训练系统：教师信号、学生模型与产物

从数据/序列/特征/分布监督到 teacher 服务、学生更新、checkpoint 和导出，比较语言、草稿、量化、图像与语音蒸馏的完整流程。

实测机器 本地 CPU（torch 2.14.0，FP64 数值参照）· 固定源码快照 TRL cd2c5287 / SpecForge 3d64e7a6前置 7.0b（完整训练步）· 7.5（适配与偏好优化）· 5.5（草稿部署）· 4.3（量化）

本章回答的三个问题

  1. 教师提供的是文本、概率、隐藏特征还是连续场，哪些量作为条件、哪些量作为目标？
  2. CE、forward/reverse KL 与 generalized JSD 怎样定义 mask、归一化和学生梯度？两家真实实现的分母口径差在哪里？
  3. 教师特征怎样离线生产、消费和恢复；导出契约如何决定学生的部署形态？

心智模型：条件与监督分开，分母决定目标

教师特征出现在学生输入里，不代表目标就是回归这些特征。需要同时画出数据来源、模型输入、loss target 与 stop-gradient 边界。除此之外还有一个常被忽略的维度：同一个 loss 分子配上不同分母就是不同目标。

关键要点：

  • 教师信号分两类角色：作条件（hidden 特征）与作监督（token 分布、序列、场）。同一实验里两种角色可以并存，但 loss target 只有后者。
  • 分子相同、分母不同就是不同目标：EAGLE3 的 LogSoftmaxLoss 除以 B×T，DFlash 的 CE 除以权重之和，TRL 按 completion 有效位置归约。
  • 离线特征库必须先定义身份字段与 ACK 协议，否则"缓存命中"可能命中过期数据。

四种目标与解析梯度

对一个有效位置，令 p=softmax(zs/T)、q=softmax(zt/T)，教师 q 视为常量；y 为 one-hot label。未乘 T2 时：

LCE=−∑iyilogpi,∂LCE∂zs,i=pi−yiT,

LF=KL(q‖p),∂LF∂zs,i=pi−qiT,

LR=KL(p‖q),∂LR∂zs,i=piT[logpiqi−KL(p‖q)].

对 0<β<1，令 m=βq+(1−β)p：

LJ=βKL(q‖m)+(1−β)KL(p‖m),

∂LJ∂zs,i=(1−β)piT[logpimi−∑jpjlogpjmj].

所有位置再乘有效 mask 并除以有效位置数。教师 detach 使梯度只回到学生；空 mask 的 mini 返回可微零值，但训练应用还应统一处理是否推进 optimizer/scheduler。

固定 TRL API 特别规定：beta=0 选择 forward KL，beta=1 选择 reverse KL，内部值使用上面的 JSD。端点是显式分支；不能把 interior JSD 趋近端点时的零值当成它的 API 行为。

forward KL 会惩罚学生漏掉教师有概率的区域，reverse KL 对学生放在教师低概率处的质量更敏感。常说的 mode-covering/seeking 是受模型族和优化限制影响的倾向；无限表达能力下二者都在 p=q 取最小，不能直接推断某方向必然改善代码准确率或降低幻觉。

高温近似需要中心化

令 z¯=1V∑izi，在 logits 相对温度较小时：

softmax(z/T)i=1V+zi−z¯VT+O(T−2).

所以 forward KL 的梯度约为：

∂LF∂zs,i≈(zs,i−z¯s)−(zt,i−z¯t)VT2.

乘 T2 可以补偿这个高温主导尺度；它是目标权重的选择，不是所有 KD 算法的必要条件。固定温度 T=4 时，乘 T² 后梯度确实是该温度未乘版本的 16 倍，但不意味着它等于 T=1 的梯度。本机 FP64 实测三种梯度范数为 0.8320819、0.0694284、1.1108544。

若学生 logits 与教师只差常数，softmax 完全相同，KL 梯度应为零；缺少均值项的公式会在这个最小反例上失败（实测残差 4.5e-15 与 9.1e-15，与数值零一致）。

分母口径：同一分子配不同分母

三家实现的分母各不相同，这是"看起来都在做 KL/CE"却得到不同训练目标的直接原因：

实现 分子 分母 结果
EAGLE3 LogSoftmaxLoss ∑vqv(log∑jezj−zv)，乘位置 mask B×T 全部行数 被 mask 的位置仍占分母
DFlash loss_type=dflash ∑CEi·wi·e−(pi−1)+/γ ∑wi（权重之和） 有效位置决定尺度，衰减改变权重
TRL DistillationTrainer 分块 JSD/KL，按有效 completion 位置求和 completion 有效计数（含 DDP 补偿） 生成长度变化会改变尺度

本机用同一批 FP64 logits/target 直接比较前两家：把一半位置 mask 掉后，DFlash 口径与 EAGLE3 口径的比值恰为 2.0（分母分别是 4 与 8）。这不是谁"错"，而是两家定义的目标不同；跨库迁移必须换成对方的分母，否则等价于改学习率。

DFlash 的块 mask 与位置衰减

DFlash 一次前向预测整个 block：Q 有 N×block_size 行，KV 由 S 个 context 槽加 N×block_size 个 draft 槽组成。按 create_dflash_block_mask（dflash_family_model.py:234）的语义：

  • context：kv_idx < S 且严格小于该 block 的 anchor 位置（inference 时 anchor 位本身不可见）；给了 sliding_window 时再加下界 anchor + q_offset - (window-1)；
  • draft：kv_idx >= S、与该 query 同一 block，且（有窗口时）kv_block_offset <= q_offset；
  • 整行再乘 block_keep_mask[b, block_id]，无效块全屏蔽。

逐位置 loss 用 draft logits 对 target token 的 CE，按 w = mask × exp(-(pos-1)_+/γ) 加权（dflash_family_model.py:723-746）。本机小例取 γ=2、block=4：块内权重为 [1.0, 1.0, 0.6065, 0.3679]，平均权重 0.7436，带衰减的 loss 2.6154 与不衰减的 2.6551 不同——衰减改的是目标权重，不是数值噪声。

acceptance rate 与 LK 变体

SpecForge 的 acceptance 定义是逐 token 的期望接受率 ∑vmin(ptarget,v,pdraft,v)，再对有效位置取 masked mean；log_acceptance_rate 对严格大于 0 的位置取对数后同样取均值。三种 LK 目标（lk_loss.py:83）：

  • alpha：−logacc―
  • tv：1−acc―
  • lambda：w·KL+(1−w)·(1−acc―)，w=kl\_scale·e−kl\_decay·acc―.detach()

本机小例的接受率 0.4491、w=0.6382，四种目标的梯度范数分别为 0.2932（纯 KL）、0.2059（alpha）、0.0956（tv）、0.2069（lambda）。把 acceptance 当"评估指标"而把 LK 当"loss 正则"都低估了差别：它们改变的是被优化的目标本身。

设计取舍

在线学生生成让教师监督学生会访问的上下文，但不会"彻底消除"分布偏差，也增加生成与教师前向成本。分块词表投影省峰值缓冲，checkpointing 用重计算换内存；离线特征可减少重复教师前向，却需要严格缓存身份、存储带宽与 ACK 协议。分母、衰减、mask 和损失方向改变的是目标，不能当成任意可互换的性能开关。

109 # [B] EAGLE3 LogSoftmaxLoss

111 def eagle3_logsoftmax_loss(block_logits: torch.Tensor, teacher_probs: torch.Tensor,
112                            position_mask: torch.Tensor) -> torch.Tensor:
113     """按 SpecForge `LogSoftmaxLoss`：逐行按教师分布加权，最后对 B×T 行取 mean。"""
114     logsumexp = torch.logsumexp(block_logits, dim=-1, keepdim=True)
115     per_token = (teacher_probs * (logsumexp - block_logits)).sum(dim=-1)
116     masked = per_token * position_mask
117     return masked.mean()

120 def eagle3_reference_autograd(block_logits, teacher_probs, position_mask):
121     """用 PyTorch 自身算子写同一函数，用于梯度对拍。"""
122     log_prob = F.log_softmax(block_logits, dim=-1)
123     per_token = -(teacher_probs * log_prob).sum(dim=-1)
124     return (per_token * position_mask).mean()

127 def check_eagle3_objective() -> dict:
128     b, t, v = 2, 3, 4
129     logits = torch.randn(b, t, v, dtype=DTYPE, generator=torch.Generator().manual_seed(7)).requires_grad_()
130     teacher_logits = torch.randn(b, t, v, dtype=DTYPE, generator=torch.Generator().manual_seed(11))
131     teacher_probs = F.softmax(teacher_logits, dim=-1)
132     mask = torch.tensor([[0.0, 1.0, 1.0], [0.0, 0.0, 1.0]], dtype=DTYPE)
133 
134     value = eagle3_logsoftmax_loss(logits, teacher_probs, mask)
135     value.backward()
136     grad_mine = logits.grad.clone()
137 
138     logits2 = logits.detach().clone().requires_grad_()
139     ref = eagle3_reference_autograd(logits2, teacher_probs, mask)
140     ref.backward()
141 
142     # 分母口径：屏蔽位置仍然进入 B×T 分母
143     dense_mask = torch.ones_like(mask)
144     value_dense = eagle3_logsoftmax_loss(logits.detach(), teacher_probs, dense_mask)
145     value_sparse = eagle3_logsoftmax_loss(logits.detach(), teacher_probs, mask)
146     unchanged_masked_positions = value_sparse / value_dense  # 3/6 位置有效时 loss 约为一半
147 
148     # forward KL 与教师熵的关系：L_row = KL(q||p) + H(q)
149     log_prob = F.log_softmax(logits.detach(), dim=-1)
150     kl = (teacher_probs * (torch.log(teacher_probs.clamp_min(1e-300)) - log_prob)).sum(dim=-1)
151     entropy = -(teacher_probs * torch.log(teacher_probs.clamp_min(1e-300))).sum(dim=-1)
152     per_row = (torch.logsumexp(logits.detach(), dim=-1, keepdim=True) - logits.detach())
153     loss_row = (teacher_probs * per_row).sum(dim=-1)
154     kl_gap = float((loss_row - (kl + entropy)).abs().max())
155 
156     # 平移不变性：给所有 logits 加常数不改变 loss 或梯度
157     shifted = logits.detach() + 5.0
158     shifted_value = eagle3_logsoftmax_loss(shifted, teacher_probs, mask)
159 
160     return {
161         "value": value.detach().item(),
162         "grad_max_abs_diff_vs_autograd": float((grad_mine - logits2.grad).abs().max()),
163         "half_masked_over_dense_loss_ratio": float(unchanged_masked_positions),
164         "row_equals_KL_plus_teacher_entropy_max_gap": kl_gap,
165         "shift_invariance_gap": abs(float(shifted_value) - float(value_sparse)),
166         "numerator_weight_of_valid_rows": float(mask.sum() / mask.numel()),
167     }

170 # ---------------------------------------------------------------------------
171 # [C] acceptance rate 与 LK 变体
172 # ---------------------------------------------------------------------------
173 def acceptance_rate(draft_logits, target_probs_on_draft, position_mask, eps=1e-8):
174     draft_p = F.softmax(draft_logits, dim=-1)
175     per_token = torch.minimum(target_probs_on_draft, draft_p).sum(dim=-1)
176     m = position_mask
177     acc = (per_token * m).sum() / m.sum().clamp_min(eps)
178     log_per_token = torch.where(per_token > 0, torch.log(per_token.clamp_min(eps)), torch.zeros_like(per_token))
179     log_acc = (log_per_token * m).sum() / m.sum().clamp_min(eps)
180     return acc, log_acc

207 # [D] DFlash per-position CE
208 # ---------------------------------------------------------------------------
209 def dflash_ce(lm_logits, target_ids, weight_mask, block_size, gamma=None):
210     ce = F.cross_entropy(lm_logits.reshape(-1, lm_logits.shape[-1]),
211                          target_ids.reshape(-1), reduction="none").reshape_as(target_ids)
212     weights = weight_mask
213     if gamma is not None and gamma > 0:
214         positions = torch.arange(block_size, dtype=weights.dtype).view(1, 1, -1)
215         decay = torch.exp(-(positions - 1).clamp(min=0) / gamma)
216         weights = weights * decay
217     return (ce * weights).sum() / weights.sum(), ce, weights

264 # ---------------------------------------------------------------------------
265 # [E] compact teacher 的分块 logsumexp/argmax
266 # ---------------------------------------------------------------------------
267 def tiled_logsumexp_argmax(hidden, weight, chunk_size):
268     running_max = None
269     running_sum = None
270     argmax_index = None
271     for start in range(0, weight.shape[0], chunk_size):
272         chunk = F.linear(hidden, weight[start:start + chunk_size]).float()
273         chunk_max = chunk.max(dim=-1, keepdim=True).values
274         if running_max is None:
275             running_max = chunk_max
276             running_sum = torch.exp(chunk - chunk_max).sum(dim=-1, keepdim=True)
277             argmax_index = chunk.argmax(dim=-1) + start
278         else:
279             new_max = torch.maximum(running_max, chunk_max)
280             running_sum = (running_sum * torch.exp(running_max - new_max)
281                            + torch.exp(chunk - new_max).sum(dim=-1, keepdim=True))
282             chunk_argmax = chunk.argmax(dim=-1) + start
283             better = chunk_max.squeeze(-1) > running_max.squeeze(-1)
284             argmax_index = torch.where(better, chunk_argmax, argmax_index)
285             running_max = new_max
286     return torch.log(running_sum.squeeze(-1)) + running_max.squeeze(-1), argmax_index

前沿

  • 草稿训练目标分家。EAGLE3 把多层教师特征当条件、用 token 分布监督；DFlash/DFlash2 走块并行预测并按位置衰减加权。两者的 mask、分母和导出契约都不同，SpecForge 也明确 --to sglang 只覆盖 EAGLE3 的 key 契约，其余走 --to hf。收益最终要计入 target 验证、接受长度与完整请求成本，而不是只报"草稿几倍加速"。
  • 在线蒸馏 API 的分化。TRL 的 DistillationTrainer 与 experimental GKD 在采样、loss 与数据流上不同，升级要按真实入口迁移，不能只改类名。
  • 连续场与语音蒸馏。LCM、DMD2、ZipVoice 面对不同的场、状态与评估对象；ModelOpt 的 QAD 是量化路径下的质量恢复，不等于领域适配。本章未执行这些训练与导出，相关规模与质量结论保持 UNVERIFIED。

陷阱

  • 分母不是细节。同一分子换成另一家的分母，等价于改学习率；本机实测两家差 2.0 倍（一半位置有效时）。
  • mask 的位置。EAGLE3 的 LogSoftmaxLoss 把 mask 放在分子、分母仍是 B×T；DFlash 的分母是权重之和。把两者混用会在长序列/稀疏监督下产生系统性尺度漂移。
  • 不同 tokenizer 的同一 logit 下标未必是同一个 token，不同切分下的序列位置也不对齐。跨词表需显式概率映射、序列级监督或其它经过验证的目标，不能直接逐元素 KL。
  • 特征缓存的身份。teacher revision、模板、token 切分、层号或 dtype 任一变化都会让离线记录失效；本章特征库对四类不符各拒绝 24/24 条，说明校验必须逐字段。
  • ACK 之前都算未提交。消费者崩溃后从 ACK 日志继续，重放未 ACK 的队尾；把"文件已写"当"消费已完成"会重复计数。
  • 温度、T² 与中心化。温度改变概率形状，T² 只改变固定温度下的权重；高温近似必须减去各自均值，否则常数平移会产生非零梯度。

自测题

  1. 学生与教师 logits 相差常数时，高温公式为什么要减去各自均值？

details 答案

softmax 对常数平移不变，概率和 KL 梯度应相同。中心化后两组 logits 的差为零；省略均值会错误产生非零梯度（本机反例残差 4.5e-15 与 9.1e-15，与数值零一致）。

  1. 固定 TRL 的 beta=.3 与 beta=0 分别是什么目标？

details 答案

内部 .3 使用 generalized JSD，mixture=.3q+.7p；端点 0 显式选择 forward KL。该 API 的端点不是直接把内部 JSD 公式代入得到的零。

  1. EAGLE3 输入了教师 hidden states，为什么不能说它做 hidden-MSE？

details 答案

输入条件与 loss target 不同。固定 SpecForge 路径将 draft logits 与教师 token 分布比较（LogSoftmaxLoss，分母 B×T），并可选择接受率相关的 LK 分支；hidden states 是条件，不是该路径中的 MSE 回归目标。

  1. 同一批 logits 分别用 EAGLE3 与 DFlash 的口径计算，为什么数值会差 2 倍？

details 答案

EAGLE3 的分母是全部 B×T 行，被 mask 的位置仍占分母；DFlash 的分母是加权 mask 的和。一半位置有效时分母分别是 8 与 4，比值恰为 2.0。迁移实现时必须换成目标库的分母。

  1. 特征库为什么需要 ACK，而不是写完文件就算缓存可用？

details 答案

写文件只表示生产者完成；消费者可能读到一半崩溃。ACK 日志是"已消费"的唯一凭据，重启后未 ACK 的记录会被重放。本机崩溃测试：第 5 条退出后重启，处理 19 条补齐 24 条，重复 0。
