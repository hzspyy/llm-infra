7.9

优化器、混合精度与训练数值稳定性

理解 AdamW/调度/EMA、参数和优化器状态、FP16/BF16/scaler、FP8/MXFP8/NVFP4 的缩放与反向计算，以及训练数值故障诊断。

"混合精度"这个词把太多互相独立的选择塞进了一个开关。参数用什么 dtype 存、乘法输入截到几位尾数、累加器多宽、反向保存什么、梯度归约用什么精度、m/v 存在哪、最后写回参数时还剩多少有效位——这是六件事，每一件由不同的代码决定。

这一章沿着一次更新把这六件事逐个打开：先用真实张量建立状态账，再把误差落到前向、dX、dW、参数写回四个位置，最后进到 FP8/FP4 的 scale 与三类 GEMM，收尾是一套能把故障定位到具体层和具体张量的记录。

判据只有一条：每个数字都要能指回一个打印出来的 tensor.dtype、一段源码或一次实测读数。

本章回答的三个问题

  1. 一次 AdamW 更新维护哪些状态，它们的 dtype 由谁决定，每参数到底多少字节？
  2. autocast、参数 dtype、累加精度和梯度归约分别管住哪一段，误差在四个位置各有多大？
  3. FP8/FP4 的 scale 怎么定、为什么转置要重新量化、故障怎样从 loss 收敛到一个具体张量？

心智模型：一条链上的六个 dtype 决策点

把一次更新画成一条链，每个环节问同一个问题：这里的 dtype 是谁写的？

机制拆解与推导

AdamW 的状态：公式之外还有 dtype 与 step 计数

一次更新的数学在 7.0b 已经推过，这里只补状态侧的三件事。

m/v 的 dtype 跟随参数。 PyTorch 用 zeros_like(p) 建立 exp_avg 与 exp_avg_sq，参数是 BF16，m/v 就是 BF16。"Adam 的二阶矩必须 FP32"不是数学要求，而是某些配方的选择。

step 是一个张量，且默认留在 CPU。 非 fused/capturable 时它是 torch.tensor(0.0, dtype=float32, device="cpu")。它是 checkpoint 里必须保存的状态，不是一个可以随手重算的 Python 整数。

两种 weight decay 在第一步就分叉。 Adam 的 L2 把 λθ 加进梯度再过自适应归一化，AdamW 直接对参数乘 1−ηλ。同一组超参数下，一维参照跑三步后 Adam(L2)=0.805443628098241，AdamW=0.804083444128180，差 1.36e-3。

真实配方的字段能对上这套状态。SmolLM3 stage1 的 optimizer 段：name: adamW、adam_beta1/2: 0.9/0.95、adam_eps: 1.0e-08、weight_decay: 0.1、clip_grad: 1.0、torch_adam_is_fused: true，外加一行容易被跳过的 accumulate_grad_in_fp32: true——模型 dtype: bfloat16，但梯度累加在 FP32。

weight_decay_exclude_named_params 只排除了 .*token_embedding.*。"norm 和 bias 一律不衰减"是常见做法，不是这份配方的写法；参数组的划分要按实际配置读，不能按习惯假设。

学习率的时钟与 EMA 的 dtype

调度器的形状（warmup+cosine 还是 WSD）和它的时钟是两件事。SmolLM3 stage1 的 lr_decay_starting_step: 4198001、lr_decay_steps: 522000、lr_decay_style: linear 是典型的 WSD：稳定段可以先跑着，之后再决定从哪一步进入衰减；cosine 则必须在开始前就知道总步数。

时钟走在有效更新上，不是尝试次数，也不是 microbatch 数。accumulation=4 时若按 microbatch 推进，2000 步的 warmup 会在 500 次真实更新内跑完，整条曲线被压缩到 1/4 的训练量里。跳步同理：100 次尝试跳了 7 次，两种计法的曲线就再也对不上。

EMA 是第三份权重，在 optimizer.step() 之后更新。它的缓冲区 dtype 需要和 decay、参数量级一起判断。参数固定在 FP32 每步下降 1e-3、EMA 用 decay=0.999 时：

step 1 100 500 1000 1500 2000
参数 +0.999000 +0.900001 +0.500006 +0.000009 −0.499988 −0.999981
FP32 EMA +0.999999 +0.995114 +0.893233 +0.631683 +0.276273 −0.136050
BF16 EMA +1.000000 +1.000000 +1.000000 +1.000000 +1.000000 +0.953125

BF16 缓冲区前一千多步完全没动：每步增量是 0.001×(p−ema)，在 1.0 附近小于 BF16 的半 ULP（2−9≈1.95×10−3），整步被舍掉，直到差值拉开到约 2 才开始移动。F5-TTS 这类依赖 EMA 权重做推理的配方，EMA 的精度直接决定最终产物。

舍入吸收、下溢与长归约是三件事

先把间距摆出来。1.0 是指数区间边界，下侧间距是上侧的一半：

dtype 1 以下间距 1 以上间距 最小正规数 最小正次正规数 max
FP32 5.96e-08 1.19e-07 1.18e-38 1.40e-45 3.40e+38
FP16 4.88e-04 9.77e-04 6.10e-05 5.96e-08 6.55e+04
BF16 3.91e-03 7.81e-03 1.18e-38 9.18e-41 3.39e+38
E4M3 6.25e-02 1.25e-01 1.56e-02 1.95e-03 4.48e+02
E5M2 1.25e-01 2.50e-01 6.10e-05 1.53e-05 5.73e+04

于是 p=1.0 时一次更新能不能落地，只看相对更新量：BF16 下 delta=3.9e-3 使参数变成 0.99609375，delta=1e-3 则原地不动。这跟梯度有没有下溢无关，是写回时的舍入吸收。反过来，FP16 的 1e-5、1e-7 落在次正规区仍是非零值，"小于最小正规数就等于零"也不成立。

长归约是另一回事。100 万个 1e-2 量级的数求和，FP64 参照 −8.145245141823：

dtype torch.sum（分块成对） 分块顺序累加 sum(dtype=fp32)
FP32 1.8e-07 3.0e-07 1.8e-07
BF16 2.5e-03 1.3e-02 1.6e-03

BF16 一行里 1.6e-03 已经来自输入本身的表示误差，换更宽的累加器只能把剩下的顺序误差压回去。这解释了为什么 loss、归一化统计量和梯度归约都要单独指定累加精度——以及为什么同一份数据换个归约顺序结果就会变。

autocast 管算子，不管参数

实测 16 个算子在 autocast 下的输出 dtype，CPU（BF16）与 CUDA（BF16/FP16）给出同一张表：linear/matmul/bmm/conv1d/scaled_dot_product_attention 降到低精度，softmax/log_softmax/layer_norm/cross_entropy/sum/mean/exp/pow/rsqrt/silu 留在 FP32，add(fp32,fp32) 输出 FP32。

分界线是"这个算子是不是由长归约的乘加主导"。GEMM 的误差随 K 增长但被累加器兜住，softmax 与 CE 里的 exp/log 会把输入误差放大成概率误差。

误差落在四个位置，量级并不相同。256 维三层 MLP、同一份 FP64 初值、相对 FP64 参照：

配置 前向 dX dW 参数更新 更新符号翻转
FP32 4.9e-07 9.6e-07 5.7e-07 1.5e-02 0.00%
FP32 + autocast BF16 3.3e-03 6.1e-03 5.2e-03 1.99 0.18%
BF16 参数与计算 3.6e-03 8.9e-03 6.9e-03 2.21 0.23%

前三列逐级放大，量级与输入 dtype 一致。最后一列是 AdamW 首步的性质：更新量约等于 ±η，与梯度大小无关，靠近零的分量只要符号被扰动，整个更新就换方向。判断数值是否可用要看 dW；参数变化看起来正常也不能反推梯度是准的。

TF32 是同一个故事的另一面。sm_120 上 1024³ 的 FP32 matmul，三种精度模式的实测 SQNR：

set_float32_matmul_precision highest high medium BF16 输入对照
SQNR (dB) 131.52 70.63 70.63 50.82

张量全程以 FP32 存储和读写，变的只是送进乘法器的尾数位数。TF32 不是一种权重格式。

损失缩放：一个窗口内的常数

FP16 的指数范围装不下整条梯度分布，所以把 loss 乘上 s，让 ∇(sL)=s∇L 整体搬进可表示区间，反向结束后再除回来。scale 取 2 的幂，乘除只改指数、不引入额外舍入。

实测的两端：真实梯度 1e-9、1e-12 直接转 FP16 是 0，乘 216 后分别是 6.56e-05 和 5.96e-08，unscale 回来仍是非零；另一端，梯度 2.0 乘 216 就越过 65504 变成 Inf。scale 太小丢梯度，太大丢一整步。

次序不能换。官方 GradScaler 的六次尝试（正常、Inf、正常、NaN、正常、正常，growth_interval=2）：

尝试 进入时 scale 注入 found_inf 参数是否变 step 返回 update 后 scale 有效更新数
1 65536 − False True None 65536 1
2 65536 Inf True False None 32768 1
3 32768 − False True None 32768 2
4 32768 NaN True False None 16384 2
5 16384 − False True None 16384 3
6 16384 − False True None 32768 4

成功与跳步都返回 None，返回值不能当成功标志。三个反例的实测后果：

  • clip 早于 unscale：缩放梯度的范数 42153.730，按 max_norm=1.0 裁剪再 unscale，真实梯度范数只剩 1.53e-05，阈值被缩小了四万倍。
  • 累积窗口内改 scale：两份 microbatch 分别按 65536 与 131072 缩放后累加，只能用一个数还原，梯度最大相对偏差 0.250——第一份的贡献被砍掉一半。
  • 跳步仍推进 scheduler：100 次尝试跳 7 次，LR 曲线整体错位，两份日志不可比。

BF16 通常不需要 scaler，但不等于不会溢出：1e20 的 BF16 矩阵自乘直接得到 inf。finite 检查与首个坏张量定位不能因为换了 dtype 就省掉。

FP8：scale 是算出来的，粒度是设计出来的

一个张量要进 FP8，先算 scale。torchao 的公式是 finfo(fp8).max / clamp(amax, 1e-12)，rowwise recipe 还会把 scale 向下取到 2 的幂。

粒度决定一个离群点能污染多大范围。128×256 的张量、主体 N(0,1)、两个 ±40/±32 的离群点：

方案 scale 个数 SQNR (dB)
per-tensor E4M3 1 31.85
per-tensor E5M2 1 25.72
rowwise E4M3（沿最后一维） 128 31.81
MXFP8 block=32 1024 30.84
NVFP4 block=16（单级 / 两级） 2048 20.39

E5M2 在同一份数据上比 E4M3 差 6 dB：多出来的指数位换走了两位尾数，而 per-tensor scale 已经把动态范围问题解决了。NVFP4 低一个档次是格式本身的代价，4 位换不回来。

两级 scale 什么时候才有用。 上表里单级与两级完全相同，因为所有块 scale 都落在 E4M3 的表示范围内。把块 amax 拉开到 8 个数量级之后，单级 SQNR 3.23 dB，两级 20.41 dB：块 scale 本身要存进 E4M3（最大 448、最小次正规 1.95e-3），超范围的块整体失真；两级先除以一个 per-tensor FP32 再存，等于把 E4M3 的窗口搬到合适的位置。

MX 的 scale 只取 2 的幂。 torchao 的 FLOOR 模式取 X=2⌊log2(amax)⌋−8，其中 8 是 E4M3 能表示的最大 2 的幂（256，不是 448）。实测第 0 块 amax=40，缩放后块内最大值 320，只用到 E4M3 上限的 71.4%。RCEIL 模式能提高利用率，代价是块内最大值可能需要饱和处理。

转置为什么要重新量化。 这件事的条件比"块缩放不随转置保持"更精确：

  • rowwise + 2 的幂 scale：沿最后一维与沿第 0 维量化，结果不同的元素占 0.00%。乘 2 的幂只改指数，浮点目标格式的舍入网格是相对的。
  • rowwise + 非 2 的幂 scale（tensorwise recipe 的默认）：不同元素占 99.1%。缩放本身引入舍入，分组一变整张网格都变。
  • MXFP8 block=32：不同元素占 1.03%，最大差 0.25。块成员变了，块 amax 跟着变，掉出窗口两端（饱和或落进次正规与零）的元素就会改变。

代价虽小但真实存在，而且 tensor core 要求数据沿归约维连续，前向与反向的归约维不同——所以同一个张量必须有两份量化结果。Transformer Engine 的做法是从同一份高精度输入直接产出正反两份，避免"对量化结果再量化"：实测二次量化后 SQNR 32.70 dB，直接从原张量量化 32.26 dB，两者相差不大但引入的误差方向不同，逐层累积起来就不能忽略。

三类 GEMM，三套量化轴

对 Y=XW⊤，一次训练要算三个矩阵乘，每个的归约维都不一样：

GEMM 左操作数 右操作数 torchao rowwise 的量化轴
Y=XW⊤ input weight input 沿 −1，weight 沿 0
dX=dYW grad_output weight grad_output 沿 −1，weight 沿 −1
dW=dY⊤X grad_output input grad_output 沿 0，input 沿 0

同一个 weight 在前向沿 dim 0、在 dX 沿 dim −1，必须量化两次。CPU 参照上三个 GEMM 的 SQNR 分别是 28.61 / 28.60 / 28.54 dB，把 dW 换成 BF16 走高精度则是 52.55 dB——这正是 ROWWISE_WITH_GW_HP 配方的取舍：三个 GEMM 里最直接影响权重更新的那个留在高精度。

累加器宽度是第三个独立维度。同一批 FP8 操作数按 32 元素分块累加：常规量级下 FP32 与 FP16 累加器的 SQNR 都是 28.6 dB，量化噪声完全盖过累加噪声；把输入放大 150 倍后，部分和越过 65504，FP16 累加器产生 456 个 Inf。低精度累加的风险在动态范围，不在有效位数。

随机舍入与 Hadamard

E2M1 只有 8 个非负取值 [0, 0.5, 1, 1.5, 2, 3, 4, 6]。把 1.2 量化 4096 次，最近邻永远给 1.0，均值偏差 −0.2；随机舍入按距离反比选择两个邻居，均值 1.205933。把同一个梯度量化后累加 200 次，最近邻的相对偏差是 −16.67%，随机舍入是 +0.83%。偏差不随步数平均掉，它是确定性的方向误差；随机舍入把它换成方差。TE 的 NVFP4 配方只对梯度用随机舍入，权重与激活仍用最近邻。

随机 Hadamard 变换针对的是另一个问题：块内的尖峰。16×16 正交变换后 (XH)(WH)⊤=XW⊤，所以它可以免费抵消。实测块内"最大/中位数"之比从 9.6 降到 3.2，被量化成零的非零元素从 582/4096 降到 141/4096。但按能量计的 SQNR 反而从 22.15 dB 降到 18.81 dB，逐分位看清楚了原因：

元素分位 最小 50% 50–90% 90–99% 最大 1%
平均相对误差（直接） 0.354 0.167 0.098 0.022
平均相对误差（Hadamard） 1.575 0.142 0.073 0.035

变换把误差从"少数元素被压成零"摊成"所有元素都带一点噪声"。小元素的相对误差因此变差，而 SQNR 这种能量口径本来就由大元素主导。选什么判据决定这个变换是赚是赔；TE 把它放在 weight 梯度这条路径上，依据是 NVFP4 预训练配方的端到端质量，不是某个合成张量的 SQNR。

按训练方法分列的状态与风险

同一套精度机制作用在不同训练方法上，常驻状态和风险点并不一样。以 Linear(1024,1024) 的 1,048,576 个基座参数、LoRA rank=16 为口径：

方法 可训练参数 合计 MiB 字节/基座参数 常驻构成

五行分别对应四个不同的层：

  • 前向溢出在第 9 层。激活最大值沿深度从 81.5 累乘到 6.49e4 越过 FP16 上限，溢出点由层号决定，只看最终 loss 无法区分第 9 层和第 8 层。
  • 梯度下溢最危险：loss 与正常尝试完全相同，finite 检查通过，optimizer 也执行了 step，唯一的信号是梯度范数为 0、零元素比例 1.000。
  • 坏样本的第一个非有限张量出现在第 0 层，沿输入回溯能定位到 batch 内第 2 条样本。
  • 空分母的 loss 是 0/0，但梯度全为 0、finite 通过、optimizer 照常执行；这一步参数仍然变了，update/weight = 1.000e-04，正好是 ηλ 的 decoupled 衰减。

所以顺序是固定的：先看有效 target 计数，再看输入，然后才是前向、反向、归约和 optimizer。顺序反了会在模型里白找一圈。

三件事写在同一段里：nn.Linear 任一维不是 16 的倍数一律跳过（硬件要求）；filter_fqns 支持手工排除，也支持 auto_filter_small_kn 按 (K,N) 自动跳过小层；能力门槛是 SM89 或 gfx942，否则只能 emulate。MXFP8 与 NVFP4 两个 converter 则要求 has_cuda_capability(10, 0)，并且 NVFP4 的文档里明确建议把 LM head 留在 BF16。

MXFP8 converter 还多一个选项 linears_saving_inputs_for_backward_in_mxfp8：一个 linear 可以保存 BF16 输入，也可以保存 columnwise MXFP8 输入。前者省一次反向量化但占更多激活内存，后者相反；而且这个选择与 activation checkpointing 策略耦合——被 checkpoint 的层在原始前向和重算时都会产出 columnwise MXFP8，尽管第一份会被丢弃。上游把 BF16 设成保守默认，把选择权交给用户。

float8.md 还有一句和分布式直接相关：rowwise scaling 下所有分布式通信都在高精度进行。tensorwise 才有 enable_fsdp_float8_all_gather（用 tensor subclass 在 all-gather 前后做转换）这条路。

设计取舍

autocast vs 模块级混合精度。 autocast 按算子查表，不动参数，改动小、行为局部，代价是每个算子边界都可能插入 cast。FSDP2 的 policy 在模块边界转换，能与通信和分片生命周期合并，但粒度更粗，一个模块内部无法再分。两者可以叠加，出问题时要先确认某个张量的 dtype 是谁决定的。

FP32 master 换什么。 显式 BF16 参数把每参数常驻状态从 16 字节降到 8 字节，代价是写回精度：小于半 ULP 的更新整步消失。加回 FP32 master 就把省下的容量还回去（实测同样 16 字节/参数），换的是"低精度计算 + 高精度累积更新"。这不是一个可以只看显存曲线决定的选项。

FP8 的收益边界。 sm_120 上 4096³ 的 GEMM，BF16 219.1 TFLOP/s、FP8 tensorwise 528.0、FP8 rowwise 408.4；换到 1024³ 分别是 146.8 / 262.6 / 201.6。但把一个张量量化成 rowwise FP8 这一步，1024 档要 0.0414 ms，而整个 FP8 GEMM 只要 0.0082 ms——未融合的 eager 实现里 amax、log2、floor、乘法、cast 各是一次 kernel，小尺寸下全是启动开销。上游把 torch.compile 列为 float8 训练的前提，正是要把这些 cast 融进相邻算子；auto_filter_small_kn 按 (K,N) 跳过小 linear 也是同一个原因。

粒度越细越好吗。 细粒度 scale 换来抗离群点能力，代价是 scale 本身的字节与 kernel 复杂度：

287 def stochastic_round_e2m1(x: torch.Tensor, gen: torch.Generator) -> torch.Tensor:
288     levels = E2M1_LEVELS
289     sign, mag = torch.sign(x), x.abs().clamp(max=F4_MAX)
290     idx = torch.bucketize(mag, levels)
291     lo = levels[(idx - 1).clamp(min=0)]
292     hi = levels[idx.clamp(max=len(levels) - 1)]
293     span = (hi - lo).clamp(min=1e-12)
294     p_hi = (mag - lo) / span
295     draw = torch.rand(mag.shape, generator=gen, dtype=torch.float64)
296     return sign * torch.where(draw < p_hi, hi, lo)

323 # ---------------------------------------------------------------- F Hadamard
324 def hadamard(n: int) -> torch.Tensor:
325     h = torch.ones(1, 1, dtype=torch.float64)
326     while h.shape[0] < n:
327         h = torch.cat([torch.cat([h, h], 1), torch.cat([h, -h], 1)], 0)
328     return h / math.sqrt(n)

MXFP8 E4M3 每 32 元素一个 E8M0 三个都需要正反两份块量化 FP32 转置副本 + swizzle 后的 scale scaled_mm 在 sm_120 可用（SQNR 27.61 dB），但必须 SWIZZLE_32_4_4；torchtitan converter 要求 SM100+ 与 torchao nightly
NVFP4 E2M1 每 16 元素一个 E4M3 + 每张量一个 FP32；权重用 16×16 二维块 梯度随机舍入，wgrad 路径加 16×16 Hadamard FP32 两级 scale + Hadamard 矩阵 + 转置副本 scaled_mm 在 sm_120 可用（SQNR 17.42 dB）；整模型训练配方要求 SM100+，本项目 UNVERIFIED

三条约束对所有 FP8/FP4 路线都成立：K 必须是 16 的倍数（实测报错 Expected trailing dimension of mat1 to be divisible by 16）；块 scale 必须按 cuBLAS 的 32×4×4 布局重排；量化 kernel 必须被编译器融合，否则小 GEMM 上的固定开销会吃掉全部收益。

前沿：NVFP4 训练配方拆成四件事

Transformer Engine 2.18 的 FP8/FP4 文档把 NVFP4 训练配方拆成四个独立机制，每一个都对应上面的一段推导：

  1. 梯度用随机舍入。最近邻舍入在重复量化中会产生确定性偏差，本章实测 200 次累加偏 −16.67%。
  2. 权重用 16×16 的二维块 scale。一维块的量化结果与其转置不同，这对权重尤其敏感；二维块让正反两个方向共享同一组 scale。这与 DeepSeek-V3 的权重块量化同源，粒度更细。
  3. 计算权重梯度时对激活与梯度做 16×16 随机 Hadamard。目标是把块内尖峰摊平，正交性保证乘积不变。
  4. 最后几层保持更高精度（例如 MXFP8）。TE 不自动做这件事，因为它看不到网络结构，需要在训练代码里嵌套 autocast 覆盖配方。

同一份文档还澄清了两个容易混淆的点：delayed scaling 用历史 amax 换取"不必先算出高精度输出再量化"，代价是每个张量多一段 amax 历史作为额外状态；MXFP8 的转置需要重新量化，所以 TE 从同一份高精度输入直接生成正反两份，而不是转置已量化的结果。

本机能验证到哪一步要说清楚：sm_120 上 BlockWise1x32 与 BlockWise1x16 的 scaled_mm 通路可用，数值已实测；但 torchtitan 的 MXFP8/NVFP4 converter 要求 has_cuda_capability(10, 0) 且依赖 torchao nightly 的 swizzle cast kernel，整模型的 FP4 训练配方在本项目环境中保持 UNVERIFIED，需要 SM100 级设备加对应版本的 torchao 才能验收。随机舍入与 Hadamard 的端到端质量收益同样只有作者的预训练结果，不能用本章的合成张量读数替代。

陷阱

陷阱 1：把 bf16=true 当成一个开关

参数存储、算子输入、累加器、保存值、梯度归约、m/v 是六个独立选择。SmolLM3 的 dtype: bfloat16 与 accumulate_grad_in_fp32: true 同时出现在一份配方里，正是因为它们不是同一件事。

陷阱 2：用 dtype 的位宽推算加速比

FP8 相对 BF16 在 4096³ 上是 2.4×，在 1024³ 上是 1.8×，而把一个张量量化成 FP8 的未融合实现在 1024 档比整个 GEMM 还贵。位宽减半从来不等于时间减半。

陷阱 3：FP16 参数配默认 eps

eps=1e-8 在 FP16 里就是 0。零梯度的行会得到 0/0，一步之后整张参数变 NaN。显式低精度参数要用 BF16，或者把 optimizer 里的所有常数按 dtype 重新检查一遍。

陷阱 4：在 unscale 之前 clip

实测阈值被缩小四万倍，梯度范数只剩真值的 1/42154。次序是 unscale_ → finite → clip → step → update，且 scale 在一个累积窗口内必须保持不变。

陷阱 5：用 if scaler.step(optimizer): 判断是否更新

成功与跳步都返回 None。有效更新数要单独计数，它同时是 scheduler 的时钟和 checkpoint 里 global_step 的语义。

陷阱 6：看 loss 判断数值健康

梯度整体下溢时 loss 与正常情况完全相同、finite 检查通过、optimizer 照常 step，唯一的信号是梯度范数为 0。反过来，loss 是 NaN 也可能只是有效 target 为 0 造成的 0/0，模型本身没有任何问题。

陷阱 7：用一个判据评价量化方案

SQNR 由大元素主导，被压成零的小元素几乎不贡献能量误差。Hadamard 变换让零元素从 582 降到 141，SQNR 却下降了 3 dB。选判据之前要先确定这个张量在下游被怎么使用。

陷阱 8：把 TF32 当成一种存储格式

TF32 是 matmul 的计算模式，张量仍以 FP32 存储和读写。它不省显存，也不改变参数的写回精度。

自测题

  1. 模型参数是 FP32、开启 BF16 autocast，为什么每参数常驻字节仍是 16？省下来的是什么？
展开

autocast 只选择算子的计算精度，不转换持久参数。参数、梯度和 zeros_like(p) 建立的 m/v 都是 FP32，合计 16 字节。省下的是反向保存的激活：同一次前向的保存值从 79.9 KiB 降到 48.4 KiB，其中 31.5 KiB 变成了 BF16。

  1. rowwise FP8 的 scale 取 2 的幂之后，沿最后一维与沿第 0 维量化同一个张量，为什么 0% 的元素结果不同？那"转置需要重新量化"又从何而来？
展开

乘一个 2 的幂只改指数，浮点目标格式的舍入网格是相对的，所以在窗口内部的元素不受分组影响。差别只出现在掉出窗口两端的元素：被饱和的、或落进次正规与零的。MX 的 32 元素块把分组改了，块 amax 跟着变，实测 1.03% 的元素因此改变；再加上 tensor core 要求数据沿归约维连续、而前向与反向的归约维不同，同一个张量必须有两份量化结果。

  1. 一次训练 loss 正常、梯度 finite 检查全部通过、optimizer 也执行了 step，但模型完全不动。可能是什么？怎么区分？
展开

两种典型原因。其一是梯度整体下溢为零：看梯度范数和零元素比例，实测下溢时范数是 0.000e+00、零元素比例 1.000。其二是参数的相对更新量小于写回 dtype 的半 ULP 被舍入吸收：看 update/weight 比值，BF16 参数在 1.0 附近的阈值是 1.95e-3。第三种要排除的是有效 target 为 0：这时 loss 会是 0/0 的 NaN，但梯度全零、finite 通过，参数只按 ηλ 衰减，实测 update/weight = 1.0e-4。

  1. ROWWISE recipe 为什么三个操作数都用 E4M3，包括梯度？
展开

"前向 E4M3、反向 E5M2"是 per-tensor scaling 时代的结论：一个 scale 要覆盖整个梯度张量的动态范围，只能用多一位指数去换。rowwise 每行一个 scale，动态范围问题已经按行解决，这时两位尾数比一位指数更值钱。实测同一份数据上 per-tensor E5M2 比 E4M3 低 6 dB。
