7.1

训练循环的系统视角

前反向内存曲线、activation checkpointing、梯度累积、混合精度与 loss scaling、优化器状态。

7.1 训练循环系统视角

推理是单步前向，训练是循环迭代：数据读取、前反向、优化器更新形成关键路径，activation checkpointing、混合精度和梯度累积改变内存与计算的平衡。本章从系统角度拆解训练循环的阶段、状态与重叠。

问题

  1. 数据读取、H2D、前反向和优化器如何形成训练关键路径？
  2. activation checkpointing、混合精度和累积分别改变哪些状态？
  3. 数据输入与 GPU 计算能重叠到什么程度？

训练循环的关键路径

单步拆解

训练一步包含五个阶段：

for batch in dataloader:                # 1. 数据准备
    inputs = batch.to(device)           # 2. H2D 传输
    outputs = model(inputs)             # 3. 前向
    loss = criterion(outputs, labels)
    loss.backward()                     # 4. 反向
    optimizer.step()                    # 5. 优化器
    optimizer.zero_grad()

在 SmolLM2-360M（batch_size=8, seq_len=512）上的单线程 baseline：

阶段 耗时 说明
数据准备 0.05 ms __getitem__ 返回一个 batch
H2D (包含在前向) 小 batch 传输隐藏在前向启动
前向 47.3 ms 包含 H2D、kernel launch、attention/MLP
反向 54.4 ms 计算梯度、accumulate 到 .grad
优化器 (包含在总时间) AdamW 更新参数
总计 101.8 ms/step

[实验: labs/L7/training_loop_systems.py, 配置: 单线程]

关键路径瓶颈：单线程数据准备在 GPU 计算期间空转，数据与计算串行。

DataLoader 流水与重叠

PyTorch DataLoader 通过多进程 worker 和预取队列实现数据与计算重叠：

  • num_workers > 0：独立进程并行调用 __getitem__。
  • prefetch_factor：每个 worker 提前准备几个 batch。
  • pin_memory=True：数据直接分配在 pinned memory，DMA 传输更快。

四种配置对比（同一模型，10 steps 平均）：

配置 num_workers pin_memory 数据准备 前向 反向 总计 墙上时间
单线程 0 False 0.05 ms 47.3 ms 54.4 ms 101.8 ms 1.02 s
2worker-nopin 2 False 0.09 ms 11.0 ms 51.4 ms 62.5 ms 0.72 s
2worker-pin 2 True 0.08 ms 10.2 ms 51.9 ms 62.2 ms 0.71 s
4worker-pin 4 True 0.08 ms 10.5 ms 51.8 ms 62.4 ms 0.76 s

[实验: labs/L7/training_loop_systems.py:exp1_dataloader_pipeline, 结果: results/crater/7.1/dataloader_pipeline.json]

核心发现：

  1. 前向时间从 47 ms 降至 10 ms：单线程时 CPU 数据准备阻塞下一 batch 的 H2D，GPU 空转；多 worker 时数据提前就绪，H2D 与上一 batch 的计算重叠。
  2. 反向时间稳定在 51 ms：反向不依赖下一 batch，worker 数量对反向无影响。
  3. pin_memory 微弱收益：本实验数据量小（~2 MB/batch），DMA 收益不明显；大 batch 或高分辨率图像场景收益显著。
  4. 4 worker 无额外收益：数据准备已不是瓶颈，增加 worker 只增加进程开销。

流水原理：

时间轴（2 worker）:
Step 0:  [前向] [反向]
           ↓ H2D 重叠
Step 1:   [Worker 0/1 准备 batch 1] ────→ [前向] [反向]
                                          ↓ H2D 重叠
Step 2:                                  [Worker 准备 batch 2] ────→ ...

数据准备与 GPU 计算并行，关键路径只包含计算部分。

内存时间线

训练循环的 GPU 内存分配遵循固定节奏，以 SmolLM2-360M FP32 训练为例：

阶段 分配内存 说明
0. 初始状态 64 MB CUDA context
1. 模型加载 1445 MB 权重（360M × 4 bytes）
2. 优化器初始化 1445 MB AdamW 未分配 momentum/variance，lazy init
3. 数据 H2D 1445 MB batch 小，内存增长不可见
4. 前向 4435 MB 激活值峰值：attention scores, MLP 中间态
5. 反向开始 3176 MB 前向激活部分释放，梯度开始累积
6. 反向结束（优化器前） 5946 MB 训练峰值：权重 + 梯度 + optimizer states
7. optimizer.step() 5674 MB 更新后，部分临时张量释放
8. zero_grad() 4215 MB 梯度张量清零但未释放
9. 下一 step 4215 MB 循环稳态内存

[实验: labs/L7/training_loop_systems.py:exp4_memory_timeline, 结果: results/crater/7.1/memory_timeline.json]

峰值内存出现在优化器更新前：此时权重、梯度和 optimizer states（momentum、variance）同时驻留。实际峰值 5946 MB 包含： - 权重：1445 MB - 梯度：1445 MB - AdamW states：2890 MB（每个参数两个 FP32 state） - 残留激活：~166 MB

优化器 lazy 初始化：PyTorch AdamW 在第一次 step() 时才分配 momentum/variance，因此阶段 2 内存未变。

Activation Checkpointing

内存换时间

前向保存所有激活值供反向使用，Transformer 每层保存 attention scores 和 MLP 中间态。Activation checkpointing（梯度检查点）只保存部分层的激活，反向时重新计算未保存层的前向。

SmolLM2-360M 对比（batch_size=8, seq_len=512）：

配置 前向 反向 总计 前向后内存 峰值内存
无 checkpointing 26.0 ms 41.4 ms 87.2 ms 7241 MB 7625 MB
有 checkpointing 26.0 ms 58.9 ms 105.0 ms 4762 MB 8698 MB

[实验: labs/L7/training_loop_systems.py:exp2_activation_checkpointing, 结果: results/crater/7.1/activation_checkpointing.json]

权衡： - 内存降低 34%：前向后内存从 7241 MB 降至 4762 MB，大部分激活未保存。 - 反向时间增加 42%：从 41.4 ms 增至 58.9 ms，需重算未保存层的前向。 - 峰值内存反增 14%：8698 MB，因为重算时前向激活与反向梯度同时存在。

Transformers 实现

from transformers import AutoModelForCausalLM

model = AutoModelForCausalLM.from_pretrained(
    "HuggingFaceTB/SmolLM2-360M-Instruct",
    torch_dtype=torch.float32
)
model.gradient_checkpointing_enable()  # 启用 checkpointing

Transformers 默认对每个 Transformer block 设置 checkpoint，即每层只保存输入和输出，中间的 attention/MLP 激活在反向时重算。

适用场景： - 激活值远大于模型参数（大 batch、长序列）。 - GPU 内存受限，宁可牺牲 20-50% 速度换取内存。 - 不适合推理（推理无反向）。

混合精度训练

FP16/BF16 autocast

混合精度训练在前向和反向中使用 FP16/BF16 计算，参数和梯度更新仍用 FP32，平衡速度与精度。

三种配置对比（SmolLM2-360M, batch_size=8, seq_len=512）：

配置 前向 反向 优化器 总计 Loss 梯度范数 峰值内存
FP32 25.4 ms 41.2 ms 23.7 ms 90.4 ms 0.0013 0.39 7625 MB
FP16+scaler 17.0 ms 23.8 ms 6.2 ms 46.9 ms 1.85 inf 4660 MB
BF16 14.2 ms 23.8 ms 23.5 ms 61.5 ms 0.22 50.2 7473 MB

[实验: labs/L7/training_loop_systems.py:exp3_mixed_precision, 结果: results/crater/7.1/mixed_precision.json]

核心差异：

  1. FP16+scaler： - 速度最快：总时间 46.9 ms，前向提速 33%，反向提速 42%。 - 数值不稳定：梯度范数 inf，loss 1.85（vs FP32 的 0.0013），需要 gradient scaling 和溢出检测。 - 内存最低：4660 MB，FP16 激活占用减半。

  2. BF16： - 速度折中：总时间 61.5 ms，前向提速 44%，但优化器仍 FP32 耗时未变。 - 数值稳定：loss 0.22，梯度范数 50.2，无 inf/NaN。BF16 动态范围与 FP32 相同（8-bit exponent），不需要 gradient scaling。 - 内存略降：7473 MB，接近 FP32。BF16 激活减半，但参数和 optimizer states 仍 FP32。

Gradient Scaling

FP16 数值范围窄（±65504），小梯度易下溢至 0。Gradient scaling 在反向前将 loss 乘以 scale（如 65536），放大梯度防止下溢，optimizer.step() 前再除以 scale 恢复。

from torch.cuda.amp import autocast, GradScaler

scaler = GradScaler()
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)

for batch in dataloader:
    optimizer.zero_grad()
    with autocast(dtype=torch.float16):  # 前向 FP16
        outputs = model(inputs)
        loss = criterion(outputs, labels)

    scaler.scale(loss).backward()        # loss *= scale, 反向
    scaler.unscale_(optimizer)           # 梯度 /= scale
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)  # 裁剪前先 unscale
    scaler.step(optimizer)               # 更新（若无 inf/NaN）
    scaler.update()                      # 动态调整 scale

实验中 FP16 的 scaler_scale=8192，说明训练初期梯度较大，scaler 自动降低了 scale（初始 65536）。

BF16 无需 scaling：BF16 指数位与 FP32 相同（8 bits），动态范围 10−38 至 1038，小梯度不会下溢，直接训练即可。

with autocast(dtype=torch.bfloat16):
    outputs = model(inputs)
    loss = criterion(outputs, labels)
loss.backward()
optimizer.step()  # 无需 scaler

选择

类型 速度 精度 内存 复杂度 适用场景
FP32 基线 最高 最高 低 调试、小模型
FP16+scaler 最快 需调试 最低 高 对精度不敏感、内存受限
BF16 快 稳定 中等 低 大多数训练（推荐）

现代训练（Llama、GPT-4 风格）默认 BF16，速度与稳定性兼顾。FP16 主要用于推理或内存极限场景。

梯度累积

当单 GPU 内存无法容纳大 batch 时，梯度累积将大 batch 拆分为多个小 mini-batch，累加梯度后一次更新。

accumulation_steps = 4
optimizer.zero_grad()

for i, batch in enumerate(dataloader):
    outputs = model(batch)
    loss = criterion(outputs, labels) / accumulation_steps  # 归一化
    loss.backward()  # 梯度累加到 .grad

    if (i + 1) % accumulation_steps == 0:
        optimizer.step()
        optimizer.zero_grad()

等价性：4 × batch_size=8 累积 ≈ 1 × batch_size=32（数值上有微小差异，因 LayerNorm/BatchNorm 统计量按 mini-batch 计算）。

代价： - 墙上时间增加 4×（4 次前向反向 vs 1 次）。 - 内存不降（峰值仍是单 mini-batch 的前向+反向+optimizer states），但允许用小 batch 模拟大 batch 的收敛效果。

适用于大模型训练（如 7B+），其中 batch_size=1 已占满 GPU，需累积达到 effective batch_size=256。

完整流水

综合应用 DataLoader 并行、BF16 和梯度累积的训练流水：

from torch.cuda.amp import autocast
from torch.utils.data import DataLoader

dataloader = DataLoader(
    dataset,
    batch_size=8,
    num_workers=4,
    pin_memory=True,
    prefetch_factor=2
)

model = AutoModelForCausalLM.from_pretrained(...)
model.gradient_checkpointing_enable()  # 如果内存受限
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)

accumulation_steps = 4
optimizer.zero_grad()

for i, batch in enumerate(dataloader):
    inputs = batch["input_ids"].to(device)
    labels = batch["labels"].to(device)

    with autocast(dtype=torch.bfloat16):
        outputs = model(inputs, labels=labels)
        loss = outputs.loss / accumulation_steps

    loss.backward()

    if (i + 1) % accumulation_steps == 0:
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        optimizer.step()
        optimizer.zero_grad()

关键路径优化： - 数据准备与 GPU 计算并行（4 workers, prefetch=2）。 - 前向反向用 BF16（速度 +40%，内存 -5~10%）。 - Activation checkpointing 按需启用（内存 -34%，速度 -20%）。 - 梯度累积模拟大 batch（effective_batch_size = 8 × 4 = 32）。

监控与调优

关键指标

训练循环性能监控关注：

指标 工具 目标
Samples/sec 训练日志 数据吞吐
GPU 利用率 nvidia-smi dmon > 90%（计算密集）
内存峰值 torch.cuda.max_memory_allocated() < 显存 × 0.9
DataLoader 队列 自定义 profiling > 0（数据不阻塞）
梯度范数 训练日志 稳定，无 inf/NaN

调优策略

症状 原因 解决
GPU 利用率 < 50% 数据阻塞 增加 num_workers, prefetch_factor
内存 OOM 激活值过大 启用 checkpointing，减小 batch_size
梯度 inf/NaN FP16 溢出 切换 BF16，或调整 scaler 初始 scale
速度慢但内存富余 未用混合精度 启用 BF16 autocast
Loss 震荡 Batch size 过小 梯度累积增大 effective batch size

总结

训练循环的系统优化围绕数据-计算流水、内存-时间权衡和数值稳定性：

  1. DataLoader 并行：2-4 worker + prefetch 将数据准备与 GPU 计算重叠，消除 CPU 阻塞。
  2. Activation checkpointing：内存降低 34%，反向时间增加 42%，适合大 batch/长序列场景。
  3. 混合精度：BF16 是默认选择（速度 +40%，稳定性好）；FP16 更快但需 gradient scaling。
  4. 内存峰值：出现在优化器更新前，包含权重、梯度和 optimizer states。
  5. 梯度累积：小 batch 模拟大 batch，不降低内存峰值，但允许突破单 batch 内存限制。
